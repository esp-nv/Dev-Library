## 2. Критични технически забележки

### 2.1. Programming Languages

- C#: актуализиране към .NET 10 LTS.
- Java: актуализиране към Java 25 LTS.
- TypeScript: разграничаване на compile-time и runtime проверки.
- JavaScript: добавяне на Node.js, backend, desktop и mobile.
- Python: разграничаване на dynamic и strong typing.
- PHP: проверка на актуалните поддържани версии.

Основни концепции за добавяне:
- Static vs Dynamic Typing.
- Strong vs Weak Typing.
- Compilation vs Interpretation.
- Compile-time vs Runtime.
- Managed vs Native Runtime.

### 2.2. Frontend Development

**React и Next.js**

React е UI библиотека, докато Next.js е framework, базиран на React.

Да се добавят:
- Routing.
- Server-side Rendering.
- Static Site Generation.
- React Server Components.
- Backend Endpoints.
- Caching.

**Vue**

Vue използва собствена реактивна система:
- ref().
- reactive().
- computed().
- watch().

**Angular**

Angular Signals не заменят автоматично RxJS. Двете технологии могат да се използват съвместно.

**Tailwind CSS**

Tailwind не заменя CSS, а предоставя utility-first подход.

Допълнителни технологии:
- CSS Modules.
- CSS-in-JS.
- Sass.
- Design Systems.
- Component Libraries.

### 2.3. Backend Development & APIs

Да се разширят описанията на:
- ASP.NET Core: Minimal APIs, EF Core, Authentication, Middleware.
- Spring Boot: Spring Security, Spring Data, JPA, Hibernate.
- NestJS: Modules, Providers, Guards, Interceptors.
- FastAPI: Dependency Injection, Pydantic, Async.
- Django: ORM, Middleware, Authentication, REST Framework.
- Laravel: Eloquent, Queues, Events, Sanctum.

**REST, GraphQL и gRPC**

Да се премахне универсалното твърдение, че gRPC е 5–10 пъти по-бърз от JSON.

Производителността зависи от:
- Размер на съобщенията.
- Сериализация.
- Мрежова латентност.
- HTTP версия.
- Имплементация.
- Конкретен benchmark.

Допълнителни корекции:
- REST не е синоним на JSON.
- GraphQL не е задължително само POST.
- REST не изисква отделен URL за всеки ресурс.
- gRPC не е предназначен единствено за микросървиси.

### 2.4. Databases & Messaging

| Технология | Липсващи теми |
|---|---|
| PostgreSQL | Indexes, Transactions, JSONB, Replication |
| SQL Server | Transactions, Indexing, Security, T-SQL |
| MongoDB | Aggregation Pipeline, Indexes, Transactions |
| Redis | Persistence, Replication, Eviction Policies |
| Kafka | Partitions, Offsets, Consumer Groups, Retention |

Redis трябва да бъде представен като in-memory data store с възможности за persistence, replication и clustering.

Kafka трябва да включва:
- At-most-once.
- At-least-once.
- Exactly-once Semantics.
- Replication.
- Retention.
- Consumer Offset Management.

Допълнителни инструменти:

- NUnit.
- xUnit.
- TestNG.
- Cucumber.
- Pact.
- WireMock.
- BrowserStack.

CI/CD:

Infrastructure as Code:

Cloud:
