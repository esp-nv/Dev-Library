## 1. БЪРЗ СТАРТ: ОТВАРЯНЕ И ПРЕВКЛЮЧВАНЕ В CHROME DEVTOOLS

| Действие | Прек Път (Windows / Linux) | Прек Път (Mac) | Резултат в браузъра |
| :--- | :--- | :--- | :--- |
| **Отваряне на DevTools** | `F12` или `Ctrl + Shift + I` | `Cmd + Option + I` | Отваря диагностичния панел. |
| **Директен избор на елемент (Inspect)** | `Ctrl + Shift + C` | `Cmd + Shift + C` | Активира лупата — посочваш кутия на екрана и виждаш нейния HTML/CSS. |
| **Отваряне директно на Console** | `Ctrl + Shift + J` | `Cmd + Option + J` | Фокусира веднага конзолата за грешки и логове. |
| **Мобилен изглед (Device Toolbar)** | `Ctrl + Shift + M` | `Cmd + Shift + M` | Симулира iPhone, iPad или произволна ширина на екрана в пиксели. |
| **Hard Reload (Без кеш)** | `Ctrl + Shift + R` | `Cmd + Shift + R` | Презарежда страницата насила, игнорирайки кешираните CSS/JS файлове. |

## 2. СТЪПКА ПО СТЪПКА: ИНСПЕКЦИЯ НА DOM И CSS В ТАБА ELEMENTS

Когато даден елемент не стои на мястото си или има грешен цвят/размер, изпълни следния алгоритъм:

1. **Посочи елемента:** Натисни `Ctrl + Shift + C` и кликни върху проблемния блок на страницата.
2. **Провери прозореца `Styles` (вдясно):**
   * Ако дадено CSS свойство е **задраскано с черта (`~~color: red;~~`)**, значи друго правило с по-висока тежест (Specificity) го е презаписало.
   * Ако до свойството има **жълт триъгълник с удивителна (`⚠️`)**, си допуснал правописна грешка в името на свойството или стойността (например `widht: 100px` вместо `width: 100px`).
3. **Провери прозореца `Computed` (до `Styles`):**
   * Погледни цветната диаграма на **Box Model** най-отгоре — тя показва точните изчислени пиксели за `margin`, `border`, `padding` и `content` в реално време.

## 3. ДИАГНОСТИКА В РЕАЛНО ВРЕМЕ: CONSOLE & NETWORK (ВХОД / ИЗХОД)

### 🔍 Сценарий А: Проверка за липсващи файлове (`404 Not Found`)
* **Вход (Грешен път в HTML):**
  ```html
  <link rel="stylesheet" href="css/stlye.css">
  <img src="images/logo.png" alt="Logo">
  ```
* **Изход в таба `Console`:**
  ```text
  GET http://127.0.0 net::ERR_ABORTED 404 (Not Found)
  GET http://127.0.0 404 (Not Found)
  ```
* **Решение:** Провери правописа на името на файла (`style.css` вместо `stlye.css`) и дали пътят започва от правилната папка.

### 🔍 Сценарий Б: Бърза проверка на DOM елементи през Console
* **Вход (Команда в `Console`):**
  ```javascript
  document.querySelectorAll('img').length
  ```
* **Изход в `Console`:**
  ```text
  <- 4
  ```
  *(Връща точния брой заредени изображения в текущото DOM дърво.)*

## 4. ИЗПИТЕН ЧЕКЛИСТ & CHEAT SHEET ПРИ СЧУПЕН ДИЗАЙН

Когато дизайнът в браузъра не отговаря на очакванията, мини по тези 4 точки за 15 секунди:

* **1. Изключи кеша:** Отвори `F12` ➔ таб `Network` ➔ сложи отметка на **`Disable cache`** ➔ натисни `Ctrl + Shift + R`.
* **2. Провери `Status` колоната в `Network`:** Всички локални `.html`, `.css`, `.js` и `.png/.jpg` файлове трябва да светят със статус **`200`** (или `304`). Ако има червен ред с **`404`**, пътят до файла е грешен.
* **3. Провери за задраскани стилове в `Styles`:** Увери се, че твоят CSS файл е зареден **след** външните библиотеки (Bootstrap / Reset CSS), за да не бъдат презаписани правилата ти.
* **4. Провери размера на екрана (`Responsive`):** Натисни `Ctrl + Shift + M` и тествай страницата на `1920px` (Desktop), `768px` (Tablet) и `375px` (Mobile).

### 📋 Бърза справка за диагностика в Chrome DevTools

| Инструмент / Таб | Команда / Действие | Какво проверява и решава? |
| :--- | :--- | :--- |
| **Console (DOM брой)** | `document.querySelectorAll('.card').length` | Връща точния брой рендерирани елементи по даден CSS селектор. |
| **Console (Активен фокус)** | `document.activeElement` | Показва кой елемент в момента държи фокуса на клавиатурата. |
| **Elements -> Computed** | Филтър `box-sizing` / `display` | Показва реално изчислените от браузъра пиксели след всички каскадни правила. |
| **Elements -> Styles** | Бутон `:hov` (Force element state) | Заключва състояние `:hover`, `:focus` или `:active`, за да инспектираш скрити менюта. |
| **Network -> Cache** | Отметка `Disable cache` + `Ctrl + Shift + R` | Спира зареждането на стари CSS/JS файлове от диска при отворен DevTools. |
| **Network -> Throttling** | Избор на `Slow 3G` / `Fast 3G` | Симулира бавен мобилен интернет, за да провериш как зареждат тежки снимки. |
| **Application -> Storage** | `Clear site data` | Изтрива напълно `LocalStorage`, `SessionStorage`, бисквитки и кеширани данни. |

## 5. СИСТЕМНИ КАПАНИ: ПРЕЗАПИСАНИ ПРОМЕНИ СЛЕД REFRESH

### 🚨 Капан №1: Редактираш CSS директно в Chrome DevTools, опресняваш и всичко изчезва
* **Какво се случва:** Правиш 15 минути корекции по цветове, отстояния и шрифтове директно в прозореца `Styles` на браузъра. Дизайнът става перфектен, натискаш `F5` (Refresh) и всички промени се изтриват безвъзвратно.
* **Защо се случва:** Chrome DevTools модифицира единствено **живото DOM дърво и CSSOM в оперативната RAM памет** на браузъра. Той няма право да презаписва директно твоите физически файлове на твърдия диск (освен ако не си настроил специално `Workspaces` мапване).
* **Как да го избегнеш:** Използвай DevTools само за **бърз визуален експеримент** (10–20 секунди). Веднага щом намериш точните пиксели или цвят, копирай готовия CSS блок от браузъра и го постави във физическия ти `.css` файл във **VS Code**.
