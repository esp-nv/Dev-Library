## 🗺️ 1. КАРТА НА РОЛИТЕ: КОЕ КАКВО Е ВСЪЩНОСТ?

Когато чуеш тези имена на интервю или в обява за работа, ги постави в точната им кутийка:

| Технология | Истинска роля в системата | База данни ли е? | Как си говори с твоя C# / Web код? |
| :--- | :--- | :--- | :--- |
| **RabbitMQ** | **Message Broker** (Пощенска опашка за задачи). | ❌ Не | C# пуска задача в опашката; друг сървър я взима и изпълнява. |
| **Apache Kafka** | **Event Streaming** (Поток от събития в реално време). | ❌ Не *(пази лог)* | Хиляди събития в секунда се записват и четат от много услуги. |
| **GraphQL** | **API Query Language** (Начин за заявяване от API). | ❌ Не | Фронтендът пита API-то кои точно полета иска да получи. |
| **SQLite / Room / Realm** | **Embedded Mobile БД** (Локална база в телефона). | ✅ **Да** | Android/iOS приложението пази данни офлайн на устройството. |
| **Active Directory / Entra ID** | **Identity Provider (IAM)** (Вход, пароли, роли). | ❌ Не *(директория)* | Издава JWT токени при логин („Sign in with Microsoft“). |
| **SAP (S/4HANA)** | **ERP Система** (Склад, фактури, счетоводство, HR). | ❌ Не *(голям софтуер)* | C# обменя поръчки/наличности със SAP чрез API (JSON/XML). |

## 📨 2. RABBITMQ СРЕЩУ APACHE KAFKA (ОПАШКИ И СЪБИТИЯ)

И двете служат за **асинхронна комуникация** между сървъри (за да не чака потребителят 10 секунди да се генерира фактура или имейл).

| Критерий | RabbitMQ (Smart Broker) | Apache Kafka (Event Log) |
| :--- | :--- | :--- |
| **Принцип на работа** | **Опашка (Queue):** Изпраща задачата към един работник (Consumer) и след като той потвърди, **я изтрива**. | **Дневник (Append-only Log):** Записва събитието на диска и го пази дни/седмици. Много системи могат да го четат независимо. |
| **Къде е предпочитан?** | Фонови задачи: изпращане на имейли, генериране на PDF, обработка на плащания (с C# **MassTransit**). | Огромни потоци: GPS локации на коли (Uber), банкови измами, кликове и логове в реално време. |

```text
[ C# Web API ] ---> ( RabbitMQ Опашка: "SendInvoiceEmail" ) ---> [ Email Worker Service ]
```

## 🔍 3. GRAPHQL СРЕЩУ REST API

**GraphQL** не замества SQL или MongoDB — той стои **между фронтенда (React/Angular/Mobile) и твоя C# бекенд** (в C# се ползва библиотеката **HotChocolate**).

* **Проблемът на REST API:** Правиш заявка `GET /api/users/5` и сървърът ти връща 30 излишни полета (адрес, ЕГН, настройки), въпреки че на екрана ти трябва само името (**Over-fetching**). Или ти трябват 3 отделни заявки (за потребител, поръчки и ревюта).
* **Решението на GraphQL:** Има само един адрес (`POST /graphql`) и клиентът изпраща точно какво иска:

```graphql
# Заявка от фронтенда към GraphQL API:
query {
  user(id: 5) {
    name
    orders {
      totalPrice
    }
  }
}
```

## 📱 4. MOBILE / ANDROID БАЗИ ДАННИ (SQLITE, ROOM, REALM)

Когато правиш мобилно приложение (Android с Kotlin/Java или React Native / .NET MAUI), телефонът често няма интернет в метрото или планината. Затова има **локална база в самия телефон**:

* **SQLite:** Вградена директно в Android и iOS. Всяка база е един обикновен файл на телефона.
* **Android Room:** Официалната библиотека на Google върху SQLite (работи като EF Core в C# — пишеш класове и тя ги превръща в SQLite таблици).
* **Realm:** Бърза NoSQL обектна база за мобилни приложения (алтернатива на SQLite с лесна синхронизация към облака).

## 🏢 5. КОРПОРАТИВНИ СИСТЕМИ: ACTIVE DIRECTORY (ENTRA ID) И SAP

В големите компании (банки, телекоми, заводи, търговски вериги) тези две системи са сърцето на ИТ инфраструктурата:

1. **Active Directory (AD) / Microsoft Entra ID (новото име на Azure AD):**
   * Управлява служителите и потребителите. Когато влезеш с фирмения си акаунт, Entra ID проверява паролата и ролята ти (напр. `HR_Manager` или `Developer`) и дава на C# приложението ти **JWT токен**, с който те пуска до определени екрани.
2. **SAP:**
   * Централният бизнес софтуер на фирмата. Когато клиент купи стока от уеб сайта (написан на C# + SQL), бекендът изпраща JSON/XML съобщение към **SAP**, за да се извади стоката от склада и да се издаде счетоводна фактура.
