## 🗺️ 1. СРАВНИТЕЛНА КАРТА НА СПЕЦИАЛИЗИРАНИТЕ БАЗИ

Класическите SQL бази търсят по **точно съвпадение** (`WHERE Name = 'Лаптоп'`). Когато ти трябва търсене по **смисъл**, по **правописни грешки** или по **сложни мрежи от връзки**, използваш специализирана база:

| Категория | Какво пази? | Най-известни представители | Основен сценарий на работа |
| :--- | :--- | :--- | :--- |
| **Vector Databases** | Списъци от числа (**Embeddings**), описващи смисъла на текст, снимка или звук. | **Pinecone**, **Qdrant**, **Weaviate**, **`pgvector`** *(PostgreSQL)* | **ChatGPT върху фирмени документи (RAG)**, търсене по снимка, препоръки. |
| **Search Engines** | Обърнат индекс (**Inverted Index**) на всяка дума в огромни текстове. | **Elasticsearch**, **OpenSearch**, **Meilisearch** | Търсачка в онлайн магазин (с грешки и филтри), централизирани логове (ELK). |
| **Graph Databases** | Възли (**Nodes**) и директни връзки (**Edges / Relationships**). | **Neo4j**, Amazon Neptune | Социални мрежи („Приятели на приятели“), засичане на банкови измами. |
| **Time-Series БД** | Измервания, подредени строго по **времеви печат (Timestamp)**. | **InfluxDB**, **TimescaleDB** *(PostgreSQL)*, Prometheus | Крипто и фондови борси, IoT сензори, мониторинг на сървъри (CPU/RAM). |

## 🤖 2. VECTOR DATABASES (ВЕКТОРНИ БД ЗА AI И RAG)

Векторните бази са сърцето на модерните AI приложения. Когато качиш фирмен PDF или база знания в AI асистент:
1. AI моделът превръща всяко изречение в **вектор** (масив от напр. `1536` числа с плаваща запетая: `[0.012, -0.45, 0.89, ...]`).
2. Близките по смисъл текстове имат **близки числа в пространството** (измерва се чрез *Cosine Similarity*).
3. Така търсенето на `"Как да си върна парите?"` намира документа `"Политика за възстановяване на суми"`, дори без нито една обща дума!

```sql
-- ============================================================
-- ПРИМЕР С PGVECTOR (ВЕКТОРНО РАЗШИРЕНИЕ В POSTGRESQL)
-- ============================================================
-- Създаване на таблица с векторна колона (1536 измерения за OpenAI embeddings)
CREATE TABLE knowledge_docs (
    id SERIAL PRIMARY KEY,
    content TEXT NOT NULL,
    embedding VECTOR(1536)
);

-- Търсене на 3-те най-близки по СМИСЪЛ документа (оператор <-> за дистанция):
SELECT content
FROM knowledge_docs
ORDER BY embedding <-> '[0.015, -0.23, ...]'
LIMIT 3;
```

## 🔎 3. SEARCH ENGINES (ELASTICSEARCH / OPENSEARCH)

Ако в онлайн магазин с 1 милион продукта напишеш в SQL `WHERE Name LIKE '%айфон 15 про%'`, базата ще сканира цялата таблица бавно и няма да намери нищо, ако потребителят е сгрешил една буква (`"аифон"`).

**Elasticsearch** решава това за милисекунди чрез **Inverted Index** (като азбучния показалец в края на учебник):
* Поддържа **Fuzzy Search** (намира думи с печатни грешки).
* Смята **Relevance Score** (показва най-точните попадения най-отгоре).
* Прави светкавични филтри по цена, марка, цвят и наличност едновременно (**Facets / Aggregations**).

```json
// ============================================================
// ELASTICSEARCH ЗАЯВКА (ТЪРСЕНЕ С ТОЛЕРАНС КЪМ ПРАВОПИСНИ ГРЕШКИ)
// ============================================================
GET /products/_search
{
  "query": {
    "match": {
      "name": {
        "query": "аифон 15",
        "fuzziness": "AUTO"
      }
    }
  }
}
```

## 🕸️ 4. GRAPH БД (NEO4J) И TIME-SERIES БД (TIMESCALEDB)

### 🔹 А. Graph Databases (`Neo4j` — език `Cypher`)
В SQL търсенето на „приятели на приятелите на приятелите“ изисква 4–5 тежки `SELF JOIN`-а, които забиват базата. В **Neo4j** връзките са записани физически като указатели и се обхождат мигновено:

```cypher
// Намери приятелите на приятелите на Иван в Neo4j (Cypher език):
MATCH (p:Person {name: "Иван"})-[:FRIEND_OF]->()-[:FRIEND_OF]->(fof:Person)
RETURN fof.name;
```

### 🔹 Б. Time-Series Databases (`TimescaleDB` / `InfluxDB`)
Когато 10 000 сензора или борсови тикери пращат данни всяка секунда:
* Обикновеният SQL индекс се претоварва от милиардите редове.
* **Time-Series** базите автоматично разделят данните на времеви парчета (**Chunks** — напр. по 1 ден), компресират старите данни с до 90% и изчисляват средни стойности по минути/часове за милисекунди.
