## 1. КАК МИСЛИМ И КАК ЧЕТЕМ САМИЯ SQL

В SQL **пишем** `SELECT` на първи ред, но двигателят на базата данни **изпълнява** заявката от източника (`FROM`) към финалния резултат (`ORDER BY`).

```sql
-- ============================================================
-- 1. ОСНОВЕН SELECT (КАК ГО ПИШЕМ СРЕЩУ КАК ГО МИСЛИМ)
-- ============================================================

SELECT Name, Grade        -- 3. Какво показвам
FROM Students             -- 1. Откъде взимам данните
WHERE Grade > 50          -- 2. Кои РЕДОВЕ оставям
ORDER BY Grade DESC;      -- 4. Как сортирам накрая

-- ЛОГИКА НА ИЗПЪЛНЕНИЕ ПОД КАПАКА:
-- FROM → WHERE → SELECT → ORDER BY
```

## 2. СИНТАКТИЧНАТА „СТЪЛБА“ И РЕДЪТ НА ИЗПЪЛНЕНИЕ

Ако нарушиш реда на писане от лявата колона, SQL връща синтактична грешка.

| Ред на писане (Синтаксис) | Ред на изпълнение (Двигател) | Какво прави клаузата? | Може ли да ползва `AS Alias` от `SELECT`? |
| :--- | :--- | :--- | :--- |
| **1.** `SELECT [DISTINCT] [TOP N]` | **6.** `SELECT` / **7.** `DISTINCT` | Избира колоните, смята формули и дава `AS Alias`. | *(Тук се създават Alias-ите)* |
| **2.** `FROM [Table1]` | **1.** `FROM` | Взима основната таблица. | ❌ Не |
| **3.** `JOIN [Table2] ON ...` | **2.** `JOIN` + `ON` | Свързва втора таблица по общия ключ (`PK = FK`). | ❌ Не |
| **4.** `WHERE [Условие]` | **3.** `WHERE` | Филтрира **индивидуалните редове** (преди групиране). | ❌ Не |
| **5.** `GROUP BY [Колони]` | **4.** `GROUP BY` | Обединява оцелелите редове в **групи**. | ❌ Не |
| **6.** `HAVING [Агрегат]` | **5.** `HAVING` | Филтрира **групите** (след `COUNT`, `SUM`, `AVG`). | ❌ Не |
| **7.** `ORDER BY [Колона]` | **8.** `ORDER BY` | Сортира крайния резултат. | ✅ **Да!** |
| **8.** `OFFSET X FETCH NEXT Y` | **9.** `TOP` / `OFFSET` | Отрязва само искания брой редове за екрана. | ✅ Да |

## 3. КОНКРЕТНИ SQL ПРИМЕРИ (СТЪПКА ПО СТЪПКА)

### 🔹 Пример А: `WHERE` + `GROUP BY` + `HAVING` (Пълна верига с агрегати)

```sql
-- ============================================================
-- 2. ПЪЛНА ВЕРИГА: JOIN + WHERE + GROUP BY + HAVING + ORDER BY
-- ============================================================
-- Задача: Намери клиенти с поне 2 поръчки над 100 лв. всяка,
-- чиято обща сума надвишава 500 лв., подредени по сума надолу.

SELECT                                  -- 6. Показвам името, броя и сумата
    c.Name AS CustomerName,
    COUNT(o.Id) AS OrdersCount,
    SUM(o.Price) AS TotalSpent
FROM Customers AS c                     -- 1. Започвам от таблицата с клиенти
JOIN Orders AS o                        -- 2. Свързвам я с поръчките
    ON c.Id = o.CustomerId
WHERE o.Price > 100                     -- 3. Махам евтините поръчки (РЕДОВЕ)
GROUP BY c.Id, c.Name                   -- 4. Групирам останалите по клиент
HAVING COUNT(o.Id) >= 2                 -- 5. Оставям само групи с >= 2 поръчки
   AND SUM(o.Price) > 500               --    и обща сума > 500 лв. (ГРУПИ)
ORDER BY TotalSpent DESC;               -- 7. Сортирам по Alias-а от SELECT
```

### 🔹 Пример Б: `LEFT JOIN` + `COALESCE` (Запазване на всички от лявата таблица)

```sql
-- ============================================================
-- 3. LEFT JOIN — ВСИЧКИ ОТ ЛЯВАТА ТАБЛИЦА (ДОРИ БЕЗ ПОРЪЧКИ)
-- ============================================================
-- Мислене: "Коя таблица искам да запазя изцяло?" -> Customers (лявата)

SELECT 
    c.Name AS CustomerName,
    COUNT(o.Id) AS OrdersCount,                 -- Брои само не-NULL поръчки (0 ако няма)
    COALESCE(SUM(o.Price), 0) AS TotalSpent     -- Превръща NULL сумата в 0.00
FROM Customers AS c
LEFT JOIN Orders AS o
    ON c.Id = o.CustomerId
GROUP BY c.Id, c.Name
ORDER BY TotalSpent DESC;
```

### 🔹 Пример В: `SUBQUERY` (Когато първо ти трябва друга стойност)

```sql
-- ============================================================
-- 4. SUBQUERY — ВЪТРЕШНА ЗАЯВКА В WHERE
-- ============================================================
-- Мислене: "Първо трябва да сметна средната оценка (AVG),
-- за да сравня всеки студент с нея."

SELECT Name, Grade
FROM Students
WHERE Grade > (
    SELECT AVG(Grade)       -- Вътрешен SELECT: връща една стойност (напр. 4.85)
    FROM Students
)
ORDER BY Grade DESC;
```

### 🔹 Пример Г: `TOP` / `OFFSET-FETCH` (Странициране в MS SQL и PostgreSQL)

```sql
-- ============================================================
-- 5. СТРАНИЦИРАНЕ (PAGINATION)
-- ============================================================

-- В MS SQL Server (вземи 2-ра страница по 5 записа):
SELECT Id, Name, Grade
FROM Students
ORDER BY Grade DESC                     -- ORDER BY е задължителен при OFFSET!
OFFSET 5 ROWS FETCH NEXT 5 ROWS ONLY;

-- В PostgreSQL / MySQL:
-- SELECT id, name, grade FROM students ORDER BY grade DESC LIMIT 5 OFFSET 5;
```

## 4. ТРИТЕ ЗЛАТНИ ПРАВИЛА ЗА ПРОВЕРКА

1. **`WHERE` срещу `HAVING`:**
   * **`WHERE` филтрира РЕДОВЕ** ➔ стои **преди** `GROUP BY` и в него **никога** не се пишат `SUM()`, `COUNT()`, `AVG()`.
   * **`HAVING` филтрира ГРУПИ** ➔ стои **след** `GROUP BY` и проверява резултата от агрегатните функции.
2. **Правилото за колоните при `GROUP BY`:**
   * В `SELECT` можеш да напишеш **само** колони, които са изброени в `GROUP BY`, или колони, обвити в агрегатна функция (`SUM`, `COUNT`, `MIN`, `MAX`, `AVG`).
3. **`COUNT(*)` срещу `COUNT(o.Id)` при `LEFT JOIN`:**
   * `COUNT(*)` брои целия ред (и ще върне `1` дори за клиент без поръчки!).
   * `COUNT(o.Id)` игнорира `NULL` стойностите и правилно връща `0` за клиент без поръчки.
