## 1. АНАТОМИЯ НА УЕБ ЕКОСИСТЕМАТА: КЛИЕНТ СРЕЩУ СЪРВЪР

Всяко съвременно уеб приложение работи въз основа на двупосочния модел **Client-Server Architecture**:
* **Клиент (Client / Frontend):** Средата, с която потребителят взаимодейства директно. Това най-често е уеб браузърът (Chrome, Firefox, Safari), който получава суров текст, интерпретира го и го рендерира визуално на екрана.
* **Сървър (Server / Backend):** Отдалечена мощна машина, която обработва бизнес логиката, удържа сигурността, комуникира с бази данни и връща готови ресурси обратно към клиента при поискване.

---

## 2. АРХИТЕКТУРЕН ТРИЪГЪЛНИК НА ФРОНТЕНД СРЕДИТЕ

Когато браузърът зареди уеб страница, неговият двигател изпълнява точно три коренно различни софтуерни компонента:
1. **HTML5 (Структура):** Определя *какви* елементи има на екрана (текст, форми, бутони).
2. **CSS3 (Визия):** Определя *как* изглеждат тези елементи (размери, разположение, цветове).
3. **JavaScript (Поведение):** Програмен език, който вдъхва живот на страницата, правейки я интерактивна (реагира на кликове, изпраща асинхронни заявки).

---

## 3. ПЛАН ЗА ИНСТАЛАЦИЯ И ВРЪЗКА МЕЖДУ СОФТУЕРНИТЕ ИНСТРУМЕНТИ

За да бъде работата ти лесна, бърза и защитена от софтуерни аномалии, твоите инструменти трябва да работят в затворен интеграционен кръг:
* **Среда за писане (IDE):** Избираме **Visual Studio Code**. Лек, модулен и бърз редактор с възможност за налагане на native C# и фронтенд снипети.
* **Среда за тестване (Браузър):** Избираме **Google Chrome** (или Chromium-базиран браузър), тъй като неговият диагностичен център *DevTools* съвпада на 100% с критериите за проверка в SoftUni и Judge.
* **Среда за мрежов одит:** **Postman** — за симулиране на HTTP трансакции и проверка на чисти JSON тела без влиянието на уеб дизайна.

## 4. ВОДЕЩИТЕ IDE СРЕДИ В ИНДУСТРИЯТА (VISUAL STUDIO, JETBRAINS, NETBEANS, SUBLIME)

### 4.1. Microsoft Visual Studio (Тежкият артилерийски монолит)
* **Философия:** Пълнофункционална, тежка среда за разработка (Heavyweight IDE), създадена от Microsoft специално за .NET средите. За разлика от VS Code, Visual Studio идва с всичко инсталирано по подразбиране — компилатори, SQL мениджъри, профилири за памет и Docker поддръжка.
* **Кога се използва:** Златен стандарт за изграждане на мащабни Enterprise Monolith MVC системи и Clean Architecture решения.
* **Плюсове:** Най-мощният бекенд дебъгер в света, перфектна native интеграция с MS SQL Server и Entity Framework Core миграции.

### 4.2. JetBrains среди: Rider, WebStorm и IntelliJ IDEA
Компанията **JetBrains** създава среди, които се задвижват от изключително мощни вградени алгоритми за статичен анализ на кода (IntelliSense):
* **JetBrains Rider:** Крос-платформено IDE за .NET, което работи еднакво бързо на Windows, Linux и Mac (изключително популярно сред програмисти, които пишат C# на MacBook).
* **JetBrains WebStorm:** Специализирано IDE единствено за **Фронтенд разработка (JavaScript, TypeScript, Angular, React, Node.js)**. Притежава най-мощното автодопълнение за HTML5 тагове, CSS Box Model изчисления и Tailwind класове в движение.
* **IntelliJ IDEA:** Първоначално създадена като №1 среда за Java, но благодарение на разширената си екосистема поддържа перфектно HTML5, JavaScript и SQL. Тя автоматично засича дублирани кодови фрагменти в паметта и извършва дълбок одит на данните (Data Flow Analysis).

### 4.3. Традиционни и олекотени среди: NetBeans и Sublime Text 3
* **Apache NetBeans:** Напълно безплатна среда с отворен код. Притежава интуитивен графичен интерфейс с влачене и пускане (Drag-and-Drop). Силната ѝ страна е в **Семантичното подчертаване на кода** (Highlighting не просто правописа, а логическата роля на уеб елементите), което помага за писане на код без уеб бъгове (FindBug интеграция).
* **Sublime Text 3:** Свръхбърз, изключително лек и гъвкав текстов редактор. Не товари процесора и RAM паметта. Притежава вградена поддръжка за Macros и готови софтуерни Snippets. Идеален избор, когато ти трябва спешно отваряне и бърза козметична поправка на тежък HTML или CSS файл.

```text
 ┌───────────────────┬───────────────────────┬─────────────────────────────┐
 │ Среда (IDE)       │ Основен Фокус         │ Скорост на Рендериране      │
 ├───────────────────┼───────────────────────┼─────────────────────────────┤
 │ VS Code           │ Фронтенд / Лек уеб    │ 🚀 Свръхбързо (RAM леко)    │
 │ Visual Studio 2022│ Тежък C# Бекенд / SQL │ 🐢 Бавно (Enterprise товар) │
 │ JetBrains Rider   │ Крос-платформен .NET  │ 🟡 Средно (Много стабилно)  │
 │ WebStorm          │ Професионален SPA     │ 🟡 Средно (Дълбока защита)  │

```

## 6. СИСТЕМНИ КАПАНИ: АДМИНИСТРАТОРСКИ ПРАВА И ПРЕТОВАРВАНЕ НА RAM ПАМЕТТА

### 🚨 Капан №1: Блокиране на конзолните команди и разширенията (Permission Denied)
* **Какво се случва:** Инсталираш VS Code разширения или се опитваш да пуснеш локален уеб сървър през терминала, но системата хвърля черна грешка и отказва достъп.
* **Точен софтуерен краш (Exception Message) в конзолата:**
  ```text
  EACCES: permission denied, mkdir '/usr/local/lib/node_modules'
  (PowerShell Error: Script execution is disabled on this system. AuthorizationManager check failed.)
  ```
* **Как да го поправиш:** Проблемът идва от рестрикции на сигурността на Windows/Mac. Винаги стартирайте VS Code и терминала с **Администраторски права (Run as Administrator)**. На Windows отворете PowerShell като администратор и изпълнете командата за отключване на скриптове: `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser`.

### 🚨 Капан №2: Лаптопът забива и затваря Kestrel сървъра при старт на Visual Studio
* **Какво правиш:** Имаш компютър с 8 GB RAM памет. Стартираш Visual Studio 2022, за да пуснеш твоя DbContext, пускаш Docker контейнер за Redis и едновременно с това отваряш Chrome браузъра с 10 таба за проверка на CSS дизайна.
* **Точен софтуерен краш (Exception Message) в Windows:**
  ```text
  Your computer is low on memory. To restore enough memory for programs to work correctly, save your files and close all open windows.
  (Process terminated due to StackOverflowException or OutOfMemoryException)
  ```
* **Защо се случва:** За разлика от лекия VS Code или Sublime Text, традиционното Visual Studio заделя насила между 2 GB и 4 GB от твоята RAM памет веднага при стартиране само за поддръжка на вътрешния си компилационен индекс. Паметта свършва и операционната система убива уеб нишките.
* **Как да го избегнеш (Инженерно решение):** Ако хардуерът ти е ограничен, спазвай **декуплиран изпитен режим**: пиши HTML/CSS и фронтенд единствено в лекия VS Code, а тежките среди като Visual Studio или Rider ги пускай само тогава, когато се налага да правиш EF Core миграции или дебъгване на базата данни.
