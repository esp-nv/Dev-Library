# 00-02-00. Браузърна диагностика и Мрежова интеграция на средите

## 1. МРЕЖОВАТА ВРЪЗКА: КАК LIVE SERVER ПРЕНАСЯ ДАННИТЕ КЪМ CHROME

Когато кликнеш върху бутона **`Go Live`** в долния десен ъгъл на VS Code, разширението стартира лек фонов Node.js уеб сървър, който заделя локален мрежов порт (обикновено порт **`5500`**).

* **Локален адрес в браузъра:** `http://127.0.0` (или `http://localhost:5500`).
* **Механизъм на работа (WebSocket Channel):** Live Server инжектира скрито JavaScript парче код (`WebSocket` връзка) в уеб страницата. Когато промениш и запишеш нещо във VS Code, сървърът изпраща светкавичен пакет по WebSocket канала и кара Google Chrome да презареди страницата автоматично без твоя ръчна намеса.
* **Защо не отваряме файла с двоен клик (`file:///C:/...`)?** При директно отваряне от диска браузърът блокира модерни заявки (CORS политика) и не презарежда автоматично промените. Локалният HTTP сървър симулира реална продукционна среда.

---

## 2. СЕНЬОР ДЕБЪГВАНЕ: КОНЗОЛАТА И ПРОВЕРКА НА HTML/CSS ГРЕШКИ

Ако даден интерактивен бутон, изображение или стил спре да работи, отваряш **Chrome DevTools** чрез клавиша **`F12`** (или `Ctrl + Shift + I` / `Cmd + Option + I` на Mac):

* **Табът Console:** Твоят най-важен изпитен радар. Ако имаш правописна грешка в JavaScript, липсващ файл (`404 Not Found` за снимка или CSS файл) или счупена WebSocket връзка, тук веднага светва червена линия с точното софтуерно съобщение за грешка и номера на реда във VS Code.
* **Табът Elements:** Показва реалното, живо **DOM дърво** в RAM паметта на компютъра ти. Можеш да правиш промени по текстовете и CSS правилата директно в браузъра в реално време, за да тестваш как ще изглежда дизайнът, преди да го запишеш твърдо на диска.
* **Табът Network:** Проследява всяка една HTTP заявка (HTML, CSS, шрифтове, изображения, API заявки), нейния статус код (`200 OK`, `304 Not Modified`, `404 Not Found`) и времето за зареждане в милисекунди.

## 3. ИНТЕГРАЦИЯ МЕЖДУ СОФТУЕРНИТЕ ПРОЗОРЦИ (SIDE-BY-SIDE LAYOUT)

Индустриалният стандарт за висока скорост при изпити и уъркшопи е разделянето на екрана на две равни части (**Side-by-Side Layout** — на Windows с `Win + Left Arrow` и `Win + Right Arrow`):

* **Лява половина на монитора:** Разполагаш прозореца на VS Code.
* **Дясна половина на монитора:** Разполагаш прозореца на Google Chrome, отворен през Live Server, заедно с активния DevTools диагностичен панел отдясно или отдолу.

```text
 ┌───────────────────────────────────────┬───────────────────────────────────────┐
 │                                       │                                       │
 │         VS Code Editor                │         Google Chrome Browser         │
 │         (Ляв прозорец)                │         (Десен прозорец)              │
 │                                       │                                       │
 └───────────────────────────────────────┴───────────────────────────────────────┘
```

*Това ти позволява да виждаш как всяка единична написана буква отляво веднага се рендерира визуално и се проверява за грешки отдясно, вдигайки скоростта на писане двойно.*

---

## 4. СИСТЕМНИ КАПАНИ: КЕШИРАНИ СТАРИ ФАЙЛОВЕ (THE CACHE TRAP)

### 🚨 Капан №1: Браузърът показва стария дизайн, въпреки че кодът във VS Code е записан
* **Какво правиш:** Променяш цвета на даден блок в CSS файла и го записваш. Live Server опреснява браузъра, но на екрана си виждаш стария цвят. Изтриваш кода, пишеш го пак — нищо не се променя.
* **Защо се случва (Капанът на браузърния кеш):** С цел икономия на интернет трафик, браузърите притежават вградена памет, наречена **Cache (Кеш)**. Когато заредят тежък CSS или JS файл веднъж, те го заключват на твърдия диск (статус `200 (from disk cache)` в Network таба) и при следващо опресняване отказват да го прочетат от уеб сървъра, зареждайки старите кеширани байтове памет.
* **Как да го поправиш (Изпитен спасителен фикс):**
  1. Отвори DevTools с **`F12`**.
  2. Кликни с **десен бутон** върху иконата за опресняване на страницата (Refresh бутона със стрелката горе вляво до адресната лента).
  3. От падналото меню избери **`Empty Cache and Hard Reload` (Изпразване на кеша и насилствено презареждане)**.
  4. *Допълнителна защита:* В таба **Network** на DevTools сложи отметка на **`Disable cache`** — докато DevTools е отворен, браузърът никога няма да зарежда стари кеширани файлове.
