## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Руска матрьошка (Recursion):** Отваряш голяма кукла, вътре намираш по-малка, вътре още по-малка, докато стигнеш до най-малката, която не се отваря (**Base Case — Дъното на рекурсията**). След това започваш да ги затваряш една по една отвътре навън (**Unwinding**).
*   **Нишката на Ариадна в лабиринт (Backtracking):** Тръгваш по коридор в лабиринт и оставяш следа (**Choose / Mark**). Ако стигнеш до задънена улица, връщаш се една крачка назад и изтриваш следата (**Unchoose / Unmark**), за да пробваш следващия коридор.

## 2. КАК РАБОТИ CALL STACK В RAM ПАМЕТТА (БЛОК-СХЕМА)

Всяко извикване на функция заделя нова **Стекова рамка (Stack Frame)** в паметта, която пази локалните променливи и адреса за връщане.

```text
Извикване: factorial(3)

1. Навлизане (Push Frames в Stack):          2. Връщане назад (Pop Frames):
┌─────────────────────────┐                  ┌─────────────────────────┐
│ factorial(1) -> return 1│ ◄── ДЪНО (Base)  │ Връща 1                 │
├─────────────────────────┤                  ├─────────────────────────┤
│ factorial(2) -> 2 * ?   │                  │ 2 * 1 = 2               │
├─────────────────────────┤                  ├─────────────────────────┤
│ factorial(3) -> 3 * ?   │                  │ 3 * 2 = 6 (Краен изход) │
└─────────────────────────┘                  └─────────────────────────┘
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Критерий | Python 3.x | C# (.NET) | JavaScript (V8 / Node.js) |
| :--- | :--- | :--- | :--- |
| **Лимит на дълбочината** | **~1 000 нива** (строг защитен лимит) | Зависи от размера на стека (~1 MB / ~10 000 нива) | ~10 000 – 15 000 нива (според V8 версията) |
| **Грешка при препълване** | `RecursionError: maximum recursion depth exceeded` | `StackOverflowException` (**Убива процеса!**) | `RangeError: Maximum call stack size exceeded` |
| **Промяна на лимита** | `sys.setrecursionlimit(5000)` | `new Thread(fn, maxStackSize)` | Флаг `--stack-size` при старт на Node.js |
| **Tail Call Optimization (TCO)** | **Не се поддържа** (умишлено от Guido) | Само в специфични 64-bit JIT сценарии | Само в Safari (JavaScriptCore), не и в V8 |

## 4. ПЛЮСОВЕ И МИНУСИ НА РЕКУРСИЯТА СРЕЩУ ИТЕРАЦИЯТА

### 🟢 Предимства (Pros):
*   **Естествен код за дървовидни структури:** Обхождане на папки във файлова система, HTML DOM дърво, JSON парсване и графи се пишат в 10 реда с рекурсия, докато с цикъл и ръчен стек изискват 50 реда.
*   **Задължителна за Backtracking:** Генериране на пермутации, комбинации, решаване на Судоку и търсене на всички пътища в лабиринт.

### 🔴 Недостатъци (Cons):
*   **Висок разход на Stack памет (O(n) Space):** Всяко извикване пази променливите си в стека, докато цикълът `for`/`while` ползва O(1) памет.
*   **Експоненциално забавяне при припокриване (\(O(2^n)\)):** Наивният рекурсивен Фибоначи преизчислява едни и същи стойности милиони пъти.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Липсващо дъно и забравено изчистване при Backtracking):
```python
# 🚨 ГРЕШКА 1: Липсва дъно (Base Case) -> безкрайна рекурсия до RecursionError!
def countdown_broken(n: int):
    print(n)
    countdown_broken(n - 1)  # Никога не спира при n == 0!

# 🚨 ГРЕШКА 2: Backtracking без .pop() (Unchoose)!
def subsets_broken(nums, index, current, result):
    if index == len(nums):
        result.append(list(current))
        return
    current.append(nums[index])
    subsets_broken(nums, index + 1, current, result)
    # ЗАБРАВЕНО: current.pop() -> списъкът се пълни с боклуци от старите клонове!
```
*   **Как да се избегне:** Първите редове на всяка рекурсивна функция **винаги** трябва да проверяват дъното (`if base_condition: return`). При Backtracking всяко добавяне (`append` / `visited.add`) **задължително** има огледално премахване (`pop` / `visited.remove`) след рекурсивното извикване.

### 🟢 ПРАВИЛЕН КОД (Тристъпков Backtracking шаблон):
```python
def generate_subsets(nums: list[int]) -> list[list[int]]:
    result = []

    def backtrack(index: int, current: list[int]):
        # 1. BASE CASE (Дъно)
        if index == len(nums):
            result.append(current.copy())  # Задължително .copy(), защото current се мени!
            return

        # 2. CHOOSE (Включваме текущия елемент)
        current.append(nums[index])
        backtrack(index + 1, current)

        # 3. UNCHOOSE (Връщаме назад - чистим следата!)
        current.pop()
        backtrack(index + 1, current)

    backtrack(0, [])
    return result
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Защо при Backtracking алгоритми в Python, C# и JavaScript добавяме копие на списъка (`result.append(current.copy())` / `new List<int>(current)` / `[...current]`), вместо директно `result.append(current)`?“*
*   **Уловката:** Кандидатите пишат `result.append(current)` и накрая получават списък от вида `[[], [], [], []]` (всички елементи са празни)!
*   **Точен Senior отговор:** Променливата `current` е **референтен тип** в паметта (един и същ списък в Heap-а). Ако добавиш директно `current` в `result`, ти не запазваш моментна снимка на числата, а само **указател към същия списък**. В края на алгоритъма, когато Backtracking-ът изпразни `current` с `.pop()`, всички записи вътре в `result` сочат към вече празния списък! Затова **винаги** правим плитко копие (`.copy()` / `[...current]`) при достигане на дъното.
