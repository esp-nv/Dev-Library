## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Касиер в супермаркет (Coin Change):** Трябва да върнеш `1.80 лв.` ресто с възможно най-малко монети. Без да мислиш за всички комбинации, ти „алчно“ хващаш **най-голямата възможна монета**, която се побира в сумата (`1 лв.`), после следващата най-голяма (`50 ст.`), после `20 ст.` и `10 ст.`.
*   **Трите златни стъпки на почти всеки Greedy алгоритъм:**
    1.  **Сортирай (Sort):** Подреди входните данни по най-важния критерий (напр. най-голяма монета, най-ранен краен час, най-висока цена на килограм).
    2.  **Вземи най-доброто сега (Greedy Choice):** На всяка стъпка избери елемента, който изглежда най-изгоден в момента, **без да се връщаш назад**.
    3.  **Провери валидността (Feasibility Check):** Увери се, че изборът не нарушава ограниченията на задачата.

## 2. АРХИТЕКТУРЕН ПОТОК НА АЛЧНИЯ АЛГОРИТЪМ И БЛОК-СХЕМА

Пример за **Activity Selection (Избор на максимален брой срещи в 1 конферентна зала)**:

```text
Вход: Срещи с начален и краен час ➔ [ (1, 4), (3, 5), (0, 6), (5, 7), (8, 9) ]
                                          │
                                          ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ 1. СОРТИРАНЕ ПО КРАЕН ЧАС (Колкото по-рано свършва, толкова по-добре!)  │
│    Ред: (1, 4) ➔ (3, 5) ➔ (0, 6) ➔ (5, 7) ➔ (8, 9)                      │
└─────────────────────────────────────────┬───────────────────────────────┘
                                          ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ 2. АЛЧЕН ИЗБОР В ЦИКЪЛ (O(n)):                                          │
│    • Взимаме (1, 4) ➔ Залата е заета до 4:00 ч.                         │
│    • Пропускаме (3, 5) и (0, 6), защото почват преди 4:00 ч.            │
│    • Взимаме (5, 7) ➔ Започва след 4:00 ч. Залата е заета до 7:00 ч.    │
│    • Взимаме (8, 9) ➔ Започва след 7:00 ч. (Общо 3 срещи - МАКСИМУМ!)   │
└─────────────────────────────────────────────────────────────────────────┘
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: GREEDY СРЕЩУ DYNAMIC PROGRAMMING И BACKTRACKING

| Критерий | Greedy Algorithms | Dynamic Programming (DP) | Backtracking |
| :--- | :--- | :--- | :--- |
| **Стратегия** | Взима най-доброто решение **сега** | Решава всички подзадачи и пази таблица | Пробва всички пътища и се връща назад |
| **Връщане назад (Undo)** | **Никога** (решението е окончателно) | Не (комбинира готови подрезултати) | **Да** (изтрива избора при задънена улица) |
| **Типична сложност** | **\(O(n \log n)\)** (заради сортирането) | O(n²) или \(O(n \cdot W)\) | \(O(2^n)\) или O(n!) (експоненциална) |
| **Гарантира ли оптимум?** | **Само за специфични задачи** | **Да, винаги** | **Да, винаги** |
| **Класически примери** | Dijkstra, Kruskal, Fractional Knapsack | 0/1 Knapsack, Coin Change (общ случай) | Судоку, Лабиринт, N-Queens |

## 4. ПЛЮСОВЕ И МИНУСИ НА АЛЧНИТЕ АЛГОРИТМИ

### 🟢 Предимства (Pros):
*   **Изключително бързи и леки:** Обикновено се свеждат до едно сортиране (\(O(n \log n)\)) и едно линейно минаване (O(n)) с минимален разход на RAM памет (O(1)).
*   **Лесни за писане и обяснение:** Кодът им е кратък, чист и интуитивен.

### 🔴 Недостатъци (Cons):
*   **Късогледство (Локален оптимум ≠ Глобален оптимум):** Алчният алгоритъм не вижда последствията в бъдещето — в много задачи най-добрият избор на стъпка 1 води до катастрофа на стъпка 5.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Сортиране по начален час или продължителност при Activity Selection):
```python
def bad_activity_selection(activities: list[tuple[int, int]]) -> list[tuple[int, int]]:
    # 🚨 ГРЕШКА: Сортиране по НАЧАЛЕН час вместо по КРАЕН час!
    # Ако първата среща е от 08:00 до 20:00 ч. [(8, 20), (9, 10), (10, 11), (11, 12)],
    # тя ще блокира залата за целия ден и ще върне само 1 среща вместо 3!
    activities.sort(key=lambda x: x)
    selected = [activities]
    for start, end in activities[1:]:
        if start >= selected[-1][1]:
            selected.append((start, end))
    return selected
```
*   **Как да се избегне:** При задачи за планиране на интервали (Interval Scheduling) **винаги сортирай по КРАЙНИЯ час (`x[1]`)**, защото срещата, която свършва най-рано, освобождава ресурса най-бързо за останалите!

### 🟢 ПРАВИЛЕН КОД (Правилно сортиране по краен час):
```python
def select_max_activities(activities: list[tuple[int, int]]) -> list[tuple[int, int]]:
    if not activities:
        return []

    # Сортираме по КРАЕН час (x[1]) възходящо -> O(n log n)
    sorted_acts = sorted(activities, key=lambda x: x[1])
    selected = [sorted_acts]

    for start, end in sorted_acts[1:]:
        last_end = selected[-1][1]
        if start >= last_end:
            selected.append((start, end))

    return selected
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Кога алчният алгоритъм за връщане на ресто (`Coin Change`) **се проваля** и защо?“*
*   **Уловката:** В реалния свят валутните системи (Евро, Лев, Долар — `1, 2, 5, 10, 20, 50`) са специално проектирани като канонични системи, за да работи Greedy алгоритъмът. Но в алгоритмичните задачи монетите могат да бъдат произволни!
*   **Точен Senior отговор:** Представи си, че имаш монети **`[1, 3, 4]`** и трябва да върнеш сума **`6`**:
    *   **Greedy алгоритъмът** ще избере най-голямата монета `4`, а после две монети по `1` ➔ **`4 + 1 + 1` (общо 3 монети)**.
    *   **Истинският оптимум** е **`3 + 3` (общо 2 монети)**!
    *   *Извод:* При произволни номинали на монетите или при **0/1 Knapsack** (където предметите не могат да се режат на части), Greedy се проваля и **задължително** се използва **Dynamic Programming (Динамично оптимиране)**.
