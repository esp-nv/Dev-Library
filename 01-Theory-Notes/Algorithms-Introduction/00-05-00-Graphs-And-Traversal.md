## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **BFS (Breadth-First Search — Камъче във водата):** Когато хвърлиш камъче в езеро, вълните се разпространяват **по кръгове (ниво по ниво)** — първо най-близките съседи (на 1 крачка), после техните съседи (на 2 крачки). Използва **Опашка (Queue — FIFO)** и гарантирано намира **най-краткия път** в непретеглен граф!
*   **DFS (Depth-First Search — Смел изследовател в пещера):** Избираш един тунел и вървиш по него **до самия му край (дъното)**, преди да се върнеш назад и да пробваш друг тунел. Използва **Стек (Stack — LIFO)** или **Рекурсия**.
*   **Топологично сортиране (Подреждане на задачи с зависимости):** Като обличане сутрин — не можеш да обуеш обувките преди чорапите. Подрежда върховете на насочен граф без цикли (**DAG**), така че всяко предварително условие да стои преди зависимата от него задача.

## 2. ВИЗУАЛНА РАЗЛИКА МЕЖДУ BFS (ВЪЛНА) И DFS (ЛАБИРИНТ) И БЛОК-СХЕМА

Даден е граф: `1` е свързан с `2` и `3`; `2` е свързан с `4` и `5`.

```text
          (1)
         /   \
       (2)   (3)
      /   \
    (4)   (5)

1. BFS (В ширина - Опашка Queue):  1 ➔ 2, 3 ➔ 4, 5  (Ниво по ниво!)
2. DFS (В дълбочина - Стек/Рек.):  1 ➔ 2 ➔ 4 ➔ 5 ➔ 3 (До дъното на всеки клон!)
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: ADJACENCY LIST СРЕЩУ ADJACENCY MATRIX И ЕЗИЦИ

### А. Представяне на граф в паметта (V = върхове, E = ребра)

| Критерий | Adjacency List (Списък на съседите) | Adjacency Matrix (Матрица V × V) |
| :--- | :--- | :--- |
| **Разход на RAM памет** | **O(V + E)** (Много икономичен!) | **O(V²)** (Огромен разход при много върхове) |
| **Проверка дали има ребро (u, v)** | \(O(\text{degree}(u))\) (обхожда съседите на u) | **O(1)** (директно `matrix[u][v] == 1`) |
| **Обхождане на всички съседи на u** | **\(O(\text{degree}(u))\)** (виждаш само реалните) | O(V) (проверяваш целия ред от нули) |
| **Кога да го избереш** | **95% от задачите** (редки графи / Sparse) | Само при малки плътни графи (V ≤ 1000) |

### Б. Структури в Python, C# и JavaScript за графи

| Компонент | Python 3.x | C# (.NET) | JavaScript (ES6+) |
| :--- | :--- | :--- | :--- |
| **Списък на съседите** | `dict[int, list[int]]` / `defaultdict(list)` | `Dictionary<int, List<int>>` | `new Map()` (ключ ➔ масив) |
| **Опашка за BFS (O(1))** | `from collections import deque` (`popleft()`) | `Queue<int>` (`Dequeue()`) | Масив + индекс `head++` (`shift()` е O(n)!) |
| **Множество `visited`** | `visited = set()` | `var visited = new HashSet<int>();` | `const visited = new Set();` |

## 4. ПЛЮСОВЕ И МИНУСИ НА BFS И DFS

### 🟢 BFS (Обхождане в ширина) — Предимства и Недостатъци:
*   **Предимства:** Гарантирано намира **най-краткия път (с най-малко стъпки)** между два върха в непретеглен граф; никога не гърми със `StackOverflowError`.
*   **Недостатъци:** Изисква повече RAM памет при много широки графи (пази цялото текущо ниво в опашката).

### 🔵 DFS (Обхождане в дълбочина) — Предимства и Недостатъци:
*   **Предимства:** Пише се в 6 реда с рекурсия; заема по-малко памет при тесни и дълбоки графи; идеален за откриване на цикли, свързани компоненти и топологично сортиране.
*   **Недостатъци:** **Не гарантира най-кратък път**; при дълбоки графи (над 1000 върха в линия) рекурсивният вариант гърми с `RecursionError` в Python.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Маркиране в `visited` чак при вадене от опашката в BFS и забравен `visited` при цикличен граф):
```python
from collections import deque

def bfs_slow_buggy(graph: dict[int, list[int]], start: int):
    queue = deque([start])
    visited = set()

    while queue:
        node = queue.popleft()
        # 🚨 ГРЕШКА: Маркираш 'visited.add(node)' ЧАК ТУК при изваждането, вместо при добавянето!
        # Ако 50 върха сочат към един и същ съсед 'X', 'X' ще бъде вкаран в опашката 50 пъти!
        # Това води до експоненциално дублиране и Time Limit Exceeded!
        visited.add(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                queue.append(neighbor)
```
*   **Как да се избегне:** В BFS **винаги** добавяй върха в `visited` **веднага в момента, в който го слагаш в опашката (`queue.append(neighbor); visited.add(neighbor)`)**, никога при изваждането му!

### 🟢 ПРАВИЛЕН КОД (Светкавичен BFS без дублиране на върхове в опашката):
```python
from collections import deque

def bfs_shortest_path(graph: dict[int, list[int]], start: int, target: int) -> int:
    if start == target:
        return 0

    queue = deque([(start, 0)])  # (текущ_връх, разстояние_в_стъпки)
    visited = {start}            # Маркираме старта веднага!

    while queue:
        node, dist = queue.popleft()

        for neighbor in graph.get(node, []):
            if neighbor == target:
                return dist + 1
            if neighbor not in visited:
                visited.add(neighbor)  # Маркираме ВЕДНАГА при влизане в опашката!
                queue.append((neighbor, dist + 1))

    return -1  # Няма път до целта
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Каква е разликата между откриване на цикъл в **ненасочен (Undirected)** граф и в **насочен (Directed)** граф чрез DFS?“*
*   **Уловката:** Кандидатите използват едно и също множество `visited` и за двата вида графи, което в насочен граф дава фалшива тревога за цикъл!
*   **Точен Senior отговор:** 
    1.  **В ненасочен граф:** Реброто `A — B` е двупосочно. Когато отидем от `A` в `B`, `B` вижда `A` като свой съсед. Затова в DFS пазим параметър **`parent` (родител)** — ако видим посетен съсед, който **не е нашият директен `parent`**, значи има цикъл!
    2.  **В насочен граф (Directed Graph):** Може да имаме пътища `A ➔ B ➔ C` и отделно `A ➔ C` (това не е цикъл, а диамант!). Ако ползваме само един `visited` сет, при влизане в `C` втория път ще помислим, че има цикъл. Затова в насочен граф пазим **три състояния (3-Color Marking)**:
        *   `0` (Непосетен / White)
        *   `1` (**В текущия път на рекурсията / Gray** — *Recursion Stack*)
        *   `2` (Напълно обходен и безопасен / Black)
        *   Има цикъл **само ако попаднем на връх със състояние `1` (Gray)**!
