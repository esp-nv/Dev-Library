## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Linear Search (Линейно търсене — Разбъркано тесте карти):** Проверяваш картите една по една от първата до последната. Не се интересува дали са подредени, но в най-лошия случай минаваш през всичките N карти (O(n)).
*   **Binary Search (Двоично търсене — Играта „Познай числото от 1 до 100“):** За да отгатнеш числото възможно най-бързо, винаги питаш за средата (`50?`). Ако отговорът е „Нагоре“, изхвърляш всички числа от `1` до `50` наведнъж. За **4 милиарда записа** ти трябват най-много **32 въпроса** (\(O(\log_2 n)\))!
*   **Желязното условие на Binary Search:** Работи **само и единствено върху СОРТИРАНИ данни** (или върху монотонна функция, какъвто е патернът *Binary Search on Answer*).

## 2. КАК РАБОТИ BINARY SEARCH (РАЗДЕЛЯЙ И ВЛАДЕЙ) И БЛОК-СХЕМА

Търсим числото **`23`** в сортиран масив: `[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]`

```text
Стъпка 1: left = 0, right = 9  ➔  mid = 4 (стойност 16)
[ 2, 5, 8, 12, (16), 23, 38, 56, 72, 91 ]
                └── 23 > 16 ➔ Преместваме left = mid + 1 (5)

Стъпка 2: left = 5, right = 9  ➔  mid = 7 (стойност 56)
[ x, x, x, x, x | 23, 38, (56), 72, 91 ]
                           └── 23 < 56 ➔ Преместваме right = mid - 1 (6)

Стъпка 3: left = 5, right = 6  ➔  mid = 5 (стойност 23)
[ x, x, x, x, x | (23), 38 | x, x, x ]
                   └── 23 == 23 ➔ ✅ НАМЕРЕНО НА ИНДЕКС 5!
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Критерий | Python 3.x | C# (.NET) | JavaScript (ES6+) |
| :--- | :--- | :--- | :--- |
| **Линейно търсене** | `arr.index(x)` / `x in arr` | `Array.IndexOf(arr, x)` | `arr.indexOf(x)` / `arr.includes(x)` |
| **Вграден Binary Search** | Модул **`bisect`** (`bisect_left`) | `Array.BinarySearch(arr, x)` | **Няма вграден** (пише се на ръка) |
| **Изчисляване на среда (`mid`)** | `mid = (left + right) // 2` | `int mid = left + (right - left) / 2;` | `const mid = (left + right) >>> 1;` |

| **Сложност (Time / Space)** | \(O(\log n)\) Време / O(1) Памет (итеративно) | \(O(\log n)\) Време / O(1) Памет | \(O(\log n)\) Време / O(1) Памет |

## 4. ПЛЮСОВЕ И МИНУСИ НА АЛГОРИТМИТЕ ЗА ТЪРСЕНЕ

### 🟢 Предимства (Pros):
*   **Експоненциална скорост на Binary Search (\(O(\log n)\)):** При 1 милион елемента линейното търсене прави средно 500 000 проверки, докато двоичното прави едва 20.
*   **Нулев допълнителен разход на RAM (O(1) Space):** Итеративният Binary Search използва само три целочислени променливи (`left`, `right`, `mid`), без да заделя масиви или стекови рамки.

### 🔴 Недостатъци (Cons):
*   **Цена на предварителното сортиране:** Ако масивът не е сортиран, сортирането му струва \(O(n \log n)\). Ако ще търсиш само **веднъж**, линейното търсене (O(n)) е по-бързо от сортиране + двоично търсене! Binary Search се изплаща, когато търсиш многократно.
*   **Изисква директен достъп по индекс (O(1)):** Работи светкавично върху масиви (`list` / `Array`), но е неефективен върху свързани списъци (`LinkedList`), защото стигането до средата там отнема O(n) стъпки.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Безкраен цикъл, грешно условие `left < right` и Integer Overflow в C#):
```python
def binary_search_broken(arr: list[int], target: int) -> int:
    left, right = 0, len(arr) - 1
    
    # 🚨 ГРЕШКА 1: 'left < right' вместо 'left <= right'!
    # Ако масивът има 1 елемент [5] и търсим 5, цикълът изобщо не влиза и връща -1!
    while left < right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            # 🚨 ГРЕШКА 2: 'left = mid' без '+ 1'!
            # Когато left=0 и right=1, mid е 0 -> left остава 0 завинаги (Безкраен цикъл)!
            left = mid
        else:
            right = mid - 1
    return -1
```
*   **Как да се избегне:** За стандартно търсене винаги пиши **`while left <= right:`** и винаги премествай границите с **`left = mid + 1`** и **`right = mid - 1`**. В C#/Java/C++ винаги пиши `int mid = left + (right - left) / 2;`, за да избегнеш препълване на 32-битов `int`.

### 🟢 ПРАВИЛЕН КОД (Железен итеративен Binary Search):
```python
def binary_search(arr: list[int], target: int) -> int:
    left, right = 0, len(arr) - 1

    while left <= right:
        mid = left + (right - left) // 2  # Безопасна формула за средата

        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return -1
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Ако в сортиран масив има дубликати — например `[1, 2, 4, 4, 4, 4, 7, 9]` — и търсим числото `4`, кой индекс ще върне стандартният Binary Search и как го модифицираме, за да намерим **първото (най-лявото)** или **последното (най-дясното)** срещане?“*
*   **Уловката:** Стандартният Binary Search спира веднага при `if arr[mid] == target: return mid`, което при горния пример връща произволен среден индекс (`3`), а не началото или края на поредицата!
*   **Точен Senior отговор:** За да намерим **първото (най-лявото) срещане (Lower Bound)**, когато видим `arr[mid] == target`, **не спираме веднага**, а записваме `result = mid` и продължаваме да търсим наляво чрез **`right = mid - 1`**! Съответно за **последното (най-дясното) срещане (Upper Bound)** записваме `result = mid` и свиваме търсенето надясно чрез **`left = mid + 1`**. Така и двете граници се намират за гарантирано $O(\log n)$ време!
