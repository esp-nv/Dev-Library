## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Трите бавни алгоритъма (O(n²)):**
    *   **Bubble Sort (Мехурчета):** Най-големите числа изплуват най-отгоре вдясно като въздушни мехурчета във вода чрез размяна на съседни елементи.
    *   **Selection Sort (Избор):** Намираш най-малкото число в целия масив и го слагаш на първо място; после намираш второто най-малко и го слагаш на второ място.
    *   **Insertion Sort (Вмъкване — Карти в ръка):** Държиш сортирани карти в лявата си ръка, взимаш нова карта с дясната и я вмъкваш на точното ѝ място сред вече подредените.
*   **Двата бързи алгоритъма (\(O(n \log n)\)):**
    *   **Merge Sort (Сливане):** Разцепваш масива наполовина, докато останат единични числа, и после ги сливаш обратно в подреден вид (като две сортирани тестета карти).
    *   **Quick Sort (Бързо сортиране):** Избираш един **Pivot (опорен елемент)** и хвърляш всички по-малки от него вляво, а всички по-големи — вдясно.
*   **Какво е Стабилно сортиране (Stable Sort)?** Ако двама студенти имат еднаква оценка `6.00` (първо е „Анна“, после е „Борис“), стабилният алгоритъм гарантира, че след сортирането по оценка **„Анна“ винаги ще остане преди „Борис“**.

## 2. ВИЗУАЛНА СХЕМА НА MERGE SORT („РАЗДЕЛЯЙ И ВЛАДЕЙ“) И BIG O ТАБЛИЦА

```text
Масив: [ 38, 27, 43, 10 ]
            /          \
     [ 38, 27 ]      [ 43, 10 ]      ◄── 1. РАЗДЕЛЯНЕ (Divide: O(log n) нива)
      /      \        /      \
   [ 38 ]  [ 27 ]  [ 43 ]  [ 10 ]
      \      /        \      /
     [ 27, 38 ]      [ 10, 43 ]      ◄── 2. СЛИВАНЕ (Conquer / Merge: O(n) на ниво)
            \          /
        [ 10, 27, 38, 43 ]           ➔ Общо време: O(n log n)
```

### 📊 Сравнителна Big O таблица на алгоритмите за сортиране

| Алгоритъм | Най-добър случай | Среден случай | Най-лош случай | Допълнителна памет | Стабилен ли е? |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Bubble Sort** | O(n) (ако е сортиран) | O(n²) | O(n²) | O(1) (In-place) | **Да** |
| **Selection Sort** | O(n²) | O(n²) | O(n²) | O(1) (In-place) | **Не** |
| **Insertion Sort** | O(n) (ако е почти сортиран) | O(n²) | O(n²) | O(1) (In-place) | **Да** |
| **Merge Sort** | \(O(n \log n)\) | \(O(n \log n)\) | **\(O(n \log n)\)** | **O(n)** (нов масив) | **Да** |
| **Quick Sort** | \(O(n \log n)\) | \(O(n \log n)\) | **O(n²)** (лош Pivot) | \(O(\log n)\) (Stack) | **Не** |

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: ВГРАДЕНОТО СОРТИРАНЕ В PYTHON, C# И JS

| Език | Вграден метод | Алгоритъм под капака | Стабилен ли е? | Сортиране по ключ / компаратор |
| :--- | :--- | :--- | :--- | :--- |
| **Python 3.x** | `arr.sort()` / `sorted(arr)` | **Timsort** (Merge + Insertion Sort) | **Да** | `arr.sort(key=lambda x: x.age)` |
| **C# (.NET)** | `Array.Sort(arr)` / `list.Sort()` | **IntroSort** (Quick + Heap + Insertion) | **Не** (за `Sort`) | `list.Sort((a, b) => a.Age.CompareTo(b.Age))` |
| **C# LINQ** | `arr.OrderBy(x => x.Age)` | **Merge Sort** | **Да** | `arr.OrderBy(x => x.Age).ThenBy(x => x.Name)` |
| **JavaScript** | `arr.sort((a, b) => a - b)` | **Timsort** (в модерния V8 от ES2019) | **Да** | `arr.sort((a, b) => a.age - b.age)` |

## 4. ПЛЮСОВЕ И МИНУСИ НА ОСНОВНИТЕ АЛГОРИТМИ ЗА СОРТИРАНЕ

### 🟢 Merge Sort — Предимства и Недостатъци:
*   **Предимства:** Гарантирано \(O(n \log n)\) време дори в най-лошия случай; стабилен алгоритъм; идеален за сортиране на огромни файлове на диска (External Sorting) и свързани списъци (`LinkedList`).
*   **Недостатъци:** Изисква допълнителна RAM памет O(n) за временните масиви при сливането.

### 🔵 Quick Sort — Предимства и Недостатъци:
*   **Предимства:** Изключително бърз на практика заради отличната локалност на процесорния кеш (Cache Locality) и работа на място (`In-place`) без заделяне на нови масиви.
*   **Недостатъци:** Нестабилен; ако масивът вече е сортиран и винаги избираш първия или последния елемент за Pivot, деградира до бавното O(n²).

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Вграденият `.sort()` в JavaScript без числов компаратор и `Bubble Sort` без ранно спиране):
```javascript
// 🚨 ГРЕШКА 1 (Класически капан в JavaScript!):
const numbers =;
numbers.sort(); 
// Резултат: [10, 100, 2, 25, 5] !! 
// Без функция компаратор JavaScript превръща числата в СТРИНГОВЕ и ги сортира по азбучен ред!

// 🚨 ГРЕШКА 2: Bubble Sort без флаг 'swapped' -> върти O(n²) дори върху вече сортиран масив!
```
*   **Как да се избегне:** В JavaScript при сортиране на числа **винаги** подавай компаратор **`(a, b) => a - b`**. В Bubble Sort слагай булев флаг `swapped = False`, за да спреш цикъла на първото минаване без размени.

### 🟢 ПРАВИЛЕН КОД (Insertion Sort — най-бързият алгоритъм за малки и почти сортирани масиви):
```python
def insertion_sort(arr: list[int]) -> list[int]:
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        # Изместваме по-големите елементи надясно
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key
    return arr
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Защо модерните езици като Python (Timsort) и C# (IntroSort) превключват тайно към **Insertion Sort**, когато подмасивите станат по-малки от 16–32 елемента?“*
*   **Уловката:** Кандидатите знаят, че Insertion Sort е \(O(n^2)\), и се чудят защо професионални алгоритми го използват вътре в себе си!
*   **Точен Senior отговор:** Big O нотацията скрива константите. При малки масиви ($N \le 32$), **Insertion Sort** има много по-малко служебни операции (без рекурсивни извиквания на функции, без делене и без заделяне на допълнителни масиви) и данните се побират изцяло в **L1 кеша на процесора**. Затова при малки порции $O(n^2)$ алгоритъмът на практика бие $O(n \log n)$ алгоритмите по реални наносекунди!
