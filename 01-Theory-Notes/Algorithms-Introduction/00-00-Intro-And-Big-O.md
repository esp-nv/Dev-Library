## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Big O не мери секунди, а БРОЙ СТЪПКИ при растеж на данните (N):** На суперкомпютър бавен алгоритъм може да мине за 1 секунда при 100 елемента, но при 1 000 000 елемента ще увисне за 10 дни. Big O измерва как се променя броят операции в **най-лошия случай (Worst Case)**.
*   **Примери от реалния живот:**
    *   **O(1) (Константно време):** Взимаш първата книга най-отгоре на купчината — независимо дали купчината има 10 или 10 000 книги, правиш **1 движение**.
    *   **\(O(\log n)\) (Логаритмично време):** Търсиш дума в хартиен речник — отваряш по средата и на всяка стъпка изхвърляш половината страници. За 1 000 000 записа правиш едва **~20 стъпки**!
    *   **O(n) (Линейно време):** Четеш книга страница по страница, докато намериш конкретно име.
    *   **O(n²) (Квадратично време):** Всеки човек в стая от N души се ръкува с всеки друг човек (вложен цикъл `for` във `for`).

## 2. СКАЛА НА БЪРЗОДЕЙСТВИЕТО (BIG O ЙЕРАРХИЯ) И БЛОК-СХЕМА

От най-бързото (зелено) към най-бавното (червено) при N = 1000 елемента:

```text
O(1)         ➔  1 операция             (Светкавично: достъп по индекс / Hash Map)
  ▼
O(log n)     ➔  ~10 операции           (Много бързо: Binary Search)
  ▼
O(n)         ➔  1 000 операции         (Бързо: един цикъл for)
  ▼
O(n log n)   ➔  ~10 000 операции       (Добро: Merge Sort / Quick Sort / вграден .sort())
  ▼
O(n²)        ➔  1 000 000 операции     (Бавно: двоен вложен цикъл for)
  ▼
O(2ⁿ)        ➔  10³⁰⁰ операции!        (Катастрофа: наивна рекурсия без мемоизация)
```

## 3. СРАВНЕНИЕ НА ОПЕРАЦИИТЕ ВЪВ ВГРАДЕНИТЕ СТРУКТУРИ (PYTHON, C#, JS)

| Операция | Python (`list` / `set` / `dict`) | C# (`List<T>` / `HashSet<T>` / `Dictionary`) | JavaScript (`Array` / `Set` / `Map`) | Сложност |
| :--- | :--- | :--- | :--- | :--- |
| **Достъп по индекс** | `arr[5]` | `list[5]` | `arr[5]` | **O(1)** |
| **Добавяне в края** | `arr.append(x)` | `list.Add(x)` | `arr.push(x)` | **O(1)** (амортизирано) |
| **Вмъкване / Триене отпред** | `arr.insert(0, x)` / `pop(0)` | `list.Insert(0, x)` / `RemoveAt(0)` | `arr.unshift(x)` / `shift()` | **O(n)** (измества всички!) |
| **Търсене в списък** | `x in arr` | `list.Contains(x)` | `arr.includes(x)` | **O(n)** |
| **Търсене в Hash таблица** | `x in my_set` / `my_dict[k]` | `set.Contains(x)` / `dict[k]` | `set.has(x)` / `map.get(k)` | **O(1)** |
| **Сортиране на масив** | `arr.sort()` (Timsort) | `list.Sort()` (IntroSort) | `arr.sort()` (Timsort в V8) | **\(O(n \log n)\)** |

## 4. ЗЛАТНИ ПРАВИЛА ЗА ПРЕСМЯТАНЕ НА BIG O

1.  **Изхвърляй константите:** Ако алгоритъмът прави 2n + 5 операции, сложността му е просто **O(n)** (константите 2 и 5 се игнорират при големи числа).
2.  **Взимай само най-големия член (Dominant Term):** Ако сложността е \(O(n^2 + n + 100)\), при n = 10 000 членът n² е 100 000 000, а n е едва 10 000. Записваме само **O(n²)**.
3.  **Последователни цикли се събират, вложени цикли се умножават:**
    *   Два цикъла един след друг: O(n) + O(n) = O(2n) → **O(n)**.
    *   Един цикъл вътре в друг: O(n) × O(n) → **O(n²)**.

## 5. КОДОВ ОДИТ: O(n²) СРЕЩУ O(n) НА ПРАКТИКА

Задача: Проверка дали в даден списък има повтарящи се елементи (Duplicates).

### ❌ БАВЕН КОД — O(n²) Време, O(1) Памет (Двоен цикъл):
```python
def has_duplicates_slow(nums: list[int]) -> bool:
    n = len(nums)
    # Всяко число се сравнява с всички останали -> при 100 000 числа прави 10 милиарда стъпки!
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] == nums[j]:
                return True
    return False
```

### 🟢 БЪРЗ КОД — O(n) Време, O(n) Памет (Търговия на памет за скорост чрез `set`):
```python
def has_duplicates_fast(nums: list[int]) -> bool:
    seen = set()  # Hash Set гарантира O(1) проверка за наличие!
    for num in nums:
        if num in seen:
            return True
        seen.add(num)
    return False
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Каква е времевата сложност на конкатенацията на стрингове в цикъл (`s += char`) в Python, C# и JavaScript, и как се решава този скрит капан?“*
*   **Уловката:** Начинаещите мислят, че `s += "a"` в цикъл от $N$ стъпки е $O(n)$, докато всъщност е **$O(n^2)$**!
*   **Точен Senior отговор:** В Python, C# и JavaScript стринговете са **неизменяеми (Immutable)** в RAM паметта. При всяка итерация `s += char` компютърът не добавя буквата в края, а заделя изцяло нов блок памет и **копира целия натрупан до момента стринг** буква по буква ($1 + 2 + 3 + \dots + N = \frac{N(N+1)}{2} \rightarrow O(n^2)$)!
    *   **Правилен фикс ($O(n)$):** В Python събираме парчетата в списък и накрая викаме `"".join(parts)`; в C# ползваме **`StringBuilder`**; в JavaScript ползваме `array.push(part)` и `array.join("")`.
