## 1. ГЛОБАЛЕН МРЕЖОВ ПОТОК (ЕНД-ТО-ЕНД ЖИЗНЕНИ ЦИКЛИ)

Ето как пътува една HTTP заявка от момента, в който потребителят въведе уеб адрес или изпрати форма през браузъра, до запечатването на информацията на твърдия диск:

```text
 [ Браузър / Клиент ] 
         │
    (URL / JSON Request) ➔ [ Мрежа / DNS / Портове ]
                                    │
                         (Улавя суровите пакети)
                                    ▼
                          [ Уеб Сървър Kestrel ]
                                    │
                          (Middleware Конвейер)
                                    ▼
                         [ Presentation Controllers ]
                                    │
                          (Model Binding & DTOs)
                                    ▼
                          [ Service Logic Layer ]
                                    │
                           (LINQ / Fluent API)
                                    ▼
                         [ Data Access / DbContext ]
                                    │
                            (Суров SQL / @p0)
                                    ▼
                          [ Физическа SQL DB ]
```

## 2. КАРТА НА ПАМЕТТА ПРИ ТРИТЕ DEPENDENCY INJECTION ЦИКЪЛА

Ето визуална карта на поведението на Heap паметта, когато IoC контейнерът обработва заявки от двама паралелни потребители едновременно:

```text
  Потребител А (Заявка 1) ────────┐
                                 ├─> [ SINGLETON ИНСТАНЦИЯ ] ➔ (Живее вечно в RAM паметта)
  Потребител Б (Заявка 2) ────────┘

  Потребител А (Заявка 1) ───────────> [ SCOPED ИНСТАНЦИЯ X ] ➔ (Умира при край на Заявка 1)
  Потребител Б (Заявка 2) ───────────> [ SCOPED ИНСТАНЦИЯ Y ] ➔ (Умира при край на Заявка 2)

  Вътре в Заявка 1 (Поискване 1) ────> [ TRANSIENT ИНСТАНЦИЯ 1 ] 
  Вътре в Заявка 1 (Поискване 2) ────> [ TRANSIENT ИНСТАНЦИЯ 2 ] ➔ (Напълно пресъздаден нов обект)
```

## 3. ДВУПОСОЧНО ДВИЖЕНИЕ НА ТРАФИКА ПРЕЗ MIDDLEWARE КОНВЕЙЕРА

Ето чертеж на двупосочния софтуерен тръбопровод (Request Pipeline) в `Program.cs`. Заявката влиза отгоре-надолу, а отговорът се връща обратно в огледален ред:

```text
  HTTP Входяща Заявка ➔ 
                        │  [ ExceptionHandlerMiddleware ]  ▲
                        ▼                                  │ (Хваща крашове на връщане)
                        │  [ HttpsRedirectionMiddleware ]  ▲
                        ▼                                  │
                        │  [ StaticFilesMiddleware ]       ▲ ➔ (Бърз изход при снимки/CSS)
                        ▼                                  │
                        │  [ RoutingMiddleware ]           ▲
                        ▼                                  │
                        │  [ AuthenticationMiddleware ]    ▲ (Прочита бисквитки/токени)
                        ▼                                  │
                        │  [ AuthorizationMiddleware ]     ▲ (Проверява роли)
                        ▼                                  │
                          [ Реалният C# Контролер ] ───────┘
```

## 4. СРАВНИТЕЛЕН ЧЕРТЕЖ НА МОНОЛИТНА СРЕДА СРЕЩУ CLEAN ARCHITECTURE

### А. Монолитна MVC архитектура (Всичко събрано в една софтуерна кутия)
```text
  ┌─────────────────────────────────────────────────────────────┐
  │                    MyMonolithProject.App                    │
  │                                                             │
  │  [ Controllers ] ──> [ Models / DTOs ] ──> [ DbContext ]     │
  │         │                                        │          │
  │   (Рендерира)                              (Пише на диск)   │
  │         ▼                                        ▼          │
  │    [ Razor Views ]                         [ SQL Server ]   │
  └─────────────────────────────────────────────────────────────┘
```

### Б. Чиста архитектура (Clean Architecture — Четири изолирани нива)
```text
   [ 4. Presentation WebAPI ] ➔ Приема HTTP мрежовия трафик и рутира адреси
               │
               ▼
   [ 3. Application Services ] ➔ Ядрото. Чист C# бизнес код, интерфейси и DTOs
               │
               ▼
   [ 2. Infrastructure Data ] ➔ Външна обвивка. Управлява DbContext, SQL и Репозитори
               │
               ▼
   [ 1. Domain Entities ] ➔ Абсолютното дъно. Чисти базови обекти на таблиците
```
