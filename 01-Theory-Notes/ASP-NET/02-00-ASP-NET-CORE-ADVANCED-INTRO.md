## 1. ЗАЩО СЪЩЕСТВУВА ADVANCED МОДУЛЪТ (КАКВИ ПРОБЛЕМИ РЕШАВА?)

Когато едно уеб приложение премине фазата на базов прототип (Fundamentals) и се превърне в мащабна производствена система, софтуерните изисквания се променят драстично. Вече не е достатъчно просто да пренасяме форми и да пълним редове в базата данни.

**Advanced модулът отговаря за сигурността, мащабируемостта и инженерния одит на корпоративно ниво:**
1.  **Капсулиране на масови процеси:** Вместо да пишем ръчни проверки за сигурност или логове във всеки един от стотиците контролери, изграждаме централизирани филтри и къстъм Middleware компоненти, които прихващат трафика автоматично.
2.  **Защита на сървърния капацитет:** Оптимизираме работата на процесорните нишки (Thread Pool) чрез дълбоко неблокиращо асинхронно програмиране, предпазвайки Kestrel сървъра от изкуствено блокиране (Thread Starvation).
3.  **Хоризонтално мащабиране:** Преминаваме от монолитни MVC страници към декуплирани, безсъстоятелни RESTful уеб услуги (Web APIs), които могат да обслужват милиони паралелни заявки и да се деплояват лесно в Docker контейнери.

## 2. АРХИТЕКТУРЕН ПОТОК НА РАЗШИРЕНАТА ОБРАБОТКА

Ето как преминава входящата HTTP заявка през напредналите слоеве за филтриране и обработка в паметта, преди да роди крайния JSON отговор:

```text
  [ HTTP Request ] ──> [ Custom Middleware ] ➔ [ Authorization Filter ] ──> [ Action Filter ]
                                                                                   │
  [ HTTP Response ] <── [ JSON / REST Body ] <── [ Асинхронна Нишка (await) ] <────┘
```

---

## 3. ТРИТЕ ОСНОВНИ СТЪЛБА НА НАПРЕДНАТАТА УЕБ АРХИТЕКТУРА

*   **Custom Application Flow:** Разширяване на системния конвейер чрез собствени Middleware компоненти, Action филтри и Exception прихващачи за глобално управление на софтуерни грешки.
*   **Decoupled Web APIs:** Проектиране на чисти уеб услуги, работещи по правилата на REST стандарта, защитени с JWT (JSON Web Tokens) и напълно изолирани от фронтенд представянето.
*   **Performance Optimization:** Налагане на кеширащи стратегии (In-Memory / Distributed Caching) и сигурна асинхронна диагностика за избягване на Deadlocks в натоварени облачни среди.
