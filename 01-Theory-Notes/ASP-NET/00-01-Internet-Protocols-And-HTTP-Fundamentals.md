## 1. КАК ПЪТУВАТ ДАННИТЕ: ПАКЕТНА КОМУНИКАЦИЯ, IP И DNS

Всяка информация на компютъра се превежда до дигитални битове (нули и единици). За да се предаде тази памет по уеб мрежата, тя се разбива на малки парчета с фиксиран обем, наречени **Пакети (Packets)**. Всеки пакет пътува самостоятелно по наличните кабелни или сателитни трасета и се сглобява обратно на крайната дестинация.

### Координация на трафика:
*   **IP Адрес (Internet Protocol):** Уникален машинен координатен адрес. 
    *   *IPv4:* 32-битова структура, представена като четири числа, разделени с точка (напр. `216.58.214.46` — Google). Максималният капацитет е около 4.3 милиарда адреса, което е недостатъчно за съвременния свят.
    *   *IPv6:* 128-битова съвременна структура, представена в шестнадесетична бройна система и разделена с двоеточие (напр. `3FFE:F200:0234:AB00:0123:4567:8901:ABCD`). Осигурява практически неограничен брой адреси.
*   **DNS (Domain Name System):** Глобална децентрализирана база данни, работеща като „телефонен указател“. Превежда четимите от хора уеб домейни (напр. `www.softuni.bg`) в сурови машинни IP адреси, за да може браузърът да знае към кой сървър да отвори мрежова връзка.

## 2. ТРАНСПОРТНИЯТ СЛОЙ: TCP СРЕЩУ UDP И МРЕЖОВИТЕ МОДЕЛИ

За да се разбере къде живеят технологиите на ASP.NET Core, индустрията използва опростения 4-слоен модел **TCP/IP Protocol Suite**:

```text
 ┌─────────────────────────────────────────────────────────────────────────┐
 │ 4. Application Layer  ──> [ HTTP, HTTPS, DNS, SMTP, SSH, FTP ]          │
 ├─────────────────────────────────────────────────────────────────────────┤
 │ 3. Transport Layer    ──> [ TCP, UDP, QUIC ]                            │
 ├─────────────────────────────────────────────────────────────────────────┤
 │ 2. Internet Layer     ──> [ IP (IPv4 / IPv6), ICMP ]                    │
 ├─────────────────────────────────────────────────────────────────────────┤
 │ 1. Link Layer         ──> [ Ethernet, Wi-Fi, Physical Hardware / Wires ]│
 └─────────────────────────────────────────────────────────────────────────┘
```

Модерният уеб се върти около два коренно различни транспортни протокола:

### А. TCP (Transmission Control Protocol) — Надеждният одитор
*   **Философия:** Изгражда твърда софтуерна сесия между клиента и сървъра. Използва заглавната информация на пакетите, за да провери дали всички парчета са пристигнали, в какъв ред са и дали размерите им съвпадат. Ако открие изгубен пакет, спира процеса и изисква повторно изпращане.
*   **Търговски компромис (Trade-off):** Гарантира **100% надеждност на данните**, но носи по-високо мрежово забавяне (`Latency`) поради постоянните проверки. Основа за HTTP/1.1 и HTTP/2.

### Б. UDP (User Datagram Protocol) — Бързият куриер
*   **Философия:** Работи на принципа „изстреляй и забрави“ (Fire-and-forget). Изпраща пакетите по мрежата без предварително изградена сесия и без изобщо да го интересува дали отсрещната страна ги получава.
*   **Търговски компромис (Trade-off):** Гарантира **максимална скорост и минимално забавяне**, но има риск от загуба на данни (Missing packets). Основа за видео разговори, онлайн игри и модерния протокол QUIC (HTTP/3).

## 3. АНАТОМИЯ НА URL АДРЕСА И СУРОВИТЕ HTTP СЪОБЩЕНИЯ

Всеки уеб ресурс се локализира чрез уникален форматиран низ, наречен **URL (Uniform Resource Locator)**.

### Разглобяване на URL структурата:
```text
  http://  mysite.com  :8080  /demo/index.php  ?id=27&lang=en  #slides
  ───────  ──────────  ─────  ───────────────  ──────────────  ───────
 Protocol     Host      Port        Path        Query String   Fragment
```
*   **Port:** Цифров идентификатор на софтуерната врата на сървъра. Диапазонът е от `0` до `65535`. Порт по подразбиране за некриптиран `HTTP` е `80`, а за защитен `HTTPS` е `443`.

Когато клиентът извика този адрес, по мрежата се изпраща суров текст, разделен на три задължителни секции:

### 📥 1. Структура на сурова HTTP Заявка (Request):
```text
POST /demo/index.php HTTP/1.1                <── [Request Line: Метод, Път, Версия]
Host: mysite.com                             <── [Headers: Метаданни / Указания]
Content-Type: application/json
User-Agent: Mozilla/5.0
                                             <── [Задължителен празен ред!]
{ "id": 27, "lang": "en" }                   <── [Body: Полезен товар / JSON данни]
```

### 📤 2. Структура на суров HTTP Отговор (Response):
```text
HTTP/1.1 200 OK                              <── [Status Line: Версия, Статус код]
Date: Mon, 09 Nov 2026 16:30:00 GMT          <── [Headers: Информация за сървъра]
Content-Type: application/json
Content-Length: 34
                                             <── [Задължителен празен ред!]
{ "status": "success", "code": 200 }         <── [Body: Върнати данни от C#]
```

## 4. СРИВОВЕ В МРЕЖАТА: ЧЕСТИ ГРЕШКИ, ЕКСПЕШЪНИ И КОРЕКЦИЯ

Когато тестваш мрежова комуникация, в конзолата на твоето C# приложение или браузър могат да възникнат следните системни сривове:

### 🚨 Капан 1: Невалидно уеб име на хост (DNS Срив)
*   **Какво се случва:** Въвеждаш грешен уеб адрес или сървърът е изключен (напр. `https://softuni-fake-address.bg`).
*   **Точно съобщение за грешка (Exception Message) в C#:**
    ```text
    HttpRequestException: No such host is known. (SocketException: Error 11001)
    ```
*   **Защо се случва:** Браузърът или C# кодът се обръщат към локалния DNS сървър, но той не може да открие такова име в глобалната база данни и не може да върне IP адрес за свързване.
*   **Как да го избегнеш:** Провери уеб адреса за правописни грешки. Ако адресът е верен, тествай дали сървърът отговаря директно през неговия суров IP адрес, заобикаляйки DNS мрежата.

### 🚨 Капан 2: Зает или грешен Порт (Port Collision)
*   **Какво се случва:** Стартираш твоето ново ASP.NET Core приложение, но си оставила друго уеб приложение да работи на същия порт (напр. порт `5001`).
*   **Точен софтуерен Crash в конзолата при стартиране:**
    ```text
    IOException: Failed to bind to address https://127.0.0.1:5001: address already in use.
    ```
*   **Защо се случва:** Операционната система забранява на два различни софтуерни процеса да слушат и улавят пакети от една и съща цифрова врата (Port) едновременно.
*   **Как да го избегнеш:** Отвори файла `Properties/launchSettings.json` във твоето уеб приложение и промени цифрата на порта на напълно произволна свободна стойност (напр. `7214`).
