## 1. СВЕЩЕНИЯТ ГРААЛ НА JOIN ЗАЯВКИТЕ (ВИЗУАЛНИ СХЕМИ)

Когато извличаме информация от две релационно свързани таблици едновременно (напр. студенти и курсове), използваме оператора `JOIN`. Изборът на правилен тип връзка определя дали ще изгубим критични редове:

### А. INNER JOIN (Само пълните съвпадения)
Връща записи само тогава, когато стойността на външния ключ (`FK`) в лявата таблица съществува като първичен ключ (`PK`) в дясната таблица. Ако има несъвпадение, редовете отпадат напълно от финалния изход.

```text
   Таблица A (Students)             Таблица B (Courses)
 ┌─────────────────────┐          ┌─────────────────────┐
 │    Alex (Course 1)  │ ────────>│  1. C# Advanced     │  🎯 ИЗХОД:
 │   Maria (Course 1)  │ ────────>│                     │  - Alex -> C# Advanced
 │    Ivan (Course 99) │ ───X     │  2. ASP.NET Core    │  - Maria -> C# Advanced
 └─────────────────────┘          └─────────────────────┘
 (Ivan отпада изцяло от отчета, защото неговият курс 99 липсва в Таблица B)
```

### Б. LEFT JOIN (Всичко отляво + каквото съвпадне отдясно)
Връща абсолютно всички записи от лявата таблица (`Students`), независимо дали имат валидна връзка в дясната. Ако даден студент няма избран курс, срещу името му се принтира стойност `NULL`.

```text
   Таблица A (Students)             Таблица B (Courses)
 ┌─────────────────────┐          ┌─────────────────────┐
 │    Alex (Course 1)  │ ────────>│  1. C# Advanced     │  🎯 ИЗХОД:
 │   Maria (Course 1)  │ ────────>│                     │  - Alex -> C# Advanced
 │    Ivan (Course 99) │ ────────>│  [ NULL / Няма ]    │  - Maria -> C# Advanced
 └─────────────────────┘          └─────────────────────┘  - Ivan -> NULL
 (Ivan ОСТАВА в крайния резултат и системата не го заличава!)
```

## 2. ТРАНСАКЦИИ В ДЕЙСТВИЕ (БЕЗОПАСНО ИЗТРИВАНЕ)

Когато извършваме критични промени по данните (`UPDATE` или `DELETE`), ние ги обвиваме в трансакция, за да имаме пълно право на заден ход, ако установим грешка:

```text
  BEGIN TRANSACTION ──> Изпълняваме Удар (DELETE/UPDATE) ──> Проверяваме (SELECT)
                                                                    │
                                          ┌─────────────────────────┴─────────────────────────┐
                                      Доволни сме?                                       Има грешка?
                                          │                                                   │
                                          ▼                                                   ▼
                                       COMMIT                                              ROLLBACK
                                [ Запази трайно в DB ]                              [ Отмени и върни назад ]
```

### 🛠️ Практически пищов за Безопасно изтриване в SSMS:
```sql
-- 1. Започваме защитен прозорец в паметта
BEGIN TRANSACTION;

-- 2. Извеждаме удара (напр. изтриване на поръчки на клиент)
DELETE FROM Orders WHERE CustomerId = 5;

-- 3. Преди да потвърдим, проверяваме какво сме направили:
SELECT * FROM Orders WHERE CustomerId = 5;

-- 4. АКО СМЕ СГРЕШИЛИ И СМЕ ИЗТРИЛИ ПОВЕЧЕ РЕДОВЕ:
ROLLBACK; -- Данните се възстановяват мигновено на място!

-- 5. АКО ВСИЧКО Е ИДЕАЛНО И ТОЧНО:
-- COMMIT; -- Разархивирай този ред и го пусни, за да запишеш на диска трайно.
```

## 3. СИЛАТА НА WILDCARDS (ТЪРСЕНЕ ПО ШАБЛОН С LIKE)

Операторът `LIKE` в комбинация с Wildcards символи позволява гъвкаво търсене по частичен текстов модел. При работа с `NVARCHAR` колони, правилата за синтаксис са следните:

*   **`%` (Процент):** Замества нула или повече произволни символи.
    *   `LIKE N'Ма%'` ➔ Намира *Мария, Мартин, Магдалена*.
    *   `LIKE N'%ива%'` ➔ Намира *Иванова, Хаджииванов, Димитрова*.
*   **`_` (Долна черта):** Замества точно един произволен символ.
    *   `LIKE N'П_т_р'` ➔ Намира *Петър, Петър*.
*   **`[]` (Квадратни скоби):** Замества точно един символ, който трябва да бъде сред изброените вътре.
    *   `LIKE N'[МИ]ва%'` ➔ Намира *Мива, Ивана*, но отхвърля *Петър*.

## 4. ЧЕСТИ ГРЕШКИ, КАПАНИ И КАК ДА ГИ ИЗБЕГНЕМ

### Капан 1: Изчезващите редове при погрешен отчет с INNER JOIN
* **Какво се случва:** Правиш отчет за управителя колко студенти има по курсове. Използваш `INNER JOIN`. Накрая системата показва 80 студенти, а ти знаеш, че в базата са 100.
* **Защо се случва:** Останалите 20 студенти са новозаписани и още нямат избран курс (`CourseId = NULL`). Понеже `INNER JOIN` изисква 100% съвпадение, той тихо е изхвърлил тези 20 души от крайния списък.
* **Как да избегнеш:** За отчети, статистики и бизнес справки винаги използвай **`LEFT JOIN`**, за да не изгубиш данни, които все още нямат изградена релация.

### Капан 2: Забравен WHERE клауза при UPDATE или DELETE заявка
* **Какво се случва:** Пишеш бързо `UPDATE Students SET Grade = 6;` с цел да промениш оценката на Иван. Понеже си изпуснала `WHERE Id = 5`, базата данни мигновено записва пълни шестици на абсолютно всички студенти в училището.
* **Как да избегнеш:** Винаги първо пиши `SELECT * FROM Students WHERE Id = 5;`, за да се увериш, че филтърът ти хваща точно тези редове, които искаш да промениш, и чак тогава трансформирай заявката в `UPDATE` или `DELETE`.
