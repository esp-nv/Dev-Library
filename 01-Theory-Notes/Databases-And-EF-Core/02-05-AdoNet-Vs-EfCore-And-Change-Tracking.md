## 1. ТРАДЦИОНЕН ДОСТЪП ДО ДАННИ: СВЪРЗАН МОДЕЛ В ADO.NET

Преди появата на модерните ORM технологии, стандартният начин за комуникация с релационни бази в .NET беше библиотека **`ADO.NET`** (използваща NuGet пакета `Microsoft.Data.SqlClient`). Тя работи по т.нар. **Свързан модел (Connected Model)**.

### Пътят на данните при ADO.NET:
1.  **`SqlConnection`**: Ръчно отваряне на мрежова връзка към SQL Server чрез Connection String.
2.  **`SqlCommand`**: Ръчно дефиниране на SQL заявка като обикновен текстов стринг.
3.  **`SqlParameter`**: Ръчно подаване на променливи с цел защита от SQL Injection.
4.  **`SqlDataReader`**: Отваряне на бърз, еднопосочен поток (Reader), който чете редовете от базата данни един по един в реално време.
5.  **Ръчно мапване**: Програмистът е длъжен ръчно да прочете всяка колона и да я превърне в C# свойство (напр. `student.Age = reader.GetInt32(2);`).
6.  **Ръчно затваряне**: Изрично затваряне на Reader-а и връзката, за да не изтече памет.

*Основен недостатък:* Огромно количество повтарящ се (Boilerplate) код, липса на compile-time проверка за правописни грешки в заявките и ниска производителност при сложни релации.

## 2. КАКВО Е ORM И КАК ENTITY FRAMEWORK CORE УПРАВЛЯВА ВРЪЗКАТА

**ORM (Object-Relational Mapping)** е технология, която автоматизира целия този тежък процес, свързвайки релационните таблици директно с нашите обикновени C# класове (POCO обекти).

| Характеристика | Традиционно ADO.NET | Entity Framework Core (ORM) |
| :--- | :--- | :--- |
| **Писане на заявки** | Суров SQL текст вътре в C# кода. | Чист C# и обектно-ориентирани LINQ заявки. |
| **Управление на връзката** | Изцяло ръчно (`connection.Open() / Close()`). | Автоматично през жизнения цикъл на `DbContext`. |
| **Преобразуване (Mapping)**| Изцяло ръчно, ред по ред през `SqlDataReader`. | Автоматично трансформиране в .NET обекти. |
| **Проследяване на промени**| Няма. Трябва изрично да пишеш нов `UPDATE` скрипт. | Автоматично следене в паметта (Change Tracking). |

---

## 3. ЖИЗНЕН ЦИКЪЛ НА CHANGE TRACKING (КОГА ОБЕКТИТЕ СТАВАТ ПРОСЛЕДЕНИ?)

Всеки `DbContext` притежава компонент, наречен **ChangeTracker**. Той следи промените по обектите и знае точно кои редове трябва да бъдат добавени, променени или изтрити, когато накрая повикаш `.SaveChanges()`.

Един C# обект (Entity инстанция) става официално **Проследен (Tracked)** от паметта на EF Core в три конкретни случая:
1.  **При извличане от базата (Returned from a query):** Когато изпълниш LINQ заявка (напр. `.FirstOrDefault()`), изтеглените от SQL Server обекти автоматично влизат в ChangeTracker-а със статус `Unchanged`.
2.  **При изрично прикачване (Explicitly attached):** Когато в кода извикаш софтуерните методи **`.Add()`**, **`.Attach()`** или **`.Update()`**, обектът се регистрира в паметта съответно със статус `Added` или `Modified`.
3.  **При релационно откриване (Detected as new entities):** Ако добавиш нов обект към колекция на вече проследен родител (напр. `trackedEmployee.Projects.Add(newProject)`), EF Core автоматично открива новото дете и го маркира за вмъкване в SQL Server.

## 4. ДЕБЪГВАНЕ: ИЗВЛИЧАНЕ НА НАТИВЕН SQL ЧРЕЗ TOQUERYSTRING()

Един от най-големите страхове на разработчиците е, че ORM средите генерират бавен и лош SQL код зад кулисите. За да провериш и анализираш точния SQL текст, който EF Core ще изпрати към сървъра, .NET ни предоставя вградения метод **`.ToQueryString()`**.

### Как се използва в реалния код:
Вместо да материализираш заявката с `.ToList()`, извикваш метода директно върху `IQueryable` веригата:

```csharp
// 1. Изграждаме LINQ заявката (Тя все още НЕ е изпълнена в базата данни!)
var query = context.Employees
    .Where(e => e.JobTitle == "Design Engineer"); // 0.1.37

// 2. Извличаме суровия SQL текст, който се крие зад C# кода
string nativeSql = query.ToQueryString(); // 0.1.41

// 3. Отпечатваме го в конзолата за анализ
Console.WriteLine(nativeSql);
```

### Финален изход в конзолата (Генерираният от EF Core SQL текст):
```sql
SELECT [e].[Id], [e].[FirstName], [e].[LastName], [e].[JobTitle]
FROM [Employees] AS [e]
WHERE [e].[JobTitle] = N'Design Engineer'
```
