## 1. ЗАЩО СЪЩЕСТВУВАТ ТЕЗИ ЗАЩИТИ (КАКЪВ ПРОБЛЕМ РЕШАВА АРХИТЕКТУРАТА?)

В големите бизнес системи (като ERP платформи, банкови софтуери и счетоводни системи) `ApplicationDbContext` не е просто плосък списък от таблици. Той работи като **Централен команден пункт и Главен пазител на сигурността**.

Вместо да разчитаме, че външните потребители, фронтендът или уеб контролерите винаги ще въвеждат и трият данните правилно, този шаблон налага **железни глобални правила директно на ниво Entity Framework Core**, преди данните изобщо да стъпят физически във файловете на SQL Server:
1.  **Предотвратява случайно изтриване** на критични системни настройки и конфигурационни котви, без които дизайнът на приложението ще се счупи фатално.
2.  **Забранява каскадното заличаване** на финансова или бизнес история, налагайки пълна счетоводна сигурност.
3.  **Скрива данните от потребителския интерфейс**, без реално да ги трие от диска (Soft Delete), запазвайки пълната одиторска следа за регулаторите.

---

## 2. АРХИТЕКТУРЕН ПОТОК НА ПРИХВАЩАНЕ НА ЗАЯВКИТЕ

Ето как преминава всяка операция за четене или запис през твоя команден център, преди да бъде преведена до SQL Server:

```text
   [ UI / Уеб Контролер ] ──> Заявка за промяна (Add / Update / Delete)
                                        │
                                        ▼
                     ┌──────────────────────────────────────┐
                     │        ApplicationDbContext          │
                     ├──────────────────────────────────────┤
                     │ 1. Сканира паметта (ChangeTracker)   │
                     │ 2. Извиква EnforceGlobalProtection() │ ──> [ Блокира промяна на Котва №1 / Проверява защитени ID-та ]
                     │ 3. Налага Глоб. Филтри (QueryFilter) │ ──> [ Скрива Soft Deleted записи / Автоматично WHERE IsDeleted=0 ]
                     └──────────────────────────────────────┘
                                        │
                               ( base.SaveChanges() )
                                        │
                                        ▼
                             [ Физически SQL Server ]
```

## 3. ТРИТЕ СТЪЛБА НА НАПРЕДНАТАТА DBCONTEXT ЗАЩИТА

Сигурността в този шаблон се крепи на три независими софтуерни компонента:
*   **Жизнен цикъл на SaveChanges (Theme & System Protection):** Пренаписване на фабричния `SaveChanges()` метод с цел автоматично сканиране на транзитната памет (`ChangeTracker`) за опити за модификация на забранени системни редове.
*   **Глобални филтри за Скриване (Soft Delete):** Автоматично инжектиране на допълнителни филтри към абсолютно всяка LINQ заявка зад кулисите, изолирайки изтритите записи от потребителския интерфейс.
*   **Глобално ограничаване на каскадите:** Пренаписване на релационните метаданни на базата с цел спиране на масовите заличавания тип „домино“.
