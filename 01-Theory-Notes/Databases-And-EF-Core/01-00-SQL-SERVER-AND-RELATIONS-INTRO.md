## 1. МОСТЪТ МЕЖДУ СВЕТОВЕТЕ (SQL SERVER ➔ C#)

При Code-First подход или при проектиране на структури от данни, правилното съответствие на типовете определя бързодействието на приложението:

| SQL Server Тип данни | C# Тип данни | Основно предназначение в софтуера |
| :--- | :--- | :--- |
| **`INT`** | `int` | Стандартни броячи, вътрешни числа и Primary Keys (`Id`). |
| **`BIGINT`** | `long` | Идентификатори за огромни масиви от данни (над 2 милиарда редове). |
| **`DECIMAL(18,2)`** | `decimal` | **Парични и точни стойности.** Задължителен за суми, сметки и баланси. |
| **`BIT`** | `bool` | Логически флагове, приемащи само `0` (False) или `1` (True). |
| **`VARCHAR(n)`** | `string` | Стандартен текст на латиница (заема 1 байт на символ). |
| **`NVARCHAR(n)`** | `string` | **Unicode текст. Задължителен за кирилица и български имена.** |
| **`DATETIME2`** | `DateTime` | Модерен стандарт за прецизна дата и час (напр. `CreatedAt`). |
| **`UNIQUEIDENTIFIER`** | `Guid` | Глобално уникален идентификатор, генериран в C# без заявка към БД. |

> **Правило за Nullable стойности:** Ако в SQL колоната е дефинирана като `NULL` (може да няма стойност), в C# типът задължително се декларира като nullable (напр. `INT NULL` ➔ `int?`, `BIT NULL` ➔ `bool?`).

## 2. МИСЛОВНАТА СТЪЛБА: СИНТАКТИЧНА ПОДРЕДБА НА SQL ЗАЯВКИТЕ

Когато пишеш SQL заявка, я изграждаш по строго дефинирана синтактична подредба:

```text
  1. SELECT     --> [ Какво точно искам да покажа на екрана като колони? ]
  2. FROM       --> [ От коя основна таблица тръгвам? ]
  3. JOIN / ON  --> [ Кои съседни таблици добавям и по какъв общ ключ? ]
  4. WHERE      --> [ Кои конкретни сурови редове оставям (Филтър преди групиране)? ]
  5. GROUP BY   --> [ По коя колона искам да разделя данните на групи? ]
  6. HAVING     --> [ Кои от вече създадените групи искам да оставя (Филтър)? ]
  7. ORDER BY   --> [ Как да сортирам крайния резултат (ASC / DESC)? ]
```

### Логически път на изпълнение от двигателя (Посока на мисълта):
```text
 FROM ──> JOIN ──> WHERE ──> GROUP BY ──> HAVING ──> SELECT ──> ORDER BY
```

## 3. СИГУРНОСТ НА ПРОМЕНИТЕ: TRANSACTION, COMMIT И ROLLBACK

При извършване на критични промени по данните (`UPDATE` или `DELETE`), те винаги се обвиват в трансакция, за да се гарантира принципа на атомарност (всичко или нищо):

*   **`BEGIN TRANSACTION;`** — Отваря защитен прозорец в паметта. Всички промени след него са временни.
*   **`COMMIT;`** — Потвърждава и записва промените трайно на диска, ако всичко е изпълнено правилно.
*   **`ROLLBACK;`** — Незабавно прекратява трансакцията и връща базата в начално състояние, ако се установи грешка.
