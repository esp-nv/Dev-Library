## 1. ЗАЩО НИ Е НУЖЕН EF CORE (КАКЪВ ПРОБЛЕМ РЕШАВА?)

В миналото, за да запишем данни от C# в SQL Server, бяхме длъжни да използваме чист `ADO.NET` — да пишем сурови SQL заявки като обикновен текст вътре в C# кода (`"INSERT INTO Students..."`), да отваряме и затваряме ръчно мрежови връзки към сървъра и да мапваме редовете от таблицата обратно към обекти. Това водеше до огромно количество досаден код и лесни правописни грешки.

**Entity Framework Core (EF Core) работи като ORM (Object-Relational Mapper).** Той служи за „автоматичен двупосочен преводач“ — превръща нашите чисти C# класове в SQL таблици и обратно. Ние пишем само структуриран C# код и LINQ заявки, а EF Core генерира и оптимизира SQL заявките зад кулисите вместо нас.

---

## 2. АНАЛОГИЯ ОТ РЕАЛНИЯ ЖИВОТ (ТЕФТЕРЪТ НА ПРЕВОДАЧА)

Представи си автоматичен преводач между български и китайски език. Ти си C# програмистът и говориш само български (C# обекти и свойства). Базата данни е китайски ресторант (SQL Server), който разбира и изпълнява команди само на китайски (SQL заявки). 

Вместо ти да учиш китайски, наемаш преводач (EF Core). Ти му казваш на български: *„Добави нов студент Иван“*, преводачът си записва това в своя служебен тефтер (`DbContext`), превежда го правилно на китайски (`INSERT INTO school_students...`) и го изпраща директно към кухнята (Базата данни).

## 3. ХРОНОЛОГИЯ НА МИГРАЦИИТЕ (ПЪЛЕН CLI КОМАНДЕН ДНЕВНИК)

Управлението на базата данни при Code-First подход се извършва през **Package Manager Console (PMC)** чрез четири фундаментални команди. Те управляват жизнения цикъл на кода и структурата на диска:

```text
               КОМАНДЕН ЖИЗНЕН ЦИКЪЛ НА КОДА И БАЗАТА ДАННИ
               
  [ Написан C# код ] ──( Add-Migration )──> [ Създаден файл-рецепта в C# ]
                                                       │
                                              ( Remove-Migration ) -> Изтрива локалния файл
                                                       │ (ако не е пратен в DB)
                                                       ▼
  [ Реална SQL DB ]  <──( Update-Database ) <──────────┘
           │
     ( Drop-Database ) ──> Пълно изтриване на физическата база данни от диска
```

*   **`Add-Migration InitialCreate`** — Сканира C# моделите и генерира C# файлове-рецепти в папка `Migrations`. Базата данни на диска все още **НЕ** е променена.
*   **`Update-Database`** — Взема генерираните рецепти, превежда ги на SQL и ги изпълнява в SQL Server. Чак в тази милисекунда промените се раждат физически на диска.
*   **`Remove-Migration`** — Изтрива последния генериран миграционен файл. Работи **само ако все още не си изпълнила** `Update-Database`.
*   **`Drop-Database`** — Изпраща команда към SQL Server и изтрива напълно физическия файл на базата данни (`.mdf` и `.ldf`) от твърдия диск, за да започнеш на чисто.
