## 🏛️ 1. ЗАЩО НИ Е НУЖЕН SQL SERVER (Какъв проблем решава?)

В релационните бази данни е критично **да не дублираме информация** и да съхраняваме данните в строго структуриран вид. Вместо да пазим името на курса, цената му и името на лектора във всеки отделен ред за всеки студент, ние разделяме данните в отделни таблици и ги свързваме чрез ключове.

### 💡 Аналогия от живота
**Гардероб с кутии за обувки.** Вместо да държиш обувките си разхвърляни по пода, ти купуваш кутии. Всяка кутия си има уникален етикет-номер (`PK` - Първичен ключ). На твоя лист-дневник (`Students`) ти не рисуваш обувката – просто записваш: *„Обувки за бягане → виж в Кутия №1“* (`CourseId` - Външен ключ).

## 📊 2. МИСЛОВНАТА СТЪЛБА: СИНТАКТИЧНА ПОДРЕДБА НА SQL

Когато пишеш или четеш SQL заявка, ти я изграждаш по следната максимална стандартна подредба (стълба). Не всяка задача изисква всички стъпки, но редът им е закован:

```text
  1. SELECT     --> [ Какво точно искам да покажа на екрана? ]
  2. FROM       --> [ От коя основна таблица тръгвам? ]
  3. JOIN / ON  --> [ Кои съседни таблици добавям и по какъв ключ? ]
  4. WHERE      --> [ Кои конкретни сурови РЕДОВЕ оставям (Филтър)? ]
  5. GROUP BY   --> [ По коя колона искам да разделя данните на ГРУПИ? ]
  6. HAVING     --> [ Кои от вече създадените ГРУПИ искам да оставя? ]
  7. ORDER BY   --> [ Как да сортирам крайния резултат (ASC / DESC)? ]
```

### 🧠 Как четем логически готов SQL код (Посока на мисълта):
```text
 FROM (Откъде?) ──> JOIN (Свързвам ли?) ──> WHERE (Редове?) ──> GROUP BY (Групи?) ──> HAVING (Групи филтър?) ──> SELECT (Покажи) ──> ORDER BY (Сортирай)
```

## 🔤 3. МОСТЪТ МЕЖДУ СВЕТОВЕТЕ: SQL SERVER ТИПОВЕ ДАННИ ──> C#

При Code-First подход или при проектиране на таблици (като в `StudentManagement` и `EnterpriseReportSystem`), мапингът на типовете данни определя производителността на паметта:

| SQL Server Тип данни | C# Тип данни | Какъв проблем решава / Къде се използва? |
| :--- | :--- | :--- |
| **`INT`** | `int` | За стандартни броячи, вътрешни числа и Идентификатори (`Id`). |
| **`BIGINT`** | `long` | За огромни числа (над 2 милиарда записи). |
| **`DECIMAL(18,2)`**| `decimal` | **Парични и точни стойности.** Задължителен за суми и баланси! |
| **`BIT`** | `bool` | Съхранява само `0` (False) или `1` (True). (напр. `IsActive`). |
| **`VARCHAR(n)`** | `string` | Текст на латиница (заема 1 байт на символ). |
| **`NVARCHAR(n)`** | `string` | **Unicode текст. Задължителен за кирилица (български имена)!** |
| **`DATETIME2`** | `DateTime` | Модерен, точен стандарт за дата и час (напр. `CreatedAt`). |
| **`UNIQUEIDENTIFIER`**| `Guid` | Глобално уникален идентификатор (`Guid.NewGuid()`). |

### 🛡️ Управление на NULL стойности (Nullable Types):
Ако в SQL колоната е дефинирана като `NULL` (може да няма стойност), в C# стойността **задължително** трябва да бъде nullable:
*   SQL: `Age INT NULL` \(\longrightarrow\) C#: `public int? Age { get; set; }`
*   SQL: `Price DECIMAL(18,2) NULL` \(\longrightarrow\) C#: `public decimal? Price { get; set; }`

## 🔀 4. СВЕЩЕНИЯТ ГРААЛ НА JOIN ЗАЯВКИТЕ (Визуални Схеми)

### 🤝 A. INNER JOIN (Само пълните съвпадения)
Връща записи, само ако стойността на външния ключ съществува и в двете таблици. Ако има несъвпадение, редовете отпадат.

```text
   Таблица A (Students)             Таблица B (Courses)
 ┌─────────────────────┐          ┌─────────────────────┐
 │    Alex (Course 1)  │ ────────>│  1. C# Advanced     │  🎯 ИЗХОД:
 │   Maria (Course 1)  │ ────────>│                     │  - Alex -> C# Advanced
 │    Ivan (Course 99) │ ───X     │  2. ASP.NET Core    │  - Maria -> C# Advanced
 └─────────────────────┘          └─────────────────────┘
 (Ivan отпада, защото курс 99 липсва в Таблица B)
```

### ⬅️ B. LEFT JOIN (Всичко отляво + каквото съвпадне отдясно)
Връща **абсолютно всички** записи от лявата таблица (`Students`), независимо дали имат записан курс. Ако нямат, връща `NULL`.

```text
   Таблица A (Students)             Таблица B (Courses)
 ┌─────────────────────┐          ┌─────────────────────┐
 │    Alex (Course 1)  │ ────────>│  1. C# Advanced     │  🎯 ИЗХОД:
 │   Maria (Course 1)  │ ────────>│                     │  - Alex -> C# Advanced
 │    Ivan (Course 99) │ ────────>│  [ NULL / Няма ]    │  - Maria -> C# Advanced
 └─────────────────────┘          └─────────────────────┘  - Ivan -> NULL
 (Ivan ОСТАВА в крайния резултат, системата не го изхвърля!)
```

## 🔒 5. СИГУРНОСТ НА ДАННИТЕ: TRANSACTION, COMMIT И ROLLBACK

Когато извършваме критични промени (CRUD операции като `UPDATE` и `DELETE`), ние ги обвиваме в **Трансакция**, за да ги третираме като едно цяло и да имаме право на заден ход, ако сгрешим.

```text
  BEGIN TRANSACTION ──> Изпълняваме Удар (DELETE/UPDATE) ──> Проверяваме (SELECT)
                                                                    │
                                          ┌─────────────────────────┴─────────────────────────┐
                                      Доволни сме?                                       Има грешка?
                                          │                                                   │
                                          ▼                                                   ▼
                                       COMMIT                                              ROLLBACK
                                [ Запази трайно в DB ]                              [ Отмени и върни назад ]
```

### 🛠️ Практически пищов за Безопасно изтриване:
```sql
BEGIN TRANSACTION;

-- Изтриваме конкретен клиент
DELETE FROM Orders WHERE CustomerId = 5;

-- Преди да е станало късно, проверяваме какво сме направили:
SELECT * FROM Orders WHERE CustomerId = 5;

-- Ако сме изтрили нещо грешно:
ROLLBACK; -- Базата се връща в начално състояние!

-- Ако всичко е перфектно:
-- COMMIT;
```
## 🔎 5.5. СИЛАТА НА WILDCARDS (Търсене по шаблон с LIKE)

Операторът **`LIKE`** в комбинация с Wildcards надгражда точното равенство (`=`), позволявайки гъвкаво търсене по частичен текст (подобно на кръстословиците) 

### Основни Wildcard символи с `NVARCHAR`:
* **`%`**: Нула или повече символи (напр. `LIKE N'Ма%'` за *Мария, Мартин*) .
* **`_`**: Точно един произволен символ (напр. `LIKE N'П_т_р'`).
* **`[]` / `[^]`**: Един символ съответно от списък или извън него (напр. `LIKE N'[МИ]ва%'`) .

---

## 🚨 ЧЕСТИ ГРЕШКИ И РЕШЕНИЯ

*   **Ситуация А (Счупен синтаксис):** Липса на кавички около шаблона (`LIKE [Ма%]`) води до грешка `Msg 102`, тъй като скобите се четат като колона .
          Решение: `LIKE N'[Ма]%'` .
*   **Ситуация Б (Търсене на реални `%` или `_`):** Използване на `ESCAPE` клаузата с наклонена черта (`\`) за нулиране силата на символа .
*   **Ситуация В (Празен изход при фиксиран `CHAR`):** Допълване с интервали изисква добавяне на процент накрая (`LIKE N'Мария%'`) .

## ❌ 6. КРИТИЧНИ SQL КАПАНИ

1. **UPDATE/DELETE без WHERE:** Променя или изтрива цялата таблица .
2. **WHERE срещу HAVING:** Филтриране съответно преди или след `GROUP BY`.
3. **Забравеният префикс N:** Води до питанки (`???`) при кирилица .
4. **Невалидни колони в GROUP BY:** Позволява само групиращата колона или агрегати .
5. **Reverse не е сортиране:** `Reverse()` само обръща текста огледално.
6. **INNER JOIN изтрива NULL редове:** За отчети винаги е за предпочитане `LEFT JOIN`.
