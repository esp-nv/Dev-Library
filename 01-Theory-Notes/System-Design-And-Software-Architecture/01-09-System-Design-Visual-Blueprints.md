## СХЕМА 1: ХОРИЗОНТАЛНО МАЩАБИРАН УЕБ КЛЪСТЕР С REDIS КЕШ

Тази диаграма визуализира пътя на входящия потребителски трафик през Nginx балансьор, който разпределя пакетите към три безсъстоятелни (Stateless) Kestrel инстанции, четейки от общ споделен паметен кеш.

```text
       [ Милиони Потребители / Браузъри ]
                       │
                       ▼ (HTTP Request)
         ┌───────────────────────────┐
         │   Nginx Load Balancer     │ ➔ Алгоритъм: Least Connections / Round Robin
         └─────────────┬─────────────┘
                       │
         ┌─────────────┼─────────────┐ (Разпределя трафика хоризонтално)
         ▼             ▼             ▼
  ┌───────────┐ ┌───────────┐ ┌───────────┐
  │  Kestrel  │ │  Kestrel  │ │  Kestrel  │ ➔ Безсъстоятелни .NET App сървъри
  │  Server 1 │ │  Server 2 │ │  Server 3 │
  └─────┬─────┘ └─────┬─────┘ └─────┬─────┘
        │             │             │
        └─────────────┼─────────────┘
                      │
        ┌─────────────┴─────────────┐
        ▼                           ▼
 ┌───────────────┐           ┌───────────────┐
 │  Redis Cache  │           │ Master SQL DB │
 │ (RAM Cluster) │           │ (Write Only)  │
 └───────────────┘           └───────────────┘
   [ Cache Hit ]               [ Cache Miss ]
   (Светкавичен                (Бавно четене
    отговор в ms)               от твърд диск)
```

## СХЕМА 2: СИНХРОННА gRPC VS. АСИНХРОННА RABBITMQ КОМУНИКАЦИЯ

Чертежът показва фундаменталната разлика между силното времево обвързване (gRPC) и декуплираната събитийна комуникация през опашки от съобщения (RabbitMQ).

### А. Синхронен gRPC поток (Блокиращ — Temporal Coupling)
```text
 [ Order Микроуслуга ] ───CheckStockAsync() (Бинарен HTTP/2) ───> [ Inventory Микроуслуга ]
        │                                                                   │
  (Нишката ЗАМРЪЗВА                                                   (Изчислява паметта
   в чакане на отговор)                                                и връща байтове)
        ▲                                                                   │
        └───────────────────── [ StockResponse ] ───────────────────────────┘
```

### Б. Асинхронен RabbitMQ поток (Неблокиращ — Event-Driven)
```text
 [ Order Микроуслуга ] ➔ (Publish Event) ➔ [ RabbitMQ Broker ] 
        │                                         │
 (Продължава веднага,                            │ (Трупа пакетите в orders_queue)
  без да чака никого)                             ▼
                                           [ orders_queue ]
                                                  │
                                          (Изтегля когатo е свободна)
                                                  ▼
                                       [ Email / Shipping Микроуслуга ]
```

## СХЕМА 3: MASTER-SLAVE РЕПЛИКАЦИЯ И ШАБЛОН ЗА ШАРДИНГ НА ДАННИ

Тази диаграма илюстрира как се цепи тежка база данни хоризонтално на базата на Modulo алгоритъм `Hash(UserId) % 2` за разпределяне на масивно писане.

```text
                         [ DbContext Write Router ]
                                     │
                      (Изчислява Sharding Key насила)
                                     ▼
                  ┌──────────────────┴──────────────────┐
                  ▼                                     ▼
        [ SQL Server Shard 0 ]                [ SQL Server Shard 1 ]
        (Пази четни UserId: 0, 2, 4)          (Пази нечетни UserId: 1, 3, 5)
         ┌────────┴────────┐                   ┌────────┴────────┐
         │  Master Server  │                   │  Master Server  │ ➔ (Само за запис / POST)
         └────────┬────────┘                   └────────┬────────┘
                  │                                     │
            (Репликация)                          (Репликация)
                  ▼                                     ▼
         ┌─────────────────┐                   ┌─────────────────┐
         │  Read-Replica   │                   │  Read-Replica   │ ➔ (Само за четене / GET)
         │  (Slave Node)   │                   │  (Slave Node)   │
         └─────────────────┘                   └─────────────────┘
```
