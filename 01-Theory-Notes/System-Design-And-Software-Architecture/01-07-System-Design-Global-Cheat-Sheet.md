## 1. ФОРМУЛИ ЗА ИЗЧИСЛЯВАНЕ НА КАПАЦИТЕТ И НАТОВАРВАНЕ

При проектиране на системи от нулата (Етап 1), използвай тези константи и математически съотношения за бързо пресмятане на хардуерния ресурс:

### 📐 А. Преобразуване към Заявки в секунда (RPS):
*   **Базова константа:** 1 денонощие = 24 часа × 60 мин × 60 сек = **86 400 секунди** (закръгля се на **100 000** за бързи изчисления наум).
*   **Формула за Среден RPS:**
    \[\text{Average RPS} = \frac{\text{Общ брой заявки за денонощие}}{86\,400}\]
*   **Формула за Пиков RPS (Peak RPS):**
    \[\text{Peak RPS} = \text{Average RPS} \times 2 \quad \text{(или } \times 3\text{)}\]

### 💾 Б. Изчисление на Дисков Обем (Storage Capacity):
*   **Формула за Дневен растеж:**
    \[\text{Storage/Day} = \text{Общ брой записи за ден} \times \text{Размер на единичен запис (KB/MB)}\]
*   **Формула за 1 година:**
    \[\text{Storage/Year} = \text{Storage/Day} \times 365\]

## 2. МАТРИЦА ЗА ИЗБОР НА БАЗА ДАННИ (SQL СРЕЩУ NOSQL)

| Критерий за Сравнение | Релационни Бази (SQL - PostgreSQL, SQL Server) | Нерелационни Бази (NoSQL - MongoDB, Cassandra) |
| :--- | :--- | :--- |
| **Структура на схемата** | Твърда, предварително дефинирана (Стриктни таблици и колони). | Гъвкава (Dynamic Schema — JSON документи, Ключ-Стойност, Графи). |
| **Сложни релации (Joins)**| **🟢 Отлична native поддръжка** през индексирани външни ключове (Foreign Keys). | ❌ Липсва. Изисква денормализация или тежко сглобяване в RAM паметта на Kestrel. |
| **Трансакционна защита**| **Желязна ACID съвместимост** (Atomicity, Consistency, Isolation, Durability). | **BASE модел** (Basically Available, Soft state, Eventual consistency). |
| **Тип Мащабиране** | Предимно Вертикално (`Scale-up`). Трудно хоризонтално шардиране. | **Хоризонтално по рождение (`Scale-out`)** чрез автоматично разпределяне на парчета. |
| **Основен бизнес избор**| Финансови системи, банкови преводи, счетоводство, ERP платформи. | Профили, чат хронологии, бързи неодитирани логове, IoT сензорни потоци. |

## 4. ТАБЛИЦА НА АРХИТЕКТУРНИТЕ СРИВОВЕ (SYSTEM EXCEPTIONS) И КОРЕКЦИЯ

| Какво изписва конзолата? (Exception) | Защо системата крашва под капака? | Точна стъпка за поправка (Решение) |
| :--- | :--- | :--- |
| `IOException: Failed to bind to address: address already in use.` | Прогресът е блокиран, тъй като портът (напр. `5001`) е зает от друго работещо приложение в Windows. | Влез в `Properties/launchSettings.json` и подмени числото на порта с напълно произволна голяма стойност. |
| `System.OutOfMemoryException was thrown.` | Извикала си `GET` списък без пагинация. Софтуерът се е опитал да изтегли милиони редове наведнъж в RAM. | Наложи задължителни `page` и `pageSize` параметри в URL заявката и филтрирай през `.Skip().Take()` на ниво SQL. |
| `HttpRequestException: Connection refused.` | Синхронна микроуслуга се опитва да извика директно съседен сървър, който в момента е изключен или паднал. | Обвийте мрежовите повиквания в защитни блокове през патeрна **Circuit Breaker** (използвайки библиотека `Polly`). |
| `Grpc.Core.RpcException: Http2ConnectionException.` | Извикала си gRPC бинарен канал по некриптиран HTTP път, което е системно забранено по подразбиране. | Премини към криптиран **HTTPS** порт, или инжектирай системния байпас флаг: `Http2UnencryptedSupport = true`. |
| `The required antiforgery cookie is not present.` | Наложила си глобален `AutoValidateAntiforgeryToken`, но външен AJAX/Postman клиент праща `POST` без токен. | Настройте Antiforgery услугата в `Program.cs` да търси криптографския ключ в HTTP Headers на пакета: `options.HeaderName = "X-XSRF-TOKEN"`. |
