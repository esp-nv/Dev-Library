## 1. ГЛОБАЛНА 4-СЛОЙНА ДИАГРАМА НА ВИСОКОНАТАВАРЕНА СИСТЕМА

Ето пълния инженерен чертеж на жизнения път на заявката при хоризонтално мащабирана MVC / Web API архитектура от нулата:

```text
       [ Множество Клиенти (Браузъри / Мобилни Апове) ]
                              │
                    (Входящ HTTP Трафик)
                              ▼
                [ Nginx Load Balancer / Proxy ]
                              │
         (Разпределя трафика по Round Robin / Least Conn)
          ┌───────────────────┼───────────────────┐
          ▼                   ▼                   ▼
   [ Kestrel App 1 ]   [ Kestrel App 2 ]   [ Kestrel App 3 ]
   (10.0.0.10:5001)    (10.0.0.11:5001)    (10.0.0.12:5001)
          │                   │                   │
          └───────────────────┼───────────────────┘
                              │
                    (Търси бърз RAM Хит)
                              ▼
                      [ Redis Cache Hub ]
                              │
            (При Cache Miss отива до твърдия диск)
                              ▼
                  [ PostgreSQL Master DB ]
```

## 2. ДИАГРАМА НА АСИНХРОНЕН EVENT-DRIVEN ПОТОК ПРЕЗ RABBITMQ

Ето как събитийният брокер (Message Broker) премахва времевата обвързаност (Temporal Coupling) между отделните независими микроуслуги:

```text
  [ Услуга за Поръчки (Publisher) ]
                 │
       (Записва в своята DB)
                 │
    (Публикува: OrderCreatedEvent)
                 ▼
     [ RabbitMQ Message Broker ] ──> (Опашка: "orders_queue")
                 │
   ┌─────────────┴─────────────┐
   (Чете асинхронно)           (Чете асинхронно)
   ▼                           ▼
[ Услуга Доставки ]       [ Услуга Фактури ]
- Сглобява пакет          - Генерира PDF
- Праща куриер            - Изпраща имейл
```

## 3. ДИАГРАМА НА MASTER-SLAVE РЕПЛИКАЦИЯ И ШАРДИНГ НА БАЗИ ДАННИ

Ето как се разделя паметта при високо съдържание на писане и четене, съчетано с хоризонтален Sharding по Modulo математически ключ:

```text
                           [ Направление на Данните ]
                                       │
                ┌──────────────────────┴──────────────────────┐
          (Само за POST/PUT/DELETE трансакции)        (Само за GET заявки)
                ▼                                             ▼
     [ SQL Master Database ]                       [ Read-Replica Slave ]
                │                                  (Копира асинхронно паметта)
        (При Шардинг)
                ▼
    Изчисляване на Hash(UserId) % 2
        ┌───────┴───────┐
        ▼               ▼
   [ Shard 0 ]     [ Shard 1 ]
   (Потребители    (Потребители
    с четен Хеш)    с нечетен Хеш)
```
