## 1. ЗЛАТНОТО ПРАВИЛО ЗА ИЗБОР (30 СЕКУНДИ)
* **Избери SQL (PostgreSQL / MS SQL):** Когато данните са **структурирани**, имат **много връзки** (`1:Many`, `Many:Many`) и изискват **100% сигурност** (банки, поръчки, потребители).
* **Избери Document NoSQL (MongoDB):** Когато всеки запис има **различни полета** (продуктов каталог с различни характеристики, логове) и ти трябва лесно мащабиране.
* **Избери Key-Value в RAM (Redis):** Когато ти трябва **светкавична скорост (< 1 ms)** за временни данни (кеш на заявки, потребителски сесии, количка).

---

## 2. МАТРИЦА НА БАЗИТЕ ДАННИ И C# БИБЛИОТЕКИТЕ

| База данни | Категория | Формат на данните | Гаранции | Основен C# пакет / ORM |
| :--- | :--- | :--- | :--- | :--- |
| **MS SQL Server** | SQL (Релационна) | Таблици, редове, колони | **ACID** | `Microsoft.EntityFrameworkCore.SqlServer` / `Dapper` |
| **PostgreSQL** | SQL (Обектно-релационна) | Таблици + `JSONB` колони | **ACID** | `Npgsql.EntityFrameworkCore.PostgreSQL` |
| **MySQL / MariaDB** | SQL (Релационна) | Таблици, редове, колони | **ACID** | `Pomelo.EntityFrameworkCore.MySql` |
| **SQLite** | SQL (Вграден файл `.db`) | Локален файл на диска | **ACID** | `Microsoft.EntityFrameworkCore.Sqlite` |
| **MongoDB** | NoSQL (Документна) | JSON / BSON документи | **BASE** *(има и транзакции)* | `MongoDB.Driver` |
| **Redis** | NoSQL (In-Memory) | Key ➔ Value в **RAM** | **BASE** (TTL изтичане) | `StackExchange.Redis` / `IDistributedCache` |

## 3. ACID СРЕЩУ BASE (НАКРАТКО)

| Критерий | SQL ➔ **ACID** (Сигурност) | NoSQL ➔ **BASE** (Скорост и мащаб) |
| :--- | :--- | :--- |
| **Приоритет** | Точност на данните (без загуба или разминаване). | Висока наличност и скорост при милиони заявки. |
| **Схема (Schema)** | **Фиксирана** (първо правиш таблица с типове). | **Гъвкава (Schema-less)** (пишеш директно JSON). |
| **Връзки (`JOIN`)** | Вградени и силно оптимизирани. | Избягват се (данните се вграждат вътре в документа). |
| **Мащабиране** | **Вертикално** (по-мощен сървър: повече RAM/CPU). | **Хоризонтално** (добавяш още сървъри в клъстер). |

## 4. ЕДНА ЗАЯВКА В 4 БАЗИ (СРАВНЕНИЕ)

**Задача:** Вземи активните потребители над 18 г., сортирани по име (първите 10).

* **MS SQL Server (T-SQL):**
  ```sql
  SELECT TOP 10 Id, Name FROM Users WHERE Age >= 18 AND IsActive = 1 ORDER BY Name ASC;
  ```
* **PostgreSQL:**
  ```sql
  SELECT id, name FROM users WHERE age >= 18 AND is_active = true ORDER BY name ASC LIMIT 10;
  ```
* **MongoDB (Shell / JSON):**
  ```javascript
  db.users.find({ age: { \$gte: 18 }, isActive: true }, { name: 1 }).sort({ name: 1 }).limit(10)
  ```
* **Redis (Key-Value — чете се директно по ключ):**
  ```bash
  GET user:101
  ```

## 5. ТОП 3 ГРЕШКИ НА ИНТЕРВЮ И В ПРАКТИКАТА
1. **Пари в `FLOAT` / `DOUBLE`:** Никога! В SQL ползвай `DECIMAL(18,2)`, в C# — `decimal`.
2. **Само Redis без основна база:** Redis е в RAM паметта — използвай го само за **кеширане (Cache)** пред SQL/MongoDB.
3. **Големи букви в PostgreSQL:** Postgres обръща имената без кавички в малки букви (`Users` ➔ `users`). Ползвай `snake_case` (`user_orders`).
