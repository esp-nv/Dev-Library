# 01-03. Сравнение на бекенд платформи: .NET срещу JVM срещу Node.js

## 1. СРАВНИТЕЛНА МАТРИЦА НА СРЕДИТЕ ЗА ИЗПЪЛНЕНИЕ (RUNTIME ENVIRONMENTS)

| Характеристика | .NET Екосистема | Java Virtual Machine (JVM) | Node.js Runtime |
| :--- | :--- | :--- | :--- |
| **Основна среда (Runtime)** | CLR (Common Language Runtime) | JVM (Java Virtual Machine) | V8 Engine + libuv |
| **Езици** | C#, F#, VB.NET | Java, Kotlin, Scala, Groovy | JavaScript, TypeScript |
| **Модел на нишките** | Multi-threaded (Истински нишки) | Multi-threaded (Истински + Виртуални нишки) | Single-threaded Event Loop (Асинхронен) |
| **Управление на паметта** | Garbage Collector (Генерационен) | Garbage Collector (G1, ZGC, Shenandoah) | V8 Garbage Collector |
| **Производителност** | Изключително висока (Ниско нативно ниво) | Висока (Enterprise мащаб) | Много висока за I/O операции |

---
## 2. УПРАВЛЕНИЕ НА НИШКИТЕ: МУЛТИНИШКОВОСТ СРЕЩУ EVENT LOOP

Начинът, по който платформите управляват процесорните нишки (Threads), определя за какви задачи са най-подходящи:

*   **.NET и JVM (Истински нишки):** Всяка заявка от потребител може да се задели на отделна системна нишка (Thread-per-Request модел). Идеални за тежки математически изчисления, обработка на големи файлове и криптиране, защото могат да натоварят всички ядра на процесора на 100%. *(Забележка: Java 21+ въведе и "Виртуални нишки" за по-лека асинхронност).*
*   **Node.js (Single-Thread Event Loop):** Изпълнява целия JavaScript код в една-единствена нишка. Когато пристигне тежка I/O заявка (например четене от база данни), Node.js я прехвърля на операционната система през библиотеката `libuv` и веднага поема следващия клиент. Когато базата отговори, събитието се връща в опашката (Event Loop). Изключително бърз за чат приложения и стандартни уеб API-та, но лесно може да бъде блокиран от една тежка математическа сметка.

---

## 3. ЧЕСТИ ГРЕШКИ, КАПАНИ И КАК ДА ГИ ИЗБЕГНЕМ

### Грешка 1: Блокиране на Event Loop-а в Node.js чрез тежка синхронна математика
* **Какво се случва:** Изпълняваш тежък цикъл за изчисляване на криптовалута или обработка на голяма снимка директно в уеб контролера на Node.js. Тъй като нишката е само една, Event Loop-ът замръзва и приложението спира да отговаря на абсолютно всички останали потребители едновременно.
* **Как да избегнеш:** За тежки CPU изчисления в Node.js изнасяй кода в `Worker Threads` или използвай .NET/Java.

### Грешка 2: Срив на паметта (Thread Starvation) при синхронно чакане в .NET / Java
* **Какво се случва:** Извикваш асинхронен метод синхронно чрез `.Result` или `.Wait()` в C#. Нишката от Thread Pool-а засяда в чакане, базата се натоварва и при внезапен трафик наличните нишки свършват, което води до забиване на уеб сървъра.
* **Как да избегнеш:** Винаги използвай `async / await` по целия път от уеб контролера до базата данни.
