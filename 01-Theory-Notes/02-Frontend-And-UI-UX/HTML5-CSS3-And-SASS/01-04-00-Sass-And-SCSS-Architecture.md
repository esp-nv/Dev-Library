## 1. КАКВО Е CSS ПРЕПРОЦЕСОР И РАЗЛИКАТА МЕЖДУ SASS И SCSS?

Чистият CSS е декларативен език и в големи проекти с хиляди редове код често води до повтаряне на цветове, шрифтове и сложни селектори. **Sass** добавя програмни възможности (променливи, влагане, миксини, функции, цикли), които се компилират в стандартен CSS преди зареждане в браузъра:

* **SCSS (`.scss` — Sassy CSS):** Модерният индустриален стандарт. Използва къдрави скоби `{}` и точка и запетая `;`, което означава, че **всеки валиден CSS файл е автоматично валиден SCSS файл**.
* **Sass (`.sass` — Indented Syntax):** По-старият синтаксис без скоби и точки и запетаи, разчитащ единствено на отстъпи (като Python). Днес се използва рядко.

## 2. АРХИТЕКТУРЕН ПОТОК: КАК КОМПИЛАТОРЪТ ПРЕВРЪЩА SCSS В СТАНДАРТЕН CSS?

Браузърите **не разбират директно `.scss` файлове**. Затова по време на разработка (Build Time) инструмент като **Dart Sass** или **Vite / Webpack** превежда кода:

```text
 ┌──────────────────────────────┐      Dart Sass Compiler      ┌──────────────────────────────┐
 │   Модулни .scss файлове      │ ───────────────────────────► │   Един минифициран .css файл │
 │  • _variables.scss           │   (Изпълнява се 1 път при    │  • style.min.css             │
 │  • _mixins.scss              │    Build; 0ms товар в        │  • Браузърът го чете директно│
 │  • main.scss                 │    браузъра на клиента!)     │    без допълнителен JS!      │
 └──────────────────────────────┘                              └──────────────────────────────┘
```

## 3. МОДУЛНА АРХИТЕКТУРА: PARTIALS (_FILE.SCSS), @USE И @FORWARD

За да не държим целия стил в един гигантски файл, разделяме кода на малки, логически файлове, наречени **Partials**:

* **Правилото за долната черта (`_`):** Файл с име `_variables.scss` или `_buttons.scss` сигнализира на компилатора да **не** генерира отделен `.css` файл за него, а да го вгради в главния `main.scss`.
* **Модерната модулна система (`@use` и `@forward`):**
  * `@use 'variables' as vars;` зарежда променливите в изолирано пространство от имена (`vars.$primary-color`), предотвратявайки сблъсъци между еднакви имена в различни файлове.
  * `@forward 'mixins';` препраща модули през централен индексен файл (`_index.scss`), изграждайки чиста 7-1 архитектура (`base/`, `components/`, `layout/`, `pages/`, `themes/`, `utils/`, `vendors/`).

## 4. СИСТЕМНИ КАПАНИ: ПРЕКАЛЕНО ДЪЛБОКО ВЛАГАНЕ (THE INCEPTION RULE) И ОСТАРЕЛИЯТ @IMPORT

### 🚨 Капан №1: Влагане на селектори на 5–6 нива дълбочина (Specificity Explosion)
* **Какво правиш:** Пишеш `.header { .nav { ul { li { a { span { color: red; } } } } } }`.
* **Защо е опасно:** Компилаторът генерира огромен, тежък селектор `.header .nav ul li a span`, който обвързва CSS-а със структурата на HTML-а, увеличава размера на крайния файл и прави презаписването на стила почти невъзможно без `!important`.
* **Железен закон (The Inception Rule):** Никога не влагай селектори на повече от **3 нива дълбочина**. Използвай родителския селектор `&` основно за псевдо-класове (`&:hover`, `&:focus`) и BEM модификатори (`&--active`).

### 🚨 Капан №2: Използване на остарялата директива `@import`
* **Защо се избягва:** Екипът на Dart Sass официално премахва `@import`, защото зарежда всички променливи глобално (замърсявайки пространството от имена) и компилира един и същ файл многократно, забавяйки Build процеса. Винаги използвай **`@use`**.
