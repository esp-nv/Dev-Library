## 1. КАКВО Е UTILITY-FIRST И ЗАЩО ЗАМЕНЯ ТРАДИЦИОННИЯ CSS?

При традиционния CSS (или методологията BEM) програмистът непрекъснато измисля изкуствени имена на класове (`.card-inner-wrapper-left-box`), прескача между HTML и CSS файлове и трупа стотици редове „мъртъв“ CSS код, който никой не смее да изтрие.

**Tailwind CSS** преобръща този модел чрез **атомарни Utility класове**, където всеки клас върши точно една конкретна CSS задача:

```text
 ┌──────────────────────────────────────────────────────────────────────────────┐
 │  ТРАДИЦИОНЕН CSS (Силна обвързаност)                                         │
 │  HTML: <button class="btn-primary">Купи</button>                             │
 │  CSS:  .btn-primary { padding: 0.5rem 1rem; background: #2563eb; ... }       │
 │  • Проблем: Промяната на един клас може да счупи 5 други страници.           │
 ├──────────────────────────────────────────────────────────────────────────────┤
 │  TAILWIND CSS (Utility-First Изолация)                                       │
 │  HTML: <button class="px-4 py-2 bg-blue-600 text-white rounded">Купи</button> │
 │  • Предимство: Стилът живее директно в компонента; нулев глобален риск.      │
 └──────────────────────────────────────────────────────────────────────────────┘
```

## 2. АРХИТЕКТУРА ПОД КАПАКА: КАК РАБОТИ JIT (JUST-IN-TIME) КОМПИЛАТОРЪТ?

В ранните версии на Tailwind браузърът зареждаше огромен CSS файл (над 3 MB) с всички възможни класове, който после се чистеше. Модерният Tailwind работи с **JIT (Just-In-Time) двигател**:

1. **Сканиране на шаблоните:** Компилаторът чете като обикновен текст всички `.html`, `.tsx`, `.vue` и `.blade.php` файлове, посочени в конфигурацията.
2. **Генериране при поискване:** Ако напишеш `bg-emerald-500` и `p-6`, JIT двигателят генерира **единствено тези две CSS правила** в крайния файл.
3. **Резултат в продукция:** Дори при огромно корпоративно приложение финалният компилиран CSS файл рядко надвишава **10–15 KB** (компресиран), което ускорява зареждането на страницата драстично.

## 3. МОДИФИКАТОРИ ЗА СЪСТОЯНИЯ И RESPONSIVE ПРЕФИКСИ (MOBILE-FIRST)

В Tailwind не пишеш `@media` заявки или `:hover` псевдо-класове в отделен файл — просто поставяш префикс с двоеточие пред всеки Utility клас:

* **Състояния (State Variants):** `hover:bg-blue-700`, `focus:ring-2`, `active:scale-95`, `disabled:opacity-50`, `dark:bg-slate-900`.
* **Адаптивност (Mobile-First Breakpoints):**
  * Без префикс (`grid-cols-1`) ➔ Важи за мобилни телефони (`0px+`).
  * `md:grid-cols-2` ➔ Активира се от `768px` нагоре.
  * `lg:grid-cols-3` ➔ Активира се от `1024px` нагоре.
* **Произволни стойности (Arbitrary Values):** Когато дизайнът изисква точен пиксел извън стандартната скала, използваш квадратни скоби: `w-[347px]`, `top-[13px]`, `bg-[#1e293b]`.

## 4. СИСТЕМНИ КАПАНИ: ДИНАМИЧНО СЛЕПВАНЕ НА КЛАСОВЕ (STRING INTERPOLATION) И SPECIFICITY

### 🚨 Капан №1: Динамично конструиране на имена на класове в JavaScript / Vue / React
* **Какво правиш:** Искаш да оцветиш бутон динамично според променлива `color = 'red'` и пишеш в шаблона:
  ```javascript
  // ❌ ГРЕШЕН ПОДХОД (JIT компилаторът няма да го засече!)
  const btnClass = `bg-${color}-600 hover:bg-${color}-700`;
  ```
* **Защо се случва:** JIT компилаторът **не изпълнява JavaScript код** — той търси цели, непрекъснати низове в изходния код чрез регулярен израз. Тъй като низът `bg-red-600` никога не се среща написан цял във файла, Tailwind изобщо не го включва в крайния CSS и бутонът остава прозрачен!
* **Как да го поправиш:** Винаги изписвай пълните имена на класовете в обект или условен израз:
  ```javascript
  // ✅ ПРАВИЛЕН ПОДХОД (Цели низове, видими за скенера)
  const colorVariants = {
      red: 'bg-red-600 hover:bg-red-700',
      blue: 'bg-blue-600 hover:bg-blue-700',
  };
  ```

### 🚨 Капан №2: Конфликт между два еднакви класа в един елемент (`p-4 p-8`)
* **Защо се случва:** В CSS не печели класът, който е написан последен в атрибута `class="p-8 p-4"`, а класът, който стои **по-надолу в генерирания CSS файл**! Затова при динамично добавяне на класове в React/Vue се използва библиотеката `tailwind-merge`, която премахва стария конфликтен клас.
