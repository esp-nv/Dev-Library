## 1. КАКВО Е RESPONSIVE WEB DESIGN И РОЛЯТА НА VIEWPORT META TAG?

**Responsive Web Design (RWD)** е подход, при който един и същ HTML и CSS код автоматично адаптира подредбата, размерите и типографията на страницата спрямо екрана на устройството (смартфон, таблет, лаптоп или 4K монитор).

За да работят Media Queries коректно на мобилни телефони, в `<head>` секцията задължително присъства следният таг:
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```
* **`width=device-width`:** Казва на мобилния браузър да приеме реалната физическа ширина на екрана (напр. `375px` за iPhone), вместо да симулира виртуален десктоп екран от `980px` и да смалява текста до нечетимост.
* **`initial-scale=1.0`:** Задава начално мащабиране 1:1 без автоматично приближаване или отдалечаване.

## 2. СТРАТЕГИИ ЗА ПРОЕКТИРАНЕ: MOBILE-FIRST СРЕЩУ DESKTOP-FIRST

```text
 ┌─────────────────────────────────────────────────────────────────────────┐
 │  MOBILE-FIRST (Индустриален стандарт -> min-width)                       │
 │  [Base CSS: Mobile < 576px] ──► [@media (min-width: 768px)] ──► [1200px] │
 │  Започваме от 1 колона за телефон и надграждаме за по-големи екрани.    │
 ├─────────────────────────────────────────────────────────────────────────┤
 │  DESKTOP-FIRST (Стар подход -> max-width)                               │
 │  [Base CSS: Desktop 1200px] ──► [@media (max-width: 992px)] ──► [576px]  │
 │  Започваме от сложен десктоп и пренаписваме/свиваме надолу.             │
 └─────────────────────────────────────────────────────────────────────────┘
```

* **Защо Mobile-First печели?** Мобилните устройства имат по-слаби процесори и батерии. При Mobile-First телефонът зарежда само лекия базов CSS за една колона, без да парсва и отменя сложни многоколонни правила за десктоп.

## 3. ОТНОСИТЕЛНИ МЕРНИ ЕДИНИЦИ (REM, EM, %, VW, VH) И FLUID ИЗОБРАЖЕНИЯ

За да бъде дизайнът еластичен, избягваме твърдите пиксели (`px`) за контейнери и типография:
* **`rem` (Root EM):** Относителна единица спрямо размера на шрифта на коренния таг `<html>` (по подразбиране `1rem = 16px`). Промяната на шрифта в `html` мащабира пропорционално целия сайт.
* **`em`:** Относителна единица спрямо шрифта на **текущия или родителския** елемент.
* **`vw` / `vh` (Viewport Width / Height):** Процент от видимата площ на прозореца на браузъра (`100vh` = 100% от височината на екрана).
* **Fluid Images (Еластични снимки):** За да не излизат изображенията извън малките екрани, налагаме глобалното правило:
  ```css
  img {
      max-width: 100%;
      height: auto;
      display: block;
  }
  ```

## 4. СИСТЕМНИ КАПАНИ: ХОРИЗОНТАЛЕН СКРОЛ (HORIZONTAL OVERFLOW) И СЧУПЕНИ ШРИФТОВЕ

### 🚨 Капан №1: Появява се досаден хоризонтален скролбар на мобилен екран
* **Какво правиш:** Задаваш на основен контейнер твърда ширина `width: 1140px;`.
* **Визуален капан:** На монитор с ширина `1920px` всичко изглежда добре, но на таблет (`768px`) или телефон (`375px`) контейнерът стърчи извън екрана и потребителят трябва да плъзга страницата наляво-надясно.
* **Как да го избегнеш:** Никога не слагай фиксиран `width` на големи контейнери. Използвай комбинацията `width: 100%; max-width: 1140px; margin: 0 auto;` — така кутията е максимум `1140px` на десктоп, но автоматично се свива до `100%` на по-малки екрани.

### 🚨 Капан №2: Грешна последователност на Media Queries (Каскадно презаписване)
* **Какво правиш:** Пишеш `@media (min-width: 992px)` **преди** `@media (min-width: 768px)` в CSS файла.
* **Защо се чупи:** На екран `1200px` и двете условия са верни (`1200 >= 992` и `1200 >= 768`). Понеже `@media (min-width: 768px)` е написана по-долу във файла, тя презаписва десктоп правилата с таблетните!
* **Правило:** При `min-width` (Mobile-First) винаги подреждай заявките **от най-малкия към най-големия брейкпойнт** (`576px` ➔ `768px` ➔ `992px` ➔ `1200px`).
