# 📘 Глава 10: Методи, Делегати, Func/Action и Ламбда изрази

**Статус:** Архитектурен справочник | **Цел:** Декомпозиция на кода, Stack Frames и подаване на поведение като параметър

---

## ⚡ 1. КАКЪВ ПРОБЛЕМ РЕШАВАТ МЕТОДИТЕ, ДЕЛЕГАТИТЕ И ЛАМБДА ИЗРАЗИТЕ?
Писането на целия код в `Main()` води до повторение, трудно дебъгване и невъзможност за преизползване. **Методите** разделят програмата на малки, изолирани блокове с една отговорност. **Делегатите и Ламбда изразите** правят следващата голяма крачка – позволяват ти да третираш **самата логика (функцията) като променлива**, която можеш да подаваш на други методи (както прави LINQ с `.Where(x => x > 5)`).

## 🧠 2. АНАТОМИЯ НА МЕТОДИТЕ И ПРЕДАВАНЕТО НА ПАМЕТ

Когато извикаш метод, .NET заделя нов **Stack Frame** (кутия в Stack паметта) за неговите локални променливи и го унищожава веднага след `return`.

### 🔀 Как се предават аргументи в C#?

| Ключова дума | Какво се подава? | Изисква ли начална стойност преди метода? | Какво се случва под капака? |
| :--- | :--- | :--- | :--- |
| *(няма)* | Копие на стойността / референцията | **Да** | За Value типове (`int`) промяната вътре **НЕ** засяга оригинала. |
| **`ref`** | Директен адрес към оригиналната променлива | **Да** | Методът чете и променя **директно** оригиналната променлива отвън. |
| **`out`** | Директен адрес за връщане на резултат | **Не** | Методът е **задължен** да присвои стойност преди да завърши (напр. `TryParse`). |
| **`in`** | Директен адрес **само за четене** | **Да** | Спестява копиране на големи `struct` обекти, без да позволява промяна. |
| **`params`** | Променлив брой аргументи като масив | **Не** | Позволява извикване като `Sum(1, 2, 3)` вместо `Sum(new int {1, 2, 3})`. |

### 🔍 Overloading (Претоварване на методи)
* Два метода в един клас могат да носят **едно и също име**, ако се различават по **сигнатура** (брой, тип или подредба на параметрите).
* ⚠️ **Важно:** Само различният `return` тип (напр. `int Calc()` и `double Calc()`) **НЕ** е валиден Overloading и дава компилационна грешка!

## 📊 3. МАТРИЦА НА ВГРАДЕНИТЕ ДЕЛЕГАТИ (Func, Action, Predicate)

В модерния C# рядко пишем ръчно `delegate`, а използваме готовите generic делегати на .NET:

| Делегат | Връща ли резултат? | Сигнатура и пример | Къде се използва най-често? |
| :--- | :--- | :--- | :--- |
| **`Action<T>`** | **НЕ** (`void`) | `Action<string> print = msg => Console.WriteLine(msg);` | За изпълнение на действия (печатане, запис в лог, нотификации). |
| **`Func<T, TResult>`** | **ДА** (последният тип) | `Func<int, int, int> add = (a, b) => a + b;` | В **LINQ** (`.Select()`, `.OrderBy()`), калкулации и трансформации. |
| **`Predicate<T>`** | **ДА** (винаги `bool`) | `Predicate<int> isEven = n => n % 2 == 0;` | В `List<T>.Find()`, `List<T>.RemoveAll()` за филтриране. |

## 🛠️ 4. ЛАМБДА ИЗРАЗИ (Lambda Expressions) НАВИГАТОР

Ламбда изразът е анонимна функция без име, написана с оператора **`=>`** (*"отива в"* / *"goes to"*).

1. **Без параметри:**
   * 🎯 `Action greet = () => Console.WriteLine("Здравей!");`
2. **Един параметър (скобите не са задължителни):**
   * 🎯 `Func<int, int> square = x => x * x;`
3. **Няколко параметъра (скобите са задължителни):**
   * 🎯 `Func<int, int, bool> isGreater = (a, b) => a > b;`
4. **Многоредова ламбда (Statement Lambda – изисква `{}` и `return`):**
   * 🎯 `Func<double, string> evaluate = grade => { if (grade >= 5.50) return "Отличен"; return "Добър"; };`

## 🚨 5. КРИТИЧНИ JUNIOR КАПАНИ ПРИ МЕТОДИ И ЛАМБДА

### 🛑 Капан 1: Closure (Затваряне) върху променлива в цикъл
* **Проблем:** Създаваш списък от `Action` делегати вътре във `for` цикъл, които печатат `i`, и накрая всички печатат последната стойност на `i` (напр. `5`), вместо `0, 1, 2, 3, 4`.
* **Причина:** Ламбда изразът улавя **самата променлива (референцията)** `i` в Heap-а, а не стойността ѝ в момента на завъртането.
* **Решение:** Копирай брояча в локална променлива вътре в цикъла: `int copy = i; actions.Add(() => Console.WriteLine(copy));`.

### 🛑 Капан 2: Странични ефекти (Side Effects) при Reference типове
* **Проблем:** Подаваш `List<int>` на метод без `ref`, правиш `list.Clear()` вътре и оригиналният списък изчезва.
* **Причина:** Въпреки че параметърът е подаден по стойност, за Reference типове се копира **адресът към същия обект в Heap-а**.
* **Решение:** Ако методът не трябва да променя оригинала, подай копие (`new List<int>(list)`) или приеми параметъра като `IReadOnlyList<int>`.
