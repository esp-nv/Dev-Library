# 🎯 Изпитен Чеклист: Какво и как се проверява в Unit Testing (NUnit + Moq)

**Статус:** Изпитен наръчник за 100% Code Coverage | **Цел:** Систематично покритие на всеки ред от бизнес логиката

---

## 🔍 1. КАКВО И КАК СЕ ПРОВЕРЯВА (ТАБЛИЦА НА ПРОВЕРКИТЕ)

На изпита всяко изискване в кода се превежда в конкретен тип проверка (Assertion):

| Какво проверяваме? | Какъв е сценарият? | Как го проверяваме в NUnit / Moq? |
| :--- | :--- | :--- |
| **Конструктор и начално състояние** | Инициализират ли се правилно полетата и колекциите (`Count == 0`)? | `Assert.IsNotNull(obj);` <br> `Assert.AreEqual(0, obj.Items.Count);` |
| **Връщана стойност (Return)** | Методът връща ли точния резултат или обект? | `Assert.AreEqual(expected, actual);` <br> `Assert.AreSame(expectedObj, actualObj);` |
| **Промяна на състояние (State)** | Промени ли се свойство (напр. `IsGraduated = true`, `Count` нарасна с 1)? | `Assert.IsTrue(student.IsGraduated);` <br> `Assert.AreEqual(1, repo.Count);` |
| **Хвърляне на грешка (Exception)** | Гърми ли методът при невалидни данни (`null`, празен стринг, `< 0`)? | `Assert.Throws<ArgumentException>(() => service.Add(null));` |
| **Текст на грешката (Message)** | Изисква ли условието конкретно съобщение при грешка? | `var ex = Assert.Throws<InvalidOperationException>(...);` <br> `Assert.AreEqual("Очакван текст", ex.Message);` |
| **Взаимодействие с Mock (Behavior)** | Извика ли Service-ът базата данни (`Save` / `Delete`) точния брой пъти? | `mockRepo.Verify(r => r.Save(It.IsAny<Student>()), Times.Once);` |

## 🛡️ 2. ЗАДЪЛЖИТЕЛЕН ЧЕКЛИСТ ЗА ПОКРИТИЕ НА ВСЕКИ КЛАС (ZOMBIES ПРАВИЛО)

За да не пропуснеш нито един скрит тест в Judge системата, минавай през всеки метод по този ред:

1. **Z – Zero (Нулеви / Празни състояния):**
   * Какво става, когато колекцията е празна (`Count == 0`)?
   * Какво става, ако подадем `0`, празен стринг `""` или `null`?
2. **O – One (Единичен елемент / Базов Happy Path):**
   * Добавяне на 1 валиден елемент, намиране на 1 елемент, изтриване на 1 елемент.
3. **M – Many (Много елементи / Колекции):**
   * Добавяне на няколко елемента, търсене сред много, проверка на обща сума или средна стойност.
4. **B – Boundary (Гранични стойности):**
   * Ако условието казва *"оценка между 2.00 и 6.00"*, тествай точно **2.00** (валидно), **6.00** (валидно), **1.99** (грешка) и **6.01** (грешка).
   * Ако има капацитет (напр. `Capacity = 5`), тествай добавянето на **5-тия** (успех) и **6-тия** елемент (грешка).
5. **I – Interface & Encapsulation (Инкапсулация):**
   * Опит за директна модификация на външна колекция (ако връща `IReadOnlyCollection<T>`).
6. **E – Exceptions (Всички `if` проверки за грешки):**
   * Отвори кода на метода, който тестваш. **Всеки един `throw new ...` в кода изисква отделен `[Test]`!**

## 🧩 3. ШАБЛОН ЗА ПЕРФЕКТЕН ТЕСТ (AAA ПАТЕРН)

Всеки тест трябва да бъде разделен визуално и логически на три части:

```csharp
[Test]
public void MethodName_ShouldExpectedBehavior_WhenCondition()
{
    // 1. ARRANGE (Подготовка: създаваме обекти, данни и настройваме Mock-овете)
    var student = new Student { Id = 1, AverageGrade = 5.80 };
    _mockRepo.Setup(r => r.GetById(1)).Returns(student);

    // 2. ACT (Действие: извикваме САМО ЕДИН метод, който тестваме в момента)
    _service.GraduateStudent(1);

    // 3. ASSERT (Проверка: доказваме резултата с Assert или Mock.Verify)
    Assert.IsTrue(student.IsGraduated);
    _mockRepo.Verify(r => r.Save(student), Times.Once);
}
```

## 🚫 4. КАКВО НЕ СЕ ТЕСТВА В UNIT ТЕСТОВЕТЕ

* **Не тествай вградени функции на C#:** Не проверявай дали `List<T>.Add()` или `string.IsNullOrEmpty()` работят.
* **Не тествай `private` методи директно:** Те се тестват индиректно през `public` методите, които ги извикват.
* **Не тествай реална база данни или файлова система:** За това използваме Mock проксита.
