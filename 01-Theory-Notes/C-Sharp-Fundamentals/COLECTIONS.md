// Когато създадеш нов List<T>, C# заделя скрит, фиксиран МАСИВ (Array) 
// в Heap паметта с начален капацитет (по подразбиране обикновено е 4 или 0).
//
// Какво се случва, когато напълниш капацитета (Count == Capacity)?
// При следващия .Add():
//   1. C# заделя в Heap-а ЧИСТО НОВ масив с ДВОЕН РАЗМЕР (Capacity * 2).
//   2. Копира всички стари елементи в новия масив (Операция O(n) - бавна!).
//   3. Изтрива стария масив (праща го на Garbage Collector-а).

// 2. СВЕТКАВИЧНОТО ТЪРСЕНЕ НА DICTIONARY И HASHSET
// ------------------------------------------------------------
// Защо Dictionary и HashSet търсят за константно време O(1), независимо дали има 10 или 10 000 000 елемента?
//
// Когато добавиш КЛЮЧ (Key):
//   1. C# извиква метода .GetHashCode() на обекта-ключ и получава число (Хеш код).
//   2. Превръща това число в индекс на вътрешен масив (наречен Buckets / Кофи).
//   3. Поставя стойността директно в тази "кофа".
//
// Когато търсиш по Ключ:
//   C# не върти foreach цикъл! Той просто пресмята хеш кода на търсения ключ и отива 
//   директно на точния адрес в паметта.
//
// ⚠️ АХИЛЕСОВАТА ПЕТА (Хеш колизия):
// Ако два напълно различни ключа върнат еднакъв HashCode, те попадат в една и съща кофа. 
// Тогава търсенето се забавя и става линейно O(n). Затова ключовете в Dictionary трябва да са уникални и непроменяеми (Immutable).
