# 📘 Глава 12: Регулярни изрази (Regular Expressions / Regex)

**Статус:** Архитектурен справочник | **Цел:** Търсене, валидиране и извличане на текстови шаблони

---

## ⚡ 1. КАКЪВ ПРОБЛЕМ РЕШАВАТ РЕГУЛЯРНИТЕ ИЗРАЗИ?
Когато трябва да валидираш имейл, телефонен номер или да извлечеш специфични данни (напр. цена и продукт) от разбъркан текст, писането на десетки `if`, `IndexOf` и `Substring` проверки става тромаво и пълно с бъгове. **Regex** описва сложни текстови правила чрез кратък, декларативен шаблон (Pattern), а .NET Regex двигателят го компилира в машина на състоянията, която намира съвпаденията мигновено.

## 📊 2. МАТРИЦА НА КЛЮЧОВИТЕ СИМВОЛИ И КВАНТИФИКАТОРИ

### 🔹 Символни класове (Какво търсим?)

| Символ | Какво съвпада? | Обратен (Отрицание) | Пример |
| :--- | :--- | :--- | :--- |
| **`.`** | Всеки един символ (без нов ред `\n`) | — | `a.c` ➔ `"abc"`, `"a1c"` |
| **`\d`** | Всяка цифра (`0-9`) | **`\D`** (всичко без цифри) | `\d\d` ➔ `"42"` |
| **`\w`** | Буква, цифра или долна черта (`a-z, A-Z, 0-9, _`) | **`\W`** (специални символи, интервали) | `\w+` ➔ `"User_1"` |
| **`\s`** | Празно пространство (интервал, табулация, нов ред) | **`\S`** (всичко без интервали) | `\s+` ➔ `"   "` |
| **`[abc]`** | Един от изброените символи (`a`, `b` или `c`) | **`[^abc]`** (нито един от тях) | `[A-Z]` ➔ главна буква |

### 🔹 Квантификатори (Колко пъти се повтаря?)

| Квантификатор | Значение | Пример |
| :--- | :--- | :--- |
| **`*`** | **0 или повече** пъти (Greedy) | `ab*` ➔ `"a"`, `"ab"`, `"abbb"` |
| **`+`** | **1 или повече** пъти (Greedy) | `\d+` ➔ `"5"`, `"1234"` |
| **`?`** | **0 или 1** път (Незадължителен елемент) | `colou?r` ➔ `"color"`, `"colour"` |
| **`{n}`** | **Точно `n`** пъти | `\d{4}` ➔ `"2026"` |
| **`{n,m}`** | **Между `n` и `m`** пъти | `\w{3,8}` ➔ дума от 3 до 8 символа |

### 🔹 Котви (Anchors – Къде в текста се намира?)
* **`^`** — Начало на текста / реда (`^\d+` ➔ започва с цифра).
* **`$`** — Край на текста / реда (`\.bg$` ➔ завършва на `.bg`).
* **`\b`** — Граница на дума (`\bcat\b` ➔ намира `"cat"`, но **НЕ** и `"scatter"`).

## 🧠 3. АНАТОМИЯ НА ГРУПИТЕ (CAPTURING & NAMED GROUPS)

Групите ти позволяват да извадиш конкретни парчета от намерения текст (напр. да отделиш името от цената).

* **Номерирана група `(...)`:** Достъпва се по индекс `match.Groups[1].Value` *(индекс `0` винаги е цялото съвпадение!)*.
* **Именувана група `(?<name>...)`:** Достъпва се директно по име `match.Groups["name"].Value` (най-чистият подход за изпита).
* **Незаписваща група `(?:...)`:** Групира логика (напр. `(?:Mr|Mrs)\.`), без да пази резултата в `Groups` (пести памет).

```csharp
string input = "Product: Laptop | Price: 1599.99";
string pattern = @"Product:\s+(?<item>[A-Za-z]+)\s+\|\s+Price:\s+(?<price>\d+\.\d{2})";

Match match = Regex.Match(input, pattern);
if (match.Success)
{
    string item = match.Groups["item"].Value;   // "Laptop"
    double price = double.Parse(match.Groups["price"].Value); // 1599.99
}
```

## 🛠️ 4. НАВИГАТОР НА КЛЮЧОВИТЕ МЕТОДИ В C# (`System.Text.RegularExpressions`)

1. **Проверка дали текстът отговаря на шаблон (Валидация):**
   * 🎯 `bool isValid = Regex.IsMatch(input, pattern);`
2. **Намиране на ПЪРВОТО съвпадение в текста:**
   * 🎯 `Match match = Regex.Match(input, pattern);`
3. **Намиране на ВСИЧКИ съвпадения в текста:**
   * 🎯 `MatchCollection matches = Regex.Matches(input, pattern);`
4. **Замяна на всички съвпадения с нов текст:**
   * 🎯 `string cleaned = Regex.Replace(input, @"\s+", " ");` *(свива множество интервали в един)*.
5. **Разделяне на текст по сложен разделител:**
   * 🎯 `string parts = Regex.Split(input, @"[,;|\s]+");`

## 🚨 5. КРИТИЧНИ JUNIOR КАПАНИ ПРИ REGEX

### 🛑 Капан 1: Забравен Verbatim String (`@`) пред шаблона
* **Проблем:** Пишеш `string pattern = "\d+";` без `@` и компилаторът хвърля грешка *Unrecognized escape sequence*.
* **Причина:** В C# символът `\` е escape символ за самия стринг (като `\n` или `\t`).
* **Решение:** Винаги слагай `@` пред шаблона: `string pattern = @"\d+";`.

### 🛑 Капан 2: Greedy (Алчно) срещу Lazy (Мързеливо) търсене
* **Проблем:** При текст `"<b>One</b> and <b>Two</b>"`, шаблонът `<b>.*</b>` хваща **целия ред** вместо само първия таг!
* **Причина:** Квантификаторите `*` и `+` са **Greedy** по подразбиране — те гълтат максимално много символи до *последното* възможно `</b>`.
* **Решение:** Добави **`?`** след квантификатора (`<b>.*?</b>`), за да стане **Lazy** и да спре на *първото* срещнато `</b>`.

### 🛑 Капан 3: Липса на котви `^` и `$` при валидация
* **Проблем:** Проверяваш дали паролата е само цифри с `Regex.IsMatch("1234abc", @"\d+")` и получаваш `true`!
* **Причина:** Без `^` и `$`, Regex връща `true`, стига *някъде* в текста да има поне една цифра.
* **Решение:** При валидация на цял вход винаги ограждай шаблона: `^\d+$`.
