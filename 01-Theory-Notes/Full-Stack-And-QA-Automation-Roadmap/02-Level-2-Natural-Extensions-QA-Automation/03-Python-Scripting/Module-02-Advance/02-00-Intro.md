## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Концепция | Python 3.x | C# (.NET) | JavaScript (ES6+) |
| :--- | :--- | :--- | :--- |
| **Стек (LIFO)** | `list` (`.append()` / `.pop()`) | `Stack<T>` (`.Push()` / `.Pop()`) | `Array` (`.push()` / `.pop()`) |
| **Опашка (FIFO)** | `collections.deque` (`.popleft()`) | `Queue<T>` (`.Dequeue()`) | `Array` (`.shift()` — бавно O(n)) |
| **Множество (Unique)** | `set` (`{1, 2, 3}`) | `HashSet<T>` | `new Set([1, 2, 3])` |
| **Улавяне на грешки** | `try ... except Exception:` | `try ... catch (Exception)` | `try ... catch (err)` |
| **Автоматично затваряне** | `with open(...) as f:` | `using var stream = ...` | `try ... finally` |

## 4. ПЛЮСОВЕ И МИНУСИ НА НАПРЕДНАЛИТЕ ИНСТРУМЕНТИ

### 🟢 Предимства (Pros):
*   **Модулът `collections`:** Предоставя C-оптимизирани структури като `deque` и `Counter`, които работят със скорост O(1) и спестяват стотици редове алгоритмичен код.
*   **Елегантно управление на ресурси:** Контекст мениджърите (`with`) напълно елиминират течовете на памет (Memory Leaks) при работа с файлове и мрежови сокети.

### 🔴 Недостатъци (Cons):
*   **Липса на вградени двумерни масиви:** Python няма нативен `int[,]` като C#. Матриците се правят като „списък от списъци“, което изисква внимание при копиране и инициализация.
*   **Няма опашка за големи масиви в базовия `list`:** Използването на `list.pop(0)` като опашка е сериозна производителна грешка при големи обеми данни.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Голо `except:` и незатворен файл):
```python
# 🚨 ГРЕШКА 1: Отваряне на файл без 'with' (ако гръмне грешка преди .close(), файлът остава заключен!)
file = open("data.txt", "w")
file.write("Важни данни")
# Липсва file.close() при срив!

# 🚨 ГРЕШКА 2: Улавяне на абсолютно всички грешки на сляпо (Pokemon Exception Handling)
try:
    result = 10 / 0
except:  # Лоша практика! Хваща дори Ctrl+C (KeyboardInterrupt) и крие истинския бъг!
    print("Нещо се счупи.")
```
*   **Как да се избегне:** Винаги отваряй файлове чрез `with open(...) as file:` и винаги посочвай конкретния тип грешка след `except` (напр. `except ZeroDivisionError:`).

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic стандарт):
```python
from collections import deque

# 1. Използване на специализирана опашка (O(1) скорост)
task_queue = deque(["Задача 1", "Задача 2", "Задача 3"])
current_task = task_queue.popleft()  # Вади първия елемент мигновено
print(f"Обработва се: {current_task}")

# 2. Защитена работа с файл и конкретно прихващане на грешка
try:
    with open("system_log.txt", "w", encoding="utf-8") as log_file:
        log_file.write(f"Завършена: {current_task}\n")
    print("Логът е записан и файлът е затворен безопасно.")
except IOError as err:
    print(f"Грешка при запис на диска: {err}")
```
*   **Изход в конзолата:**
    ```text
    Обработва се: Задача 1
    Логът е записан и файлът е затворен безопасно.
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Защо използването на стандартен Python `list` за опашка чрез `my_list.pop(0)` е сериозна грешка при големи масиви от данни и как се решава?“*
*   **Уловката:** На малки тестове с 10 елемента `pop(0)` работи мигновено и заблуждава разработчика.
*   **Точен Senior отговор:** Стандартният `list` в Python е имплементиран като динамичен масив от указатели в паметта. Когато премахнеш първия елемент с `pop(0)`, Python е принуден да премести **всички останали `n - 1` елемента с една позиция наляво**, което има алгоритмична сложност **O(n)**. При 1 милион елемента това блокира процесора. Решението е класът **`collections.deque`** (Double-Ended Queue), който под капака е **двойносвързан списък от блокове** и премахва от двата края (`popleft()` и `pop()`) за константно време **O(1)**.
