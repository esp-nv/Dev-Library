## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Трите нива на долните черти (`_`):**
    *   **Без долна черта (`self.name`):** Публично (Public) — отворена врата за всички.
    *   **Една долна черта (`self._name`):** Защитено (Protected) — джентълменско споразумение: *„Вътрешно поле е, не го пипай отвън, освен ако не наследяваш класа“* (Python не го блокира технически).
    *   **Две долни черти (`self.__name`):** Частно (Private) — Python включва защита, като тайно преименува променливата в паметта, за да не може да бъде прочетена директно като `obj.__name`.
*   **Декораторът `@property`:** Превръща метод на класа в свойство, което се чете и записва като обикновена променлива (`user.age = 25`), но под капака минава през строга валидация (като `get` и `set` аксесорите в C#).

## 2. ЕТАПИ НА NAME MANGLING В RAM ПАМЕТТА И БЛОК-СХЕМА

Когато напишеш атрибут с две водещи долни черти (`__balance`), Python прилага алгоритъма **Name Mangling** (преименуване на името), за да предпази полето от случайни сблъсъци при наследяване.

```text
Клас: BankAccount   |   Атрибут в кода: self.__balance = 500

┌──────────────────────────┐     1. Компилация       ┌─────────────────────────┐
│ self.__balance = 500     │ ──────────────────────► │ Name Mangling Двигател  │
│                          │   (Засича 2 долни черти)│ Добавя '_ИмеНаКласа'    │
└──────────────────────────┘                         └────────────┬────────────┘
                                                                  │ 2. Запис в __dict__
                                                                  ▼
┌──────────────────────────┐     3. Опит за прочит:   ┌─────────────────────────┐
│ acc.__balance ➔ ГРЕШКА!  │ ◄─────────────────────── │ Реално име в паметта:   │
│ (AttributeError)         │   acc._BankAccount__balance│ '_BankAccount__balance' │
└──────────────────────────┘                         └─────────────────────────┘
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Концепция | Python 3.x | C# (.NET) | JavaScript (ES2022+) |
| :--- | :--- | :--- | :--- |
| **Публично поле** | `self.age` | `public int Age { get; set; }` | `this.age` |
| **Защитено поле (Protected)** | `self._age` (само конвенция!) | `protected int _age;` (строго) | Няма нативно (`_age` конвенция) |
| **Частно поле (Private)** | `self.__age` (Name Mangling) | `private int _age;` (строго) | `#age` (истинско твърдо Private) |
| **Getter / Setter** | `@property` и `@age.setter` | `get { ... } set { ... }` | `get age() { }` / `set age(v) { }` |
| **Read-Only свойство** | Само `@property` без `.setter` | `public int Age { get; }` | Само `get age() { }` |

## 4. ПЛЮСОВЕ И МИНУСИ НА КАПСУЛАЦИЯТА В PYTHON

### 🟢 Предимства (Pros):
*   **Елегантни `@property` валидации:** Можеш да започнеш с обикновено публично поле (`self.price`), а по-късно да го превърнеш в `@property` с валидация, без да счупиш нито един ред код в останалата част от проекта, който ползва `obj.price`.
*   **Защита при множествено наследяване:** Name Mangling гарантира, че ако два родителски класа имат вътрешни променливи с еднакво име `__id`, те няма да се презапишат една друга в детето.

### 🔴 Недостатъци (Cons):
*   **Няма истинска криптографска или компилационна защита:** Всеки може да прочете `obj._ClassName__private_field`, ако знае името на класа.
*   **Бавни извиквания при прекомерно `@property`:** Тъй като `@property` под капака е извикване на функция, достъпът до него е по-бавен от директното четене на атрибут в цикли с милиони итерации.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Безкрайна рекурсия в `@property` Setter!):
```python
class UserAccount:
    def __init__(self, age: int):
        self.age = age  # Извиква сетъра по-долу!

    @property
    def age(self) -> int:
        # 🚨 ГРЕШКА 1: Чете self.age вместо вътрешното self._age -> Безкрайна рекурсия!
        return self.age

    @age.setter
    def age(self, value: int):
        if value < 0:
            raise ValueError("Възрастта не може да е отрицателна!")
        # 🚨 ГРЕШКА 2: Пише в self.age, което отново вика същия сетър -> RecursionError!
        self.age = value
```
*   **Как да се избегне:** Вътре в `@property` и `@x.setter` **винаги** чети и пиши в скрито поле с долна черта отпред (`self._age` или `self.__age`), никога в самото име на пропъртито!

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic стандарт с `@property` и валидация):
```python
class Product:
    def __init__(self, name: str, price: float):
        self.name = name
        self.price = price  # Минава през сетъра още при създаването!

    @property
    def price(self) -> float:
        return self.__price

    @price.setter
    def price(self, value: float) -> None:
        if value <= 0:
            raise ValueError("Цената трябва да бъде по-голяма от 0 лв.!")
        self.__price = round(value, 2)

    # Read-Only свойство (няма сетър -> не може да се променя директно)
    @property
    def price_with_vat(self) -> float:
        return round(self.__price * 1.20, 2)

laptop = Product("ThinkPad X1", 2500.0)
print(f"Продукт: {laptop.name} | Без ДДС: {laptop.price} лв. | С ДДС: {laptop.price_with_vat} лв.")

laptop.price = 2300.0  # Валидира се автоматично през сетъра
print(f"Нова цена с ДДС: {laptop.price_with_vat} лв.")
```
*   **Изход в конзолата:**
    ```text
    Продукт: ThinkPad X1 | Без ДДС: 2500.0 лв. | С ДДС: 3000.0 лв.
    Нова цена с ДДС: 2760.0 лв.
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Какво се случва, ако в `__init__` присвоим стойност на `self.age = -5`, когато имаме дефиниран `@age.setter` с валидация?“*
*   **Уловката:** Някои кандидати мислят, че `__init__` заобикаля сетъра и записва `-5` директно.
*   **Точен Senior отговор:** Ако в `__init__` напишеш `self.age = age` (без долна черта), Python **автоматично задейства `@age.setter`** още при инициализацията на обекта и веднага ще хвърли `ValueError` при невалидни данни. Ако обаче в `__init__` напишеш `self._age = age` (с долна черта), ти директно записваш в скритото поле и **прескачаш валидацията** в сетъра при създаване! Затова добрата практика е в `__init__` да се пише `self.age = age`, за да се валидират данните още при раждането на обекта.
