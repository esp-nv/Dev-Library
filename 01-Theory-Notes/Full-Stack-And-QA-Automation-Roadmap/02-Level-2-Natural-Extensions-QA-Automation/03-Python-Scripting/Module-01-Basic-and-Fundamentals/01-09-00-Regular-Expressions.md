## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Законът за суровия текст `r"..."`:** Винаги слагай буквата **`r`** (Raw string) пред кавичките на шаблона! В Python наклонената черта `\` се използва за специални символи (като `\n` за нов ред). Ако напишеш обикновен стринг `"\d+"`, Python ще се опита да го преведе преди Regex двигателя да го види. С `r"\d+"` казваш: *„Не пипай наклонените черти, предай текста суров директно на Regex двигателя“*.
*   **Главни срещу малки букви:** Малката буква търси символа (`\d` = цифра, `\w` = буква/цифра, `\s` = интервал), а **ГЛАВНАТА буква търси точно обратното** (`\D` = всичко без цифри, `\W` = специални символи, `\S` = всичко без интервали).

## 2. ЕТАПИ НА ОБРАБОТКА НА REGEX И БЛОК-СХЕМА

Модулът `re` в Python използва двигател с връщане назад (**Backtracking NFA Engine**). Когато извикаш търсене, шаблонът се компилира в машина на състоянията.

```text
Входен текст: "Цена: 150 лв."   |   Шаблон: r"\d+"

┌──────────────────────────┐     1. Компилация       ┌─────────────────────────┐
│ Шаблон r"\d+"            │ ──────────────────────► │ Вътрешен Bytecode обект │
│                          │   (Кешира се в RAM)     │ (State Machine)         │
└──────────────────────────┘                         └────────────┬────────────┘
                                                                  │ 2. Сканиране на текста
                                                                  ▼
┌──────────────────────────┐     3. Извличане        ┌─────────────────────────┐
│ Match Обект:             │ ◄────────────────────── │ Намира цифрите '150'    │
│ .group() -> "150"        │   (Връща Match или None)│ на позиции (6, 9)       │
└──────────────────────────┘                         └─────────────────────────┘
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Операция | Python `re` | C# `System.Text.RegularExpressions` | JavaScript `RegExp` |
| :--- | :--- | :--- | :--- |
| **Импортиране / Дефиниция** | `import re` + `r"\d+"` | `new Regex(@"\d+")` | `/\d+/g` (литерал) |
| **Първо съвпадение** | `re.search(pattern, text)` | `Regex.Match(text, pattern)` | `text.match(/\d+/)` |
| **Всички съвпадения** | `re.findall(pattern, text)` | `Regex.Matches(text, pattern)` | `text.matchAll(/\d+/g)` |
| **Замяна на текст** | `re.sub(pat, repl, text)` | `Regex.Replace(text, pat, repl)` | `text.replaceAll(/\d+/g, repl)` |
| **Именувана група** | `(?P<year>\d{4})` | `(?<year>\d{4})` | `(?<year>\d{4})` |

## 4. ПЛЮСОВЕ И МИНУСИ НА РЕГУЛЯРНИТЕ ИЗРАЗИ

### 🟢 Предимства (Pros):
*   **Светкавична валидация и парсване:** С един ред шаблон заменяш десетки редове вложени `if` проверки, `.split()` и `.isdigit()` цикли.
*   **Стандартизиран език:** Почти същите правила работят в Python, C#, JavaScript, SQL и Linux конзоли.

### 🔴 Недостатъци (Cons):
*   **Трудна поддръжка ("Write-only code"):** Сложните регулярни изрази за имейли или URL адреси се четат изключително трудно след няколко месеца.
*   **Риск от ReDoS (Catastrophic Backtracking):** Лошо написан шаблон с вложени квантификатори (като `(a+)+`) може да накара процесора да увисне на 100% за минути при подаване на специално подбран текст.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД (И КОМЕНТАРИ)

### ❌ ГРЕШЕН КОД (Липсващ `r""` префикс и срив при `None`):
```python
import re

text = "Код за достъп: 9482"

# 🚨 ГРЕШКА 1: Липсва 'r' пред кавичките! При по-сложни символи като \b (граница на дума)
# Python го чете като Backspace символ вместо Regex команда!
# 🚨 ГРЕШКА 2: Директно викане на .group() без проверка дали изобщо има съвпадение!
match = re.search("\d{6}", text) # Търси 6 цифри, но в текста има само 4 -> връща None!
# print(match.group()) -> Гърми с AttributeError: 'NoneType' object has no attribute 'group'!
```
*   **Как да се избегне:** Винаги слагай `r` пред шаблона (`r"\d{6}"`) и **винаги** проверявай `if match:` преди да извикаш `.group()`.

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic стандарт с именувани групи и защита):
```python
import re

log_line = "[2026-11-11] ERROR: User 'esp_nv' failed login from IP 192.168.1.55"

# Използваме r"""...""" с именувани групи (?P<име>...) за кристална четимост
pattern = r"\[(?P<date>\d{4}-\d{2}-\d{2})\] (?P<level>[A-Z]+): User '(?P<user>\w+)'"

match = re.search(pattern, log_line)

# Задължителна проверка преди достъп до групите
if match:
    print(f"Дата:  {match.group('date')}")
    print(f"Ниво:  {match.group('level')}")
    print(f"Потребител: {match.group('user')}")
else:
    print("Няма съвпадение в лог реда.")
```
*   **Изход в конзолата:**
    ```text
    Дата:  2026-11-11
    Ниво:  ERROR
    Потребител: esp_nv
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Каква е разликата между Алчни (Greedy) и Мързеливи (Lazy) квантификатори в Regex и защо шаблонът `r'<.*>'` чупи парсването на HTML тагове?“*
*   **Уловката:** Ако подадеш текста `"<div>Здравей</div>"`, програмистите очакват `r"<.*>"` да хване само първия таг `"<div>"`.
*   **Точен Senior отговор:** По подразбиране квантификаторите `*` и `+` са **Алчни (Greedy)** — те се опитват да погълнат възможно най-дългия парче текст! Затова `r"<.*>"` започва от първото `<` и стига чак до последното `>`, поглъщайки целия ред `"<div>Здравей</div>"` наведнъж.
    *   **Правилен фикс:** Добавя се въпросителен знак `?` веднага след квантификатора (`r"<.*?>"`). Това го превръща в **Мързелив (Lazy)**, принуждавайки го да спре веднага при първото срещнато затварящо `>`, връщайки точно `['<div>', '</div>']`.
