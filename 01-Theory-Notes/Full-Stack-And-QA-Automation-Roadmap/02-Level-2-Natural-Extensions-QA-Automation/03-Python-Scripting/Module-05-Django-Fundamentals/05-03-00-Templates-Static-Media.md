## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Трите символа на DTL (Django Template Language):**
    *   **`{{ променлива }}` (Двойни фигурни скоби):** Принтира стойност на екрана (като `print()`).
    *   **`{% команда %}` (Фигурни скоби + Процент):** Изпълнява логика — `if`, `for`, `extends`, `block`, `url`, `static`.
    *   **`{# коментар #}` (Фигурни скоби + Диез):** Сървърен коментар — изтрива се напълно на сървъра и никога не стига до HTML кода в браузъра (за разлика от `<!-- HTML коментар -->`).
*   **`STATIC` срещу `MEDIA` файлове:**
    *   **`STATIC` (Статични файлове):** Това са файловете на **програмиста** — твоите CSS стилове, JavaScript скриптове и логото на сайта. Те се качват с кода в Git.
    *   **`MEDIA` (Медийни файлове):** Това са файловете на **потребителите** — качените от тях аватари, снимки на обяви и PDF документи. Те се качват в реално време и **никога не се пазят в Git**.

## 2. ЕТАПИ НА РЕНДИРАНЕ НА ШАБЛОН И БЛОК-СХЕМА

Django използва **Server-Side Rendering (SSR)** — сървърът сглобява крайния HTML текст и го праща готов към браузъра:

```text
┌──────────────────────────┐     1. Наследяване          ┌─────────────────────────┐
│ child.html               │ ─────────────────────────► │ base.html               │
│ {% extends 'base.html' %}│   (Попълва празните дупки  │ Съдържа <head>, Navbar, │
│ {% block content %}...   │    {% block content %})    │ Footer и CSS линкове    │
└──────────────────────────┘                            └────────────┬────────────┘
                                                                     │ 2. Инжектира Context {}
                                                                     ▼
┌──────────────────────────┐     3. Auto-Escaping (XSS)  ┌─────────────────────────┐
│ Чист HTML отговор        │ ◄───────────────────────── │ Превръща <script> в     │
│ (200 OK към браузъра)    │   (Защита от хакери!)       │ безопасен текст &lt;... │
└──────────────────────────┘                            └─────────────────────────┘
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: DJANGO DTL СРЕЩУ C# RAZOR И JS/REACT

| Концепция | Django DTL (Python) | ASP.NET Core Razor (C#) | React / JSX (JS/TS) |
| :--- | :--- | :--- | :--- |
| **Извеждане на променлива** | `{{ user.username }}` | `@Model.Username` | `{user.username}` |
| **Условна конструкция** | `{% if x %} ... {% endif %}` | `@if (x) { ... }` | `{x && <div />}` |
| **Цикъл** | `{% for item in list %} ... {% endfor %}` | `@foreach (var item in list) { }` | `{list.map(item => ...)}` |
| **Наследяване на Layout** | `{% extends "base.html" %}` | `Layout = "_Layout.cshtml";` | `<Layout>{children}</Layout>` |
| **Генериране на линк по име** | `{% url 'books:detail' book.id %}` | `asp-action="Detail" asp-route-id="..."` | `<Link to={\`/books/${id}\`}>` |
| **Статични файлове** | `{% load static %}` + `{% static 'css/a.css' %}` | `~/css/a.css` (`wwwroot/`) | `import './a.css'` |

## 4. ПЛЮСОВЕ И МИНУСИ НА DTL, STATIC И MEDIA ФАЙЛОВЕТЕ

### 🟢 Предимства (Pros):
*   **Вградена защита от XSS (Cross-Site Scripting):** По подразбиране Django автоматично неутрализира всеки опасен HTML или `<script>` таг, дошъл от базата данни.
*   **Мощно наследяване на шаблони (DRY):** Пишеш менюто (`navbar`) и долната лента (`footer`) само веднъж в `base.html`, а всички 50 страници в сайта го наследяват с един ред.

### 🔴 Недостатъци (Cons):
*   **Умишлено ограничен синтаксис:** В DTL не можеш да пишеш сложен Python код или да викаш функции с аргументи (напр. `{{ user.get_posts(5) }}` хвърля `TemplateSyntaxError`!). Всички изчисления трябва да са готови в `views.py` преди рендирането.
*   **Django не сервира `MEDIA` файлове в продукция:** На жив сървър (`DEBUG = False`) Django спира да обслужва качените снимки — трябва да се настроят Nginx или облачно хранилище (AWS S3 / Cloudinary).

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Опасен `|safe` филтър върху потребителски текст и хардкоднати пътища):
```html
<!-- 🚨 ГРЕШКА 1: Използване на |safe върху текст, въведен от потребител! -->
<!-- Ако хакер напише коментар "<script>stealCookies()</script>", браузърът ще го изпълни! -->
<p>{{ user_comment|safe }}</p>

<!-- 🚨 ГРЕШКА 2: Хардкодване на URL адреси и CSS пътища! -->
<link rel="stylesheet" href="/static/css/style.css">
<a href="/books/5/">Виж книга</a>
```
*   **Как да се избегне:** Никога не слагай `|safe` на потребителски данни. Винаги ползвай таговете `{% static '...' %}` и `{% url '...' %}` (както `asp-action` в C#), за да не чупиш линковете при смяна на URL структурата.

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic HTML шаблон с наследяване и защита):
```html
{% extends "base.html" %}
{% load static %}

{% block title %}Каталог с книги{% endblock %}

{% block content %}
    <link rel="stylesheet" href="{% static 'css/catalog.css' %}">

    <h1>Налични книги ({{ books|length }})</h1>

    {% for book in books %}
        <div class="book-card">
            {% if book.cover_image %}
                <img src="{{ book.cover_image.url }}" alt="{{ book.title }}">
            {% endif %}
            <h3>{{ book.title }}</h3>
            <a href="{% url 'books:detail' book.pk %}">Детайли</a>
        </div>
    {% empty %}
        <p>В момента няма добавени книги в каталога.</p>
    {% endfor %}
{% endblock %}
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Какво представляват Context Processors в Django (напр. `django.template.context_processors.request` или `auth`) и кога пишем свой собствен Context Processor?“*
*   **Уловката:** Начинаещите програмисти подават `{"user": request.user, "categories": Category.objects.all()}` ръчно във всяко едно `return render(...)` из целия проект.
*   **Точен Senior отговор:** **Context Processor** е обикновена Python функция, която приема `request` и връща речник `dict`. Всички ключове в този речник стават **автоматично достъпни във всеки един HTML шаблон в целия сайт**, без да ги подаваш ръчно в `views.py`! Точно благодарение на вградените Context Processors в шаблоните винаги имаме променливата `{{ user }}` и `{{ request }}`. Пишем свой собствен, когато имаме глобални елементи за навигацията (например брой артикули в количката или списък с категории в главното меню).
