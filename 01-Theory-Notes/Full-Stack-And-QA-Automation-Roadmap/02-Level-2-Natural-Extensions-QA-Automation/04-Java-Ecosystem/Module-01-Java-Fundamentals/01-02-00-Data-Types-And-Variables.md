## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Четирите чаши за цели числа (от най-малката към най-голямата):**
    1.  `byte` (1 байт = 8 бита): от **`-128` до `127`** (малка чашка за кафе — събира години на човек или проценти).
    2.  `short` (2 байта = 16 бита): от **`-32 768` до `32 767`**.
    3.  `int` (4 байта = 32 бита): от **`-2.14 милиарда` до `+2.14 милиарда`** (стандартната чаша за всичко в Java).
    4.  `long` (8 байта = 64 бита): до **`±9 квинтилиона`** (огромна кофа — **задължително** слагай суфикс **`L`** в края на големи числа, напр. `long pop = 8_000_000_000L;`, иначе компилаторът го мисли за `int` и гърми!).
*   **`float` и `double` срещу `BigDecimal`:**
    *   `double` (8 байта) и `float` (4 байта, суфикс `f`) са за физика, графики и геометрия.
    *   **Никога не смятай пари с `double`!** За банкови сметки и цени в Java се ползва единствено **`BigDecimal`**.

## 2. ЙЕРАРХИЯ НА АВТОМАТИЧНОТО ПРЕОБРАЗУВАНЕ (WIDENING CASTING) И БЛОК-СХЕМА

От по-малка към по-голяма кутия Java прелива автоматично без загуба на данни (**Implicit / Widening**). В обратната посока трябва изричен каст `(int)` (**Explicit / Narrowing**), при който дробната част се отрязва!

```text
Автоматично разширяване (Без загуба на данни):
byte (1B) ──► short (2B) ──► int (4B) ──► long (8B) ──► float (4B) ──► double (8B)
                                ▲
                             char (2B)

Ръчно стесняване (Narrowing — изисква (тип) и реже данни!):
double 3.99  ──►  (int) 3.99  ──►  3  (Дробната част .99 се изхвърля без закръгляне!)
```

| :--- | :--- | :--- | :--- | :--- |
| **Цяло число (32-bit)** | `int count = 42;` | `int count = 42;` | `count = 42` (безкраен) | `let count = 42;` (`Number`) |

## 4. ПЛЮСОВЕ И МИНУСИ НА СИСТЕМАТА ОТ ТИПОВЕ В JAVA

### 🟢 Предимства (Pros):
*   **Максимална защита от скрити преобразувания:** За разлика от JavaScript (`"5" - 2 == 3`, но `"5" + 2 == "52"`), в Java не можеш случайно да събереш или извадиш несъвместими типове без явна декларация.
*   **Ясни долни черти в големи числа:** Можеш да пишеш `int million = 1_000_000;` за четимост (също като в C# и Python).

### 🔴 Недостатъци (Cons):
*   **Липса на беззнакови цели числа (`uint`, `ulong`):** Дори възрастта на човек или броят елементи трябва да се пазят в signed `int` (макар от Java 8 да има помощни методи `Integer.compareUnsigned()`).
*   **Неудобен синтаксис на `BigDecimal`:** Тъй като в Java няма претоварване на оператори (`+`, `-`, `*`), с `BigDecimal` не пишеш `a + b`, а `a.add(b)`.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД (ФИНАНСОВА ТОЧНОСТ И ПРЕЛИВАНЕ)

### ❌ ГРЕШЕН КОД (Целочислено делене, `double` за пари и `new BigDecimal(double)`):
```java
// 🚨 ГРЕШКА 1: Целочислено делене (int / int = int)!
double half = 5 / 2; // Резултатът е 2.0, а НЕ 2.5!

// 🚨 ГРЕШКА 2: Използване на double за пари (IEEE 754 закръгляне)!
System.out.println(0.1 + 0.2); // Извежда: 0.30000000000000004!

// 🚨 ГРЕШКА 3: Създаване на BigDecimal от double вместо от String!
BigDecimal badMoney = new BigDecimal(0.1); 
// Записва вътре 0.1000000000000000055511151231257827021181583404541015625!
```
*   **Как да се избегне:** За дробно делене направи поне единия операнд `double` (`5.0 / 2` или `(double) a / b`). За пари **винаги** подавай **`String`** в конструктора на `BigDecimal` (`new BigDecimal("0.1")`) или ползвай `BigDecimal.valueOf(0.1)`.

### 🟢 ПРАВИЛЕН КОД (Точна финансова аритметика и безопасно кастване):
```java
import java.math.BigDecimal;
import java.math.RoundingMode;

public class PrecisionDemo {
    public static void main(String[] args) {
        // 1. Правилно дробно делене
        int a = 5, b = 2;
        double exactHalf = (double) a / b; // 2.5

        // 2. Безопасна работа с пари чрез BigDecimal и String
        BigDecimal price = new BigDecimal("19.99");
        BigDecimal vatRate = new BigDecimal("1.20");
        BigDecimal total = price.multiply(vatRate).setScale(2, RoundingMode.HALF_UP);

        System.out.println("Крайна цена с ДДС: " + total); // 23.99
    }
}
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Какво ще се случи, ако в Java съберем две променливи от тип `byte` (`byte a = 10; byte b = 20; byte c = a + b;`) и защо компилаторът отхвърля този ред?“*
*   **Уловката:** Кандидатите мислят, че `10 + 20 = 30` се побира в `byte` (до 127), така че кодът трябва да се компилира без проблем!
*   **Точен Senior отговор:** Кодът **няма да се компилира** (`Incompatible types: possible lossy conversion from int to byte`). Причината е правилото **Numeric Promotion (Повишаване на типовете)** в спецификацията на Java: при всяка аритметична операция (`+`, `-`, `*`, `/`) върху типове, по-малки от `int` (`byte`, `short`, `char`), JVM автоматично ги превръща в **`int`** преди сметката! Затова резултатът от `a + b` е от тип `int` и изисква изричен каст: `byte c = (byte) (a + b);` (същото правило важи и в C#!).
