## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **`ArrayList` = Разтеглив шкаф с номерирани чекмеджета:** Под капака държи обикновен масив `Object[]` с начален размер **10**. Четенето на чекмедже #500 (`list.get(500)`) става за **O(1)** (мигновено). Но ако вмъкнеш ново чекмедже най-отпред (`list.add(0, x)`), трябва да преместиш всички останали 500 чекмеджета с едно надясно (**O(n)**).
*   **`LinkedList` = Влакова композиция от вагони:** Всеки вагон (`Node`) пази своята стойност и два указателя — към **предишния** и към **следващия** вагон (Doubly Linked List). Откачането на първия или последния вагон става за **O(1)**, но за да стигнеш до 500-ния вагон (`list.get(500)`), кондукторът трябва да мине пеша през всичките 500 вагона (**O(n)**).
*   **Златно правило в Java:** В **99% от случаите** използвай **`ArrayList`**, защото процесорният кеш чете непрекъснатия му масив десетки пъти по-бързо от разпръснатите в RAM паметта възли на `LinkedList`!

## 2. АРХИТЕКТУРА НА `ARRAYLIST` СРЕЩУ `LINKEDLIST` (БЛОК-СХЕМА)

```text
1. ArrayList (Непрекъснат блок в Heap паметта -> O(1) достъп по индекс):
   Индекси:   [  0  |  1  |  2  |  3  | ... |  9  ]
   Стойности: [ "A" | "B" | "C" | null| ... | null]  (size = 3, capacity = 10)

2. LinkedList (Разпръснати възли в Heap паметта -> O(n) достъп по индекс):
   ┌──────────────┐      ┌──────────────┐      ┌──────────────┐
   │ prev: null   │ ───► │ prev         │ ───► │ prev         │
   │ data: "A"    │ ◄─── │ data: "B"    │ ◄─── │ data: "C"    │
   │ next         │      │ next         │      │ next: null   │
   └──────────────┘      └──────────────┘      └──────────────┘
```

## 4. ПЛЮСОВЕ И МИНУСИ НА `ARRAYLIST` И `LINKEDLIST`

### 🟢 `ArrayList` — Предимства и Недостатъци:
*   **Предимства:** Светкавичен достъп по индекс ($O(1)$); минимален разход на памет на елемент; отличен за итерация и сортиране.
*   **Недостатъци:** Бавно вмъкване/изтриване в началото ($O(n)$); при препълване на капацитета прави алокация на нов масив `oldCapacity + (oldCapacity >> 1)` (1.5x).

### 🔵 `LinkedList` — Предимства и Недостатъци:
*   **Предимства:** Имплементира едновременно `List` и `Deque` (двустранна опашка), позволявайки $O(1)$ добавяне/махане от двата края (`addFirst`, `removeLast`).
*   **Недостатъци:** Всеки елемент заема ~24 байта допълнителна памет за обекта `Node` и двата му указателя; бавно търсене по индекс ($O(n)$).

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД (`REMOVE(INT)` И `ARRAYS.ASLIST` КАПАНИ)

### ❌ ГРЕШЕН КОД (Опит за `.add()` върху `List.of()` / `Arrays.asList()` и `remove(int)` върху `List<Integer>`):
```java
// 🚨 ГРЕШКА 1: List.of() създава НЕПРОМЕНЯЕМ (Immutable) списък!
List<String> fixed = List.of("A", "B");
fixed.add("C"); // Хвърля UnsupportedOperationException по време на изпълнение!

// 🚨 ГРЕШКА 2: Arrays.asList() създава списък с ФИКСИРАН размер (гърми при .add() / .remove())!
List<String> semiFixed = Arrays.asList("A", "B");
semiFixed.add("C"); // Също хвърля UnsupportedOperationException!

// 🚨 ГРЕШКА 3: Изтриване на число 5 от List<Integer> без Integer.valueOf()!
List<Integer> nums = new ArrayList<>(List.of(5, 10, 15));
nums.remove(5); // Java търси ИНДЕКС 5 вместо стойност 5 -> IndexOutOfBoundsException!
```
*   **Как да се избегне:** Когато ти трябва истински, свободно изменяем списък с начални стойности, **винаги** го обвивай в **`new ArrayList<>(List.of(...))`**. За изтриване на числова стойност от `List<Integer>` винаги пиши **`nums.remove(Integer.valueOf(5))`**.

### 🟢 ПРАВИЛЕН КОД (Истински изменяем списък и безопасно изтриване):
```java
import java.util.ArrayList;
import java.util.List;

public class SafeListsDemo {
    public static void main(String[] args) {
        // Истински изменяем ArrayList с начални елементи
        List<Integer> nums = new ArrayList<>(List.of(5, 10, 15, 5));

        nums.add(20);                        // Работи!
        nums.remove(Integer.valueOf(5));     // Премахва ПЪРВАТА срещната стойност 5 ->
        nums.removeIf(n -> n == 5);          // Премахва ВСИЧКИ останали 5-ци ->

        System.out.println(nums);
    }
}
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Каква е разликата между Fail-Fast и Fail-Safe итераторите в Java колекциите, и защо `for (String s : list) { list.remove(s); }` хвърля `ConcurrentModificationException` дори в еднонишкова програма?“*
*   **Уловката:** Кандидатите често мислят, че `ConcurrentModificationException` се случва само когато две различни нишки променят списъка едновременно!
*   **Точен Senior отговор:** `ArrayList` поддържа вътрешен брояч на промените, наречен **`modCount`**. Когато започнеш `for-each` цикъл, скритият `Iterator` запомня началната стойност (`expectedModCount = modCount`). Ако вътре в цикъла извикаш `list.remove(s)` директно върху списъка, `modCount` се увеличава, но итераторът не знае за това. На следващата стъпка итераторът вижда `modCount != expectedModCount` и веднага хвърля **`ConcurrentModificationException`** (поведение **Fail-Fast**, за да предотврати тихо пропускане на елементи).
    *   **Правилни решения:** Използвай **`list.removeIf(s -> condition)`** (най-чистият начин в модерна Java) или изричен **`Iterator`** с неговия собствен метод **`iterator.remove()`**.
