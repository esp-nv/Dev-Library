## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **`String` е табела, гравирана върху камък (Immutable):** След като създадеш `String s = "Java";`, нито една буква в този обект в паметта не може да бъде променена. Всеки метод като `.toUpperCase()`, `.replace()` или `+` **не променя оригинала**, а създава изцяло нов каменен блок в паметта.
*   **`StringBuilder` е бяла дъска с маркер (Mutable):** Можеш да дописваш (`.append()`), вмъкваш (`.insert()`) и изтриваш (`.delete()`) текст върху същия вътрешен масив от байтове без да заделяш нова памет на всяка стъпка.
*   **`StringBuilder` срещу `StringBuffer`:** Имат абсолютно еднакви методи, но `StringBuilder` е **бърз и еднонишков** (ползва се в 99.9% от случаите), докато `StringBuffer` е старият **многонишкова (Thread-Safe)** вариант със `synchronized` методи (по-бавен).

## 2. АРХИТЕКТУРА НА STRING CONSTANT POOL В HEAP ПАМЕТТА (БЛОК-СХЕМА)

От Java 7 насам **String Pool** се намира вътре в главната **Heap** памет (за да може Garbage Collector-ът да почиства неизползваните низове):

```text
STACK ПАМЕТ                     HEAP ПАМЕТ
┌──────────────────────┐        ┌───────────────────────────────────────────────────┐
│ s1 ──────────────────┼───────►│ ┌───────────────────────────────────────────────┐ │
│ s2 ──────────────────┼───────►│ │ STRING CONSTANT POOL                          │ │
│                      │        │ │   "Java" @ 0x100  (Споделен между s1 и s2!)   │ │
│                      │        │ └───────────────────────────────────────────────┘ │
│ s3 ──────────────────┼───────►│ Обект new String("Java") @ 0x500 (Извън пула!)    │
└──────────────────────┘        └───────────────────────────────────────────────────┘
* Резултат: (s1 == s2) е TRUE, но (s1 == s3) е FALSE! А s1.equals(s3) е винаги TRUE!
```

## 4. ПЛЮСОВЕ И МИНУСИ НА `STRING`, `STRINGBUILDER` И `STRINGBUFFER`

### 🟢 Защо `String` е направен неизменяем (Immutable)? — 3 архитектурни причини:
1.  **Пестене на RAM чрез String Pool:** Десетки променливи със стойност `"OK"` или `"Admin"` сочат към един и същ байтов масив в паметта.
2.  **Сигурност (Security):** В Java пароли, URL адреси към бази данни и имена на класове се подават като `String`. Ако стрингът можеше да се променя, външен код би могъл да подмени пътя на файла след проверката за права.
3.  **Кеширане на `hashCode()`:** Тъй като съдържанието никога не се променя, `String` изчислява своя `hashCode()` само **веднъж** и го пази кеширан — затова `String` е най-бързият възможен ключ в `HashMap`.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД ($O(n^2)$ КОНКАТЕНАЦИЯ В ЦИКЪЛ)

### ❌ ГРЕШЕН КОД (Конкатенация със `+=` в цикъл — $O(n^2)$ убиец на производителността):
```java
String result = "";
// 🚨 ГРЕШКА: При всяка от 100 000-те стъпки Java създава нов String обект и копира целия стар текст!
// Отнема ~5–10 секунди и запълва Heap паметта с боклук за Garbage Collector-а!
for (int i = 0; i < 100_000; i++) {
    result += i + ",";
}
```
*   **Как да се избегне:** В цикъл **никога** не слепвай стрингове с `+` или `+=`. Използвай **`StringBuilder`** (същите 100 000 стъпки минават за **3 милисекунди**!).

### 🟢 ПРАВИЛЕН КОД (Светкавично изграждане на текст със `StringBuilder`):
```java
public class CleanStringBuilderDemo {
    public static void main(String[] args) {
        StringBuilder sb = new StringBuilder();

        for (int i = 0; i < 100_000; i++) {
            sb.append(i).append(",");
        }

        String finalResult = sb.toString();
        System.out.println("Дължина: " + finalResult.length());
    }
}
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Каква е разликата между **`s.trim()`** и модерния метод **`s.strip()`** (въведен в Java 11), и каква оптимизация направи Java 9 в паметта на `String` (**Compact Strings**)?“*
*   **Уловката:** Кандидатите често мислят, че `trim()` и `strip()` правят едно и също нещо, и не знаят как Java намали разхода на памет за стрингове наполовина.
*   **Точен Senior отговор:** 
    1.  **`trim()` срещу `strip()`:** Старият `trim()` премахва само ASCII символи с код $\le 32$ (`\u0020`), но **не разпознава Unicode интервали** (като неразделим интервал `\u00A0` или типографски шпации). Модерният **`strip()`** (заедно с `stripLeading()` и `stripTrailing()`) използва `Character.isWhitespace()` и чисти правилно **всички Unicode интервали**.
    2.  **Compact Strings (Java 9+):** Преди Java 9 всеки `String` пазеше буквите в `char[]` (по 2 байта UTF-16 на символ), дори когато текстът е само на латиница. От Java 9 нататък `String` използва **`byte[]` + 1 байт кодировка (`LATIN1` или `UTF16`)** — ако текстът съдържа само Latin-1 символи, заема **1 байт на символ вместо 2 байта**, спестявайки до 50% от Heap паметта на сървъра!
