## 1. ЛОКАЛИЗИРАНЕ НА ЕЛЕМЕНТИ В УЕБ ОБКРЪЖЕНИЕТО

За да може автоматизираният тестов робот да кликне върху бутон или да въведе текст в уеб форма, той трябва първо да намери точния адрес на този елемент в зареденото в RAM паметта **DOM (Document Object Model) дърво**. Този процес се нарича локализиране.

Браузърният двигател предоставя вградени методи за търсене, подредени по софтуерна надеждност:
*   `By.Id`: Най-бързият и сигурен начин, тъй като по стандарт ID атрибутът трябва да бъде напълно уникален в рамките на уеб страницата.
*   `By.Name`: Търсене по име на уеб контролата (критично при Model Binding обвързвания).
*   `By.ClassName` и `By.TagName`: Търсене по CSS клас или HTML таг (връща масиви от обекти).

---

## 2. CSS СЕЛЕКТОРИ: СКОРОСТ И БАЗОВИ СЪВПАДЕНИЯ

Когато елементите нямат уникални ID атрибути, се преминава към използване на **CSS Селектори (`By.CssSelector`)**. Те използват същия синтаксис, с който графичният енджин на браузъра налага стиловете:
*   `#submit-btn` ➔ Маркира елемент с конкретно ID (еквивалент на `By.Id`).
*   `.form-control` ➔ Маркира елементи, притежаващи дадения CSS клас.
*   `div.card > p` ➔ Търси директно дете параграф `<p>`, намиращ се вътре в контейнер `<div>` с клас `card`.

---

## 3. НАПРЕДНАЛИ XPATH СТРАТЕГИИ И СЕМАНТИЧНИ ОСИ

Когато уеб интерфейсът е изключително динамичен и елементите се променят непрекъснато, най-мощното инженерно оръжие е **XPath (XML Path Language)**. За разлика от CSS (който може да навигира само отгоре-надолу по дървото), XPath притежава двупосочна софтуерна гъвкавост.

### А. Абсолютен срещу Относителен път:
*   **Абсолютен път (`/html/body/div[1]/form/input`):** Започва строго от корена. **Изключително чуплив анти-патерн** – ако разработчиците добавят дори един допълнителен `<div>` по средата, целият път се срива.
*   **Относителен път (`//input[@name='Email']`):** Сканира уеб документа и открива елемента навсякъде, без значение колко дълбоко е вложен.

### Б. Напреднали XPath Оси (Axes) за динамични структури:
Когато дадено поле няма атрибути, но се намира до познат статичен елемент, използваме релационни оси:
*   `//label[text()='Имейл']/following-sibling::input` ➔ Намира текстовия етикет с точен текст 'Имейл' и хваща следващото кутийка-брат (`following-sibling`), разположена веднага до него.
*   `//input[@id='username']/parent::div` ➔ Навигира нагоре по дървото, за да улови директния родителски контейнер (`parent`) на инпута.
