## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Четирите букви за режим на отваряне:**
    *   **`"r"` (Read):** Само за четене. Ако файлът липсва, програмата гърми с `FileNotFoundError`.
    *   **`"w"` (Write - Опасният режим!):** За писане. Ако файлът не съществува — създава го. Ако **вече съществува — изтрива цялото му старо съдържание на мига** и започва на чисто!
    *   **`"a"` (Append):** За добавяне в края. Създава файла ако липсва, а ако съществува — дописва новите редове най-отдолу, без да пипа старите.
    *   **`"x"` (Exclusive Creation):** Създава нов файл, но **гърми с `FileExistsError`**, ако такъв файл вече съществува (защита против случайно презаписване).

## 2. ЕТАПИ НА РАБОТА НА CONTEXT MANAGER (`WITH`) И БЛОК-СХЕМА

Ключовата дума **`with`** използва протокола на контекст мениджърите (методите `__enter__` и `__exit__`), което е пълният еквивалент на `using` блока в C#.

```text
with open("report.txt", "r", encoding="utf-8") as file:

┌──────────────────────────┐     1. __enter__()         ┌─────────────────────────┐
│ Влизане в 'with' блока   │ ─────────────────────────► │ Операционната система   │
│                          │   Отваря файлов дескриптор │ заключва и подава файла │
└──────────────────────────┘                            └────────────┬────────────┘
                                                                     │ 2. Четене / Писане
                                                                     ▼
┌──────────────────────────┐     3. __exit__()          ┌─────────────────────────┐
│ Файлът е затворен и      │ ◄───────────────────────── │ Излизане от блока       │
│ RAM буферът е изчистен!  │   (Изпълнява се ВИНАГИ,    │ (Дори при възникнала    │
└──────────────────────────┘    дори при Exception!)    │ грешка вътре!)          │
                                                        └─────────────────────────┘
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Операция | Python 3.x | C# (.NET) | JavaScript (Node.js `fs`) |
| :--- | :--- | :--- | :--- |
| **Автоматично затваряне** | `with open("f.txt") as f:` | `using var sr = new StreamReader(...)` | `fs.readFileSync()` (затваря сам) |
| **Четене на целия текст** | `f.read()` | `File.ReadAllText("f.txt")` | `fs.readFileSync("f.txt", "utf8")` |
| **Четене ред по ред** | `for line in f:` (Lazy!) | `File.ReadLines("f.txt")` (Lazy) | `readline` интерфейс (Streams) |
| **Модерни пътища** | `from pathlib import Path` | `Path.Combine("dir", "f.txt")` | `path.join("dir", "f.txt")` |
| **Изтриване на файл** | `os.remove("f.txt")` | `File.Delete("f.txt")` | `fs.unlinkSync("f.txt")` |

## 4. ПЛЮСОВЕ И МИНУСИ НА ФАЙЛОВИТЕ ОПЕРАЦИИ В PYTHON

### 🟢 Предимства (Pros):
*   **Итерация ред по ред без заемане на RAM:** Файловият обект е вграден итератор. Изразът `for line in file:` чете само по един ред в паметта, което позволява обработката на 50 GB лог файлове на лаптоп с 8 GB RAM.
*   **Модулът `pathlib`:** Превръща файловите пътища в обекти, които автоматично оправят наклонените черти между Windows (`\`) и Linux (`/`).

### 🔴 Недостатъци (Cons):
*   **Зависимост от системния енкодинг на Windows:** Ако пропуснеш `encoding="utf-8"`, на Windows Python често ползва `cp1251` или `cp1252` по подразбиране, което води до `UnicodeDecodeError` или маймуница при кирилица.
*   **Тих капан с `file.read()`:** Извикването на `.read()` зарежда абсолютно целия файл в RAM паметта наведнъж и премества вътрешния курсор накрая — второ извикване на `.read()` връща празен стринг `""`!

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Зареждане на гигантски файл в RAM и липсващ енкодинг):
```python
# 🚨 ГРЕШКА 1: Липсва encoding="utf-8" (чупи кирилицата под Windows!)
# 🚨 ГРЕШКА 2: .readlines() зарежда целия файл в списък в паметта (OutOfMemory при големи логове!)
with open("huge_server.log", "r") as f:
    all_lines = f.readlines()  # Опасно при файлове над 1 GB!
    for line in all_lines:
        if "ERROR" in line:
            print(line)
```
*   **Как да се избегне:** Винаги добавяй `encoding="utf-8"` и обхождай директно файловия обект (`for line in f:`), без `.readlines()`.

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic стандарт с `pathlib` и стрийминг четене):
```python
from pathlib import Path

# 1. Създаване на крос-платформен път (работи еднакво на Windows и Linux)
log_path = Path("logs") / "app_audit.txt"
log_path.parent.mkdir(parents=True, exist_ok=True)  # Създава папка 'logs', ако липсва

# 2. Безопасен запис с UTF-8 енкодинг
with open(log_path, "w", encoding="utf-8") as file:
    file.write("INFO: Системата стартира успешно.\n")
    file.write("ERROR: Връзката с Redis прекъсна!\n")
    file.write("INFO: Връзката е възстановена.\n")

# 3. Оптимизирано четене ред по ред (без претоварване на RAM)
with open(log_path, "r", encoding="utf-8") as file:
    for line_number, line in enumerate(file, start=1):
        if "ERROR" in line:
            print(f"[Ред {line_number}] {line.strip()}")
```
*   **Изход в конзолата:**
    ```text
    [Ред 2] ERROR: Връзката с Redis прекъсна!
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Какво представлява файловият курсор (File Pointer) в Python и защо извикването на `f.read()` два пъти подред в един и същ `with` блок връща празен текст втория път?“*
*   **Уловката:** Кандидатите често мислят, че `f.read()` изтрива или затваря файла след прочитане.
*   **Точен Senior отговор:** Когато отвориш файл, операционната система поддържа вътрешен указател за позиция в байтове (**File Pointer**), който започва от позиция `0` (началото на файла). Когато извикаш `f.read()`, указателят прочита всичко и остава паркиран **в самия край на файла (EOF - End Of File)**. При второ извикване на `f.read()` той започва да чете от края нататък и намира `0` байта (`""`).
    *   **Правилен фикс:** За да върнеш курсора обратно в началото на файла без да го затваряш и отваряш наново, се извиква методът **`f.seek(0)`**.
