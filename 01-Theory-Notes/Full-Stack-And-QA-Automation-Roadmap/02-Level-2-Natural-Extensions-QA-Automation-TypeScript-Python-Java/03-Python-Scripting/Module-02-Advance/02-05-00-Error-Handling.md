## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Четирите блока на `try`:**
    *   **`try:`** ➔ „Опитай да направиш това“ (рисковият код).
    *   **`except:`** ➔ „Ако гръмне, хвани го тук“ (спасителната мрежа).
    *   **`else:`** ➔ „Ако всичко мине гладко без грешки, направи и това“ (изпълнява се **само** при успех).
    *   **`finally:`** ➔ „Каквото и да стане, направи това накрая“ (изпълнява се **винаги**, дори да има `return` или нов срив).
*   **EAFP срещу LBYL:** В C# и JS пишем LBYL (*Look Before You Leap* — първо проверяваме с `if` дали файлът съществува, после го отваряме). В Python следваме **EAFP** (*Easier to Ask for Forgiveness than Permission* — направо отваряме файла в `try`, и ако го няма, хващаме `FileNotFoundError`).

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Концепция | Python 3.x | C# (.NET) | JavaScript (ES6+) |
| :--- | :--- | :--- | :--- |
| **Блокове за прихващане** | `try` / `except` / `else` / `finally` | `try` / `catch` / `finally` | `try` / `catch` / `finally` |
| **Хвърляне на грешка** | `raise ValueError("Съобщение")` | `throw new ArgumentException("...")` | `throw new Error("...")` |
| **Базов клас за грешки** | `Exception` (над него е `BaseException`) | `System.Exception` | `Error` |
| **Потребителска грешка** | `class MyError(Exception): pass` | `class MyException : Exception` | `class MyError extends Error` |
| **Препращане на грешката** | `raise` (без аргументи) | `throw;` (без променлива!) | `throw err;` |

## 4. ПЛЮСОВЕ И МИНУСИ НА УПРАВЛЕНИЕТО НА ГРЕШКИ

### 🟢 Предимства (Pros):
*   **Уникалният блок `else:` в `try`:** Позволява ти да изолираш в `try` **само** онзи един ред код, който наистина може да гръмне, а останалата логика да сложиш в `else:`, за да не хванеш случайно грешка от съвсем друго място.
*   **Бързи изключения в Python:** За разлика от C# и Java, където хвърлянето на `Exception` е много скъпа операция за процесора, в Python изключенията са леки и са част от нормалния поток на езика (дори `for` циклите спират вътрешно чрез `StopIteration`).

### 🔴 Недостатъци (Cons):
*   **Скриване на грешки при лошо писане:** Използването на общ `except Exception:` може да погълне правописна грешка в име на променлива (`NameError`) и да заблуди програмиста, че грешката е дошла от мрежата или базата данни.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Грешен ред на `except` блоковете и голо `except:`):
```python
try:
    number = int(input("Въведи число: "))
    result = 100 / number
# 🚨 ГРЕШКА 1: Поставяне на общия 'Exception' ПЪРВИ!
# Той хваща всичко и долният 'ZeroDivisionError' никога няма да се изпълни!
except Exception:
    print("Обща грешка.")
except ZeroDivisionError:
    print("Деление на нула!") # Мъртъв код (Unreachable)!
```
*   **Как да се избегне:** Винаги подреждай `except` блоковете от **най-конкретния** към **най-общия** (точно както в C#).

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic стандарт с Custom Exception и `else`/`finally`):
```python
# 1. Дефиниране на собствен (Custom) клас за бизнес грешка
class InsufficientFundsError(Exception):
    pass

def withdraw_money(balance: float, amount: float) -> float:
    if amount <= 0:
        raise ValueError("Сумата за теглене трябва да е положителна.")
    if amount > balance:
        raise InsufficientFundsError(f"Недостатъчна наличност! Баланс: {balance} лв.")
    return balance - amount

# 2. Пълна 4-степенна защита при извикване
current_balance = 500.0

try:
    new_balance = withdraw_money(current_balance, 200.0)
except (ValueError, InsufficientFundsError) as err:
    print(f"[❌ ОТКАЗ]: {err}")
else:
    # Изпълнява се САМО ако няма грешка в try блока
    current_balance = new_balance
    print(f"[✅ УСПЕХ]: Трансакцията мина. Нов баланс: {current_balance} лв.")
finally:
    # Изпълнява се ВИНАГИ
    print("[🔒 ОДИТ]: Банковата сесия е затворена.")
```
*   **Изход в конзолата:**
    ```text
    [✅ УСПЕХ]: Трансакцията мина. Нов баланс: 300.0 лв.
    [🔒 ОДИТ]: Банковата сесия е затворена.
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Каква е разликата между `except Exception:` и голото `except:` в Python и защо голото `except:` е опасно?“*
*   **Уловката:** Кандидатите често мислят, че двете правят абсолютно едно и също.
*   **Точен Senior отговор:** Над класа `Exception` в йерархията на Python стои още по-висок базов клас — **`BaseException`**. От него наследяват системни сигнали за спиране на програмата като **`KeyboardInterrupt`** (когато натиснеш `Ctrl+C` в терминала) и **`SystemExit`** (когато извикаш `sys.exit()`).
    *   Голото `except:` (без посочен клас) хваща `BaseException` — това означава, че ако програмата ти влезе в безкраен цикъл, **няма да можеш да я спреш дори с `Ctrl+C`**, защото `except:` ще погълне сигнала за спиране!
    *   Затова **винаги** трябва да наследяваш и хващаш най-много `except Exception:`, никога голо `except:`.
