## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Една звездичка (`*args`) = Кортеж (`tuple`):** Събира всички излишни позиционни аргументи в една торба без имена. Името `args` е само конвенция — важната е **едната звездичка `*`**.
*   **Две звездички (`**kwargs`) = Речник (`dict`):** Събира всички излишни именувани аргументи (`key=value`) в речник. Името `kwargs` (Keyword Arguments) е конвенция — важни са **двете звездички `**`**.
*   **Closure (Затваряне) = Раница с провизии:** Когато външна функция върне вътрешна функция, вътрешната си тръгва, но си взима „раница“ (`__closure__`), в която е прибрала локалните променливи на външната функция, дори след като външната вече е приключила изпълнението си.

## 2. ЕТАПИ НА РАБОТА НА CLOSURE (ЗАТВАРЯНЕ) И БЛОК-СХЕМА

```text
def make_multiplier(factor):
    def multiply(number):
        return number * factor  # Помни 'factor' в своята раница!
    return multiply

┌──────────────────────────┐     1. Извикване:          ┌─────────────────────────┐
│ double = make_multiplier(2)│ ────────────────────────► │ Външната функция умира, │
│                          │                           │ но запазва factor = 2   │
└──────────────────────────┘                           └────────────┬────────────┘
                                                                    │ 2. Връща multiply
                                                                    ▼
┌──────────────────────────┐     3. Извикване:          ┌─────────────────────────┐
│ Резултат: 10             │ ◄──────────────────────── │ double(5) ➔ 5 * 2       │
│                          │                           │ (Чете factor от раницата)│
└──────────────────────────┘                           └─────────────────────────┘
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Концепция | Python 3.x | C# (.NET) | JavaScript (ES6+) |
| :--- | :--- | :--- | :--- |
| **Неограничени аргументи** | `def f(*args):` (`tuple`) | `void F(params int[] args)` | `function f(...args)` (`Array`) |
| **Именувани аргументи** | `def f(**kwargs):` (`dict`) | Няма директен речников еквивалент | Деструктуриране на обект `({a, b})` |
| **Разопаковане при викане** | `func(*my_list, **my_dict)` | Няма директен оператор за масив | `func(...myArray)` (Spread) |
| **Рекурсия (Лимит на стека)** | Строг лимит (~1000 извиквания) | Зависи от размера на Stack (~1MB) | Зависи от браузъра (~10 000+) |
| **Tail Call Optimization** | **Не се поддържа** | Поддържа се от JIT в някои случаи | Само в Safari (WebKit) |

## 4. ПЛЮСОВЕ И МИНУСИ НА НАПРЕДНАЛИТЕ ФУНКЦИИ

### 🟢 Предимства (Pros):
*   **Изключителна гъвкавост при API обвивки (Wrappers):** С `*args` и `**kwargs` можеш да напишеш универсална функция, която приема всякакви параметри и ги препраща директно към друга функция, без да знае какви са те.
*   **Елегантно пазене на състояние чрез Closures:** Позволява избягване на глобални променливи и излишни класове за прости броячи или фабрики за функции.

### 🔴 Недостатъци (Cons):
*   **Липса на Tail Call Optimization при рекурсия:** Дълбоката рекурсия в Python бързо удря тавана на стека и хвърля `RecursionError` (затова при големи дървета се предпочитат цикли със стек/опашка).
*   **Загуба на IntelliSense при `*args/**kwargs`:** Когато функция приема `**kwargs`, редакторът не може да ти подскаже какви точно имена на аргументи очаква тя.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Грешен ред на аргументите и рекурсия без дъно):
```python
# 🚨 ГРЕШКА 1: Грешна подредба на параметрите в дефиницията (хвърля SyntaxError!)
# Правилният ред е винаги: (позиционни, *args, именувани_с_дефолт, **kwargs)
# def bad_func(**kwargs, *args): -> SyntaxError: arguments cannot follow var-keyword argument

# 🚨 ГРЕШКА 2: Рекурсия без базово условие (Base Case) за спиране
def infinite_countdown(n):
    print(n)
    return infinite_countdown(n - 1)  # Гърми с RecursionError: maximum recursion depth exceeded!
```
*   **Как да се избегне:** Винаги спазвай строгия ред `(normal, *args, default=1, **kwargs)`. Всяка рекурсивна функция трябва да започва с `if` проверка за дъно (Base Case), която връща резултат без ново рекурсивно извикване.

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic стандарт с `*args`, `**kwargs` и рекурсия):
```python
# 1. Универсална функция за логване на събития с *args и **kwargs
def log_audit_event(event_type: str, *tags: str, **metadata) -> None:
    print(f"[СЪБИТИЕ]: {event_type}")
    if tags:
        print(f"  Етикети (tuple): {tags}")
    if metadata:
        for key, val in metadata.items():
            print(f"  Метаданни -> {key}: {val}")

log_audit_event("USER_LOGIN", "Security", "Auth", user_id=105, ip="10.0.0.1")

# 2. Защитена рекурсия с ясно базово условие (Факториел)
def factorial(n: int) -> int:
    if n <= 1:  # Базово условие (Base Case) - спира рекурсията
        return 1
    return n * factorial(n - 1)

print(f"Факториел от 5: {factorial(5)}")
```
*   **Изход в конзолата:**
    ```text
    [СЪБИТИЕ]: USER_LOGIN
      Етикети (tuple): ('Security', 'Auth')
      Метаданни -> user_id: 105
      Метаданни -> ip: 10.0.0.1
    Факториел от 5: 120
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Какъв е скритият капан при създаване на списък от ламбда функции или Closures вътре в `for` цикъл (Late Binding Closures)?“*
*   **Уловката:** Ако напишеш `funcs = [lambda: i for i in range(3)]` и извикаш `funcs()`, очакваш резултат `0`, но получаваш **`2`**! И трите функции връщат `2`!
*   **Точен Senior отговор:** В Python затварянията са **късно обвързани (Late Binding)**. Вътрешната функция не записва стойността на `i` в момента на създаването си, а пази препратка към самата променлива `i` в обхвата на цикъла. Когато цикълът приключи, `i` е останало на последната си стойност (`2`), и когато извикаш функциите по-късно, всички четат `2`.
    *   **Правилен фикс:** Подава се `i` като аргумент по подразбиране в самата ламбда, което принуждава Python да го оцени веднага: `funcs = [lambda i=i: i for i in range(3)]`.
