## 1. ИНТЕРВЮ ВЪПРОСНИК (TOP 6 ВЪПРОСА С ТОЧНИ SENIOR ОТГОВОРИ)

1. **Въпрос:** *„Какво е **GIL (Global Interpreter Lock)** в CPython и кога използваме `threading`, кога `asyncio` и кога `multiprocessing`?“*
   * **Отговор:** GIL е заключване в стандартния CPython интерпретатор, което позволява на **само една нишка** да изпълнява Python байткод в даден момент.
     * **`asyncio` (Single-threaded Event Loop):** Най-добър за висока конкурентност при **I/O-bound** задачи (хиляди HTTP заявки, заявки към PostgreSQL, Redis).
     * **`threading`:** Подходящ за по-стари блокиращи I/O библиотеки (защото по време на мрежово/дисково чакане GIL се освобождава).
     * **`multiprocessing`:** Задължителен за **CPU-bound** задачи (тежки математически изчисления, обработка на изображения, ML), тъй като вдига отделни процеси на ОС, всеки със собствен Python интерпретатор и собствен GIL.

2. **Въпрос:** *„Каква е разликата между **`__new__`** и **`__init__`** в жизнения цикъл на Python обекта?“*
   * **Отговор:** `__new__(cls, ...)` е **конструкторът**, който реално заделя памет и създава празния обект (използва се при Singleton или наследяване на неизменяеми типове като `str`/`tuple`). `__init__(self, ...)` е **инициализаторът**, който получава вече създадения обект `self` и попълва неговите атрибути.

3. **Въпрос:** *„Как работи **MRO (Method Resolution Order)** при множествено наследяване в Python?“*
   * **Отговор:** Python използва алгоритъма **C3 Linearization**, който гарантира, че подкласовете се проверяват преди базовите класове и се спазва редът отляво надясно в декларацията `class Child(MixinA, BaseB):`. Редът може да се види по всяко време чрез `Child.__mro__`.

4. **Въпрос:** *„Каква е разликата между **`@staticmethod`** и **`@classmethod`**?“*
   * **Отговор:** `@staticmethod` е обикновена функция, поставена в пространството на имената на класа (не получава нито `self`, нито `cls`). `@classmethod` получава самия клас като първи аргумент **`cls`** и е идеален за **алтернативни конструктори / Factory методи** (напр. `User.from_json(raw_str)`).

5. **Въпрос:** *„Как работи управлението на паметта и Garbage Collector-ът в Python?“*
   * **Отговор:** Основният механизъм е **Reference Counting** (всеки обект пази брояч колко референции сочат към него — щом стане `0`, паметта се освобождава мигновено). За цикли от референции (`a.ref = b` и `b.ref = a`) се грижи допълнителен **Generational Garbage Collector** (`gc` модул).

6. **Въпрос:** *„Каква е разликата между Генератор (`yield`) и Итератор (`__iter__` / `__next__`)?“*
   * **Отговор:** Всеки генератор е итератор, но се пише много по-лесно с ключовата дума `yield` — при всяко извикване на `next()` функцията изпълнява кода до следващия `yield`, замразява локалните си променливи в паметта и връща стойността.

## 2. СКРИТИ КАПАНИ В PYTHON (`IS` СРЕЩУ `==`, SHALLOW VS DEEP COPY, LATE BINDING CLOSURES)

1. **Капанът на `is` срещу `==` (Идентичност в паметта срещу Стойност):**
   * `==` сравнява **стойностите** (вика `__eq__`). `is` сравнява **адресите в паметта (`id(a) == id(b)`)**.
   * CPython кешира малките цели числа от `-5` до `256`, затова `256 is 256` връща `True`, но `1000 is 1000` (при променливи в различни редове) връща `False`!
   * **Правило:** Използвай `is` **единствено** за `None`, `True` и `False` (`if user is None:`). За всичко останало ползвай `==`!
   
2. **Капанът на Shallow Copy (`list.copy()` / `[:]`) при вложени колекции:**
   * `b = a.copy()` копира само външния списък, но вложените списъци/речници вътре остават **споделени референции**!
   * **Решение:** За пълно независимо копие на сложни структури използвай `import copy; b = copy.deepcopy(a)`.

3. **Капанът на Late Binding Closures в цикъл:**
   * Ако създадеш списък от ламбди `[lambda: i for i in range(3)]`, и трите функции ще върнат `2` (последната стойност на `i`), защото променливата `i` се търси чак при извикването им.
   * **Решение:** Замрази текущата стойност като аргумент по подразбиране: `[lambda i=i: i for i in range(3)]`.

## 3. DEBUGGING & PROFILING TECHNIQUES В PYTHON (`BREAKPOINT()`, VS CODE, `CPROFILE`, `TRACEMALLOC`)

*   **Вграденият дебъгер `breakpoint()` (Python 3.7+):**
    * Постави `breakpoint()` на произволен ред в кода — Python автоматично стартира интерактивния дебъгер **`pdb`** (или закача VS Code дебъгера).
    * **Основни команди в `pdb` конзолата:**
      * `n` (*next*) — изпълнява следващия ред (без да влиза във функции).
      * `s` (*step*) — влиза вътре в извиканата функция.
      * `c` (*continue*) — продължава изпълнението до следващия Breakpoint.
      * `p expr` (*print*) — принтира стойността на произволен израз или променлива.
      * `ll` (*longlist*) — показва целия изходен код на текущата функция.
*   **Бърз дебъг принт с `f"{var=}"` (Python 3.8+):**
    * Вместо `print("user_id:", user_id)`, пиши **`print(f"{user_id=}, {len(items)=}")`** — автоматично принтира и името на променливата, и нейната стойност!
*   **Откриване на бавни функции с `cProfile`:**
    * Стартирай скрипта с `python -m cProfile -s tottime app.py`, за да видиш коя точно функция изяжда най-много CPU време.
*   **Откриване на утечки на RAM с `tracemalloc`:**
    ```python
    import tracemalloc
    tracemalloc.start()
    # ... изпълнение на тежка функция ...
    current, peak = tracemalloc.get_traced_memory()
    print(f"Текуща RAM: {current / 1024:.1f} KB | Пикова RAM: {peak / 1024:.1f} KB")
    tracemalloc.stop()
    ```
