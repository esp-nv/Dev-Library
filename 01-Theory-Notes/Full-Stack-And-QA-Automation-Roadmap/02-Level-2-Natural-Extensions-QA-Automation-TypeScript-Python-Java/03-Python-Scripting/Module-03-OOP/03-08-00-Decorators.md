## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Подарък в опаковъчна хартия:** Декораторът е просто **опаковъчна хартия (Wrapper)** около твоята функция. Когато сложиш `@my_decorator` над `def say_hi():`, Python прави следното зад кулисите: `say_hi = my_decorator(say_hi)`. Така всеки път, когато някой извика `say_hi()`, той всъщност извиква опаковката, която прави нещо преди и/или след оригиналната функция.
*   **Защо слагаме `@wraps(func)`:** Когато обвиеш подарък в хартия, етикетът с името отдолу се скрива. Без `@wraps`, функцията `say_hi.__name__` започва да се казва `"wrapper"` вместо `"say_hi"`. Декораторът `@wraps` прехвърля оригиналното име и документация върху опаковката.

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Концепция | Python 3.x | C# (.NET) | JavaScript / TypeScript |
| :--- | :--- | :--- | :--- |
| **Синтаксис** | `@decorator` над `def` или `class` | `[Attribute]` (напр. `[Authorize]`) | `@decorator` (в TypeScript и ES stage 3) |
| **Механизъм** | Динамично обвиване на функции (Runtime) | Метаданни + Reflection / Middleware | Обвиване на дескриптори и класове |
| **Запазване на име** | `@functools.wraps(func)` | Името на метода не се променя | Името на метода се запазва |
| **Множество декоратори** | Подреждат се един над друг (отдолу нагоре) | `[Attr1] [Attr2]` | `@Dec1 @Dec2` |

## 4. ПЛЮСОВЕ И МИНУСИ НА ДЕКОРАТОРИТЕ В PYTHON

### 🟢 Предимства (Pros):
*   **Перфектно Аспектно-ориентирано програмиране (AOP):** Изнасяш логване, измерване на време, кеширане (`@lru_cache`) и проверка за права на достъп извън бизнес логиката.
*   **Кристален и преизползваем код:** Написваш декоратора веднъж и го слагаш с един ред `@` над 50 различни функции.

### 🔴 Недостатъци (Cons):
*   **Сложност при декоратори с аргументи:** Изискват 3 нива на вложени функции (фабрика ➔ декоратор ➔ wrapper), което затруднява четенето.
*   **Усложнено дебъгване:** В Stack Trace при грешка се появяват допълнителните нива на `wrapper` функциите.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Забравен `return` на резултата и липсващи `*args, **kwargs`):
```python
def bad_logger(func):
    # 🚨 ГРЕШКА 1: wrapper() не приема *args, **kwargs -> гърми ако функцията има аргументи!
    def wrapper():
        print("Извикване на функция...")
        # 🚨 ГРЕШКА 2: Липсва 'return' пред func() -> оригиналният резултат се губи и става None!
        func()
    return wrapper

@bad_logger
def get_secret_code():
    return 9999

code = get_secret_code()  # Извежда текста, но 'code' е None вместо 9999!
```
*   **Как да се избегне:** Вътрешният `wrapper` **винаги** трябва да приема `(*args, **kwargs)`, да има декоратор `@wraps(func)` и да връща резултата с `return func(*args, **kwargs)`.

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic стандарт с `@wraps` и измерване на време):
```python
import time
from functools import wraps

def measure_execution_time(func):
    @wraps(func)  # Запазва оригиналното име и docstring на функцията
    def wrapper(*args, **kwargs):
        start_time = time.perf_counter()
        
        result = func(*args, **kwargs)  # Изпълнява оригинала и пази резултата
        
        elapsed = (time.perf_counter() - start_time) * 1000
        print(f"[⏱️ ОДИТ] Функция '{func.__name__}' завърши за {elapsed:.2f} ms.")
        return result  # Връща оригиналния резултат!
    return wrapper

@measure_execution_time
def calculate_heavy_sum(n: int) -> int:
    return sum(range(n))

answer = calculate_heavy_sum(1_000_000)
print(f"Резултат: {answer}")
```
*   **Изход в конзолата:**
    ```text
    [⏱️ ОДИТ] Функция 'calculate_heavy_sum' завърши за 18.45 ms.
    Резултат: 499999500000
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Ако поставим два декоратора един над друг (`@dec_A` най-отгоре и `@dec_B` точно над `def my_func():`), в какъв ред се прилагат и в какъв ред се изпълняват при викане на функцията?“*
*   **Уловката:** Кандидатите често бъркат реда на обвиване с реда на изпълнение.
*   **Точен Senior отговор:** Синтаксисът `@dec_A` над `@dec_B` над `def my_func()` е абсолютно еквивалентен на математическата композиция: **`my_func = dec_A(dec_B(my_func))`**.
    1.  **Ред на обвиване (при зареждане на модула):** Първо вътрешният `@dec_B` обвива `my_func`, а след това външният `@dec_A` обвива резултата (**отдолу нагоре**).
    2.  **Ред на изпълнение (при викане на `my_func()`):** Първо тръгва кодът на външния `@dec_A` (преди `func()`), после влиза във вътрешния `@dec_B`, изпълнява самата `my_func()`, и накрая излиза обратно през `@dec_B` и `@dec_A` (**като луковица — отвън навътре и после обратно навън**).
