## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **`self` е точно като `this` в C# и JS:** Единствената разлика е, че в C# думата `this` е скрита и автоматична, докато в Python трябва **изрично да напишеш `self` като първи параметър** на всеки метод в класа, за да знае обектът за коя точно инстанция става дума.
*   **Магическите методи (`__dunder__`):** Двойните долни черти отпред и отзад (напр. `__init__`, `__str__`) се наричат **Dunder** (*Double Under*). Това са вградените куки на Python, чрез които казваш на езика как да създаде обекта, как да го принтира или как да събере два твои обекта със знака `+`.

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| ООП Концепция | Python 3.x | C# (.NET) | JavaScript (ES6+) |
| :--- | :--- | :--- | :--- |
| **Конструктор** | `def __init__(self, name):` | `public User(string name)` | `constructor(name)` |
| **Текуща инстанция** | `self.name` (пише се изрично) | `this.name` (по подразбиране) | `this.name` (динамичен контекст) |
| **Наследяване** | `class Admin(User):` (множествено!) | `class Admin : User` (само 1 клас) | `class Admin extends User` (само 1) |
| **Частно поле (Private)** | `self.__secret` (Name Mangling) | `private string _secret;` (строго) | `#secret` (нативно частно поле) |
| **Интерфейси** | Няма `interface` (ползва се `ABC` или `Protocol`) | `interface IUser` (строг договор) | Няма в JS (само в TypeScript) |

## 4. ПЛЮСОВЕ И МИНУСИ НА ООП В PYTHON

### 🟢 Предимства (Pros):
*   **Поддръжка на Множествено наследяване (Multiple Inheritance):** Един клас може да наследи функционалност от няколко базови класа едновременно (Mixins патерн), което C# и Java забраняват за класове.
*   **Duck Typing и гъвкавост:** Не ти трябват десетки интерфейси, за да постигнеш полиморфизъм — стига два класа да имат метод `.save()`, те са взаимозаменяеми.

### 🔴 Недостатъци (Cons):
*   **Няма истинска, непробиваема капсулация:** В Python важи философията *"We are all consenting adults here"* — дори частните полета с `__` могат да бъдат достъпени отвън, ако програмистът умишлено напише специалното им преименувано име.
*   **Динамично добавяне на полета по време на работа:** По подразбиране можеш случайно да допишеш `user.naem = "Иван"` (с правописна грешка) и Python няма да хвърли грешка, а просто ще създаде ново поле на този конкретен обект!

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Забравен `self` и споделен списък на ниво клас):
```python
class BadTeam:
    # 🚨 ГРЕШКА 1: Списък, дефиниран директно в класа (Class Attribute), а не в __init__!
    # ВСИЧКИ създадени отбори ще споделят ЕДИН И СЪЩ списък в паметта!
    members = []

    # 🚨 ГРЕШКА 2: Липсва 'self' като първи параметър на метода!
    def add_member(name):
        BadTeam.members.append(name)  # Гърми с TypeError при извикване през инстанция!
```
*   **Как да се избегне:** Променливите, които са уникални за всеки обект (като списък с членове, име, баланс), **винаги** се дефинират вътре в `__init__` чрез `self.members = []`.

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic ООП стандарт):
```python
class EngineeringTeam:
    def __init__(self, team_name: str):
        # Атрибути на конкретната инстанция (Instance Attributes)
        self.team_name = team_name
        self.members: list[str] = []

    def add_member(self, member_name: str) -> None:
        self.members.append(member_name)

    # Магически метод за красиво принтиране на обекта (еквивалент на ToString() в C#)
    def __str__(self) -> str:
        return f"Екип '{self.team_name}' | Членове: {', '.join(self.members)}"

backend_team = EngineeringTeam("Core API")
backend_team.add_member("Елизабет")
backend_team.add_member("Георги")

print(backend_team)
```
*   **Изход в конзолата:**
    ```text
    Екип 'Core API' | Членове: Елизабет, Георги
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Каква е разликата между специалните методи `__new__` и `__init__` в Python и кой от тях всъщност е истинският конструктор?“*
*   **Уловката:** 90% от кандидатите отговарят, че `__init__` е конструкторът.
*   **Точен Senior отговор:** Технически погледнато, **`__new__` е истинският конструктор**, а **`__init__` е инициализатор**:
    1.  **`__new__(cls, ...)`** се извиква **първи** — той заделя реална оперативна памет (RAM), създава празния обект и го връща.
    2.  **`__init__(self, ...)`** се извиква **веднага след това**, приема вече създадения обект като `self` и просто пълни началните му стойности (затова `__init__` никога не трябва да има `return`). Методът `__new__` се пренаписва при създаване на **Singleton** патерн или наследяване от неизменяеми типове като `int` и `str`.
