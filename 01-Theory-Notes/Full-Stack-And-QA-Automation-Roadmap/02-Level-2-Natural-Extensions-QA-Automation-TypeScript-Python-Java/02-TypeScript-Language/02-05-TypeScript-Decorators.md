# 02-05. TypeScript Декоратори: Метапрограмиране и Аспекти

**Модул 02:** TypeScript | **Лекционна тема 05:** Метапрограмиране, експериментални декоратори на класове и методи, прихващане на софтуерни нишки (Interception).

---

## 1. АРХИТЕКТУРЕН АНАЛИЗ & ПРЕДИМСТВА И НЕДОСТАТЪЦИ

Декораторите (**Decorators**) са специален вид декларации, които могат да бъдат прикачени към декларация на клас, метод, аксесор, свойство или параметър. Те се използват за метапрограмиране и имплементиране на **Аспектно-ориентирано програмиране (Aspect-Oriented Programming - AOP)**, като позволяват инжектирането на странична логика (логване, сигурност, валидация) без директна модификация на оригиналния софтуерен код, силно наподобявайки атрибутите (`[Attributes]`) в C# средите.

### 🟢 Предимства (Pros):
*   **Чисто разделение на отговорностите (Separation of Concerns):** Извлича повтаряща се инфраструктурна логика (напр. одит контроли) извън бизнес методите.
*   **Декларативен и чист синтаксис:** Налагането на мета-логика става елегантно през символа `@` директно над компонента.

### 🔴 Недостатъци (Cons):
*   **Експериментална софтуерна спецификация:** Изисква изричното активиране на флага `"experimentalDecorators": true` във файла `tsconfig.json`, тъй като стандартът преминава през дълга еволюция спрямо ECMAScript спецификациите.
*   **Сложно дебъгване под товар:** Тъй като декораторите променят поведението на обектите в паметта динамично по време на Runtime, откриването на грешки в стека изисква дълбоко разбиране на рефлексията.

---

## 2. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Анти-патърн с ръчно набиване на лог нишки във всеки метод):
```typescript
class AccountService {
    public updateBalance(amount: number) {
        // 🚨 ДЕФЕКТ: Силно дублиране на код и размиване на бизнес логиката с логове!
        console.log($"[ОДИТ ТРАФИК] Стартиране на метод updateBalance с параметър {amount}");
        
        // Реална бизнес операция...
        console.log("[ОДИТ ТРАФИК] КРАЙ: Успешно изпълнение на операцията.");
    }
}
```

### 🟢 ПРАВИЛЕН КОД (Строг TypeScript стандарт с Аспектен Декоратор):
```typescript
// 1. Дефиниране на фабрика за декоратор над методи (Method Interceptor)
function LogTransaction() {
    return function (
        target: any,
        propertyKey: string,
        descriptor: PropertyDescriptor
    ) {
        // Капсулиране на оригиналния C# / TS метод от паметта
        const originalMethod = descriptor.value;

        // Пренаписване на софтуерната нишка с аспектен прихващач
        descriptor.value = function (...args: any[]) {
            console.log(`[🚀 REDIS AUDIT LOG] Извикване на метод: '${propertyKey}' с аргументи: ${JSON.stringify(args)}`);
            
            // Изпълнение на оригиналната бизнес операция
            const result = originalMethod.apply(this, args);
            
            console.log(`[✅ REDIS AUDIT LOG] Успешен край на трансакцията за '${propertyKey}'.`);
            return result;
        };

        return descriptor;
    };
}

// 2. Прилагане на мета-декоратора в бизнес логиката
class FinancialController {
    private cachedBalance: number = 1500;

    @LogTransaction() // 🟢 Аспектно инжектиране на лог контрол без пипане на тялото на метода
    public executeTransfer(accountDto: string, amount: number): void {
        this.cachedBalance -= amount;
        console.log(`[Бизнес Логика] Трансферът от ${amount} лв. към ${accountDto} е обработен.`);
    }
}

// 3. Извикване и паметен одит на рефлексията
const coreProcessor = new FinancialController();
coreProcessor.executeTransfer("BG_AUTH_8912739", 350);
```
*   **Коментар към кода:** Декораторът `@LogTransaction()` хваща дескриптора на метода `executeTransfer` преди неговото изпълнение в браузъра, прочита подадените аргументи и затваря трансакцията чисто, запазвайки бизнес метода кристално чист от инфраструктурен спам.
*   **Очакван компилационен изход в конзолата:**
    ```text
    [🚀 REDIS AUDIT LOG] Извикване на метод: 'executeTransfer' с аргументи: ["BG_AUTH_8912739",350]
    [Бизнес Логика] Трасферът от 350 лв. към BG_AUTH_8912739 е обработен.
    [✅ REDIS AUDIT LOG] Успешен край на трансакцията за 'executeTransfer'.
    ```
