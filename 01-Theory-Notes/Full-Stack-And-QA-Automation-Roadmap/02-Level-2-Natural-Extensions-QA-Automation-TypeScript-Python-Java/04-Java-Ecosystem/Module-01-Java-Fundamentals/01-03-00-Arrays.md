## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Кутия за яйца с фиксиран брой гнезда:** Когато създадеш `int[] nums = new int[5];`, JVM заделя точно 5 съседни клетки в паметта. Не можеш да добавиш 6-то яйце и не можеш да извадиш гнездо — размерът на масива е **неизменяем (`final` поле `.length`)** през целия му живот.
*   **Стойности по подразбиране (Default Values):** За разлика от локалните променливи, клетките на нов масив **никога не са неинициализирани**:
    *   Числови масиви (`int[]`, `double[]`) ➔ пълнят се автоматично с **`0`** / **`0.0`**.
    *   Булеви масиви (`boolean[]`) ➔ пълнят се с **`false`**.
    *   Обектни масиви (`String[]`, `Integer[]`) ➔ пълнят се с **`null`**.

## 2. КАК ИЗГЛЕЖДА ЕДИН МАСИВ В RAM ПАМЕТТА (STACK + HEAP БЛОК-СХЕМА)

Всички масиви в Java са **обекти** и живеят в **Heap паметта**, дори когато пазят примитиви `int`:

```text
STACK ПАМЕТ                           HEAP ПАМЕТ (Непрекъснат блок памет)
┌───────────────────────┐             ┌──────────────────────────────────────────────┐
│ int[] arr             │             │ Обект int[] (length = 4)                     │
│ (Адрес: 0x7F10) ──────┼────────────►│ Индекс:  [0]     [1]     [2]     [3]         │
└───────────────────────┘             │ Стойност: 10  │   20  │   30  │   40         │
                                      │ Адрес:  0x7F10  0x7F14  0x7F18  0x7F1C (+4B) │
                                      └──────────────────────────────────────────────┘
```
*Формула за мигновен достъп $O(1)$:* `Адрес на arr[i] = Начален_Адрес + (i × Размер_на_типа_в_байтове)`. Затова `arr[0]` и `arr[999999]` се четат за абсолютно еднакво време!

## 3. СРАВНИТЕЛНА ТАБЛИЦА: JAVA ARRAYS СРЕЩУ C#, PYTHON И JAVASCRIPT

| Операция / Концепция | ☕ Java 21+ (`T[]`) | 🟣 C# 12+ (`T[]`) | 🐍 Python 3.x (`list`) | 🟡 JavaScript (`Array`) |
| :--- | :--- | :--- | :--- | :--- |
| **Декларация с размер** | `int[] arr = new int[5];` | `int[] arr = new int[5];` | `arr = [0] * 5` | `const arr = new Array(5).fill(0);` |
| **Инициализация със стойности** | `int[] arr = {1, 2, 3};` | `int[] arr = [1, 2, 3];` | `arr = [1, 2, 3]` | `const arr = [1, 2, 3];` |
| **Дължина на масива** | `arr.length` (без скоби!) | `arr.Length` (главно L) | `len(arr)` | `arr.length` |
| **Последният елемент** | `arr[arr.length - 1]` | `arr[^1]` (Index from end) | `arr[-1]` | `arr.at(-1)` |
| **Печат на масив в конзола** | `Arrays.toString(arr)` | `string.Join(", ", arr)` | `print(arr)` | `console.log(arr)` |
| **Сравнение на съдържание** | `Arrays.equals(a, b)` | `a.SequenceEqual(b)` | `a == b` | `JSON.stringify(a) === ...` |
| **Копиране на масив** | `Arrays.copyOf(arr, arr.length)` | `(int[])arr.Clone()` / `arr[..]` | `arr.copy()` / `arr[:]` | `[...arr]` |
| **Грешка при невалиден индекс** | `ArrayIndexOutOfBoundsException` | `IndexOutOfRangeException` | `IndexError` | Връща `undefined` (не гърми!) |

## 4. ПЛЮСОВЕ И МИНУСИ НА СТАТИЧНИТЕ МАСИВИ В JAVA

### 🟢 Предимства (Pros):
*   **Максимална скорост и нулев overhead:** При `int[]` стойностите лежат директно една до друга в кеша на процесора (CPU Cache Friendly), без Boxing и без допълнителни обекти в паметта.
*   **Типова безопасност:** Компилаторът гарантира, че в `int[]` никога няма да попадне `String` или `null`.

### 🔴 Недостатъци (Cons):
*   **Фиксиран размер:** Не можеш да добавяш или триеш елементи динамично — за променлива дължина се използва `ArrayList<T>`.
*   **Скрит капан с `toString()`:** Ако напишеш `System.out.println(arr);` директно върху масив, Java **няма да принтира числата**, а странния адрес в паметта от вида **`[I@4617c264`**!

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД (`==` ВЪРХУ МАСИВИ И РЕФЕРЕНТНО КОПИРАНЕ)

### ❌ ГРЕШЕН КОД (Копиране с `=` и сравнение с `==` или `.equals()` върху масиви):
```java
int[] a = {1, 2, 3};
int[] b = {1, 2, 3};

// 🚨 ГРЕШКА 1: И '==' и 'a.equals(b)' върху масиви сравняват АДРЕСИТЕ в паметта, а не числата!
System.out.println(a == b);        // false!
System.out.println(a.equals(b));   // пак false! (Масивите не пренаписват Object.equals)

// 🚨 ГРЕШКА 2: Присвояване с '=' не копира масива, а създава втори псевдоним към същата памет!
int[] copy = a;
copy[0] = 999; // Променя и оригиналния масив 'a[0]' на 999!
```
*   **Как да се избегне:** За сравнение на съдържанието на масиви **винаги** ползвай **`Arrays.equals(a, b)`** (или `Arrays.deepEquals(m1, m2)` за 2D матрици). За истинско копие ползвай **`Arrays.copyOf(a, a.length)`** или `a.clone()`.

### 🟢 ПРАВИЛЕН КОД (Чисти операции с масиви чрез помощния клас `java.util.Arrays`):
```java
import java.util.Arrays;

public class CleanArraysDemo {
    public static void main(String[] args) {
        int[] original = {30, 10, 20};
        int[] copy = Arrays.copyOf(original, original.length);

        System.out.println(Arrays.equals(original, copy)); // true

        Arrays.sort(copy); // Сортира само копието: [10, 20, 30]
        System.out.println("Оригинал: " + Arrays.toString(original));
        System.out.println("Сортирано копие: " + Arrays.toString(copy));
    }
}
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Каква е разликата между многомерните масиви в Java (`int[][] matrix`) и правоъгълните многомерни масиви в C# (`int[,] matrix`)?“*
*   **Уловката:** C# разработчиците често пренасят навиците си от `int[,]` директно в Java и остават изненадани от поведението на редовете!
*   **Точен Senior отговор:** В Java **няма истински правоъгълни матрици** (като `int[,]` в C#). В Java `int[][]` всъщност е **Jagged Array (масив от референции към отделни едномерни масиви)** — точно като `int[][]` в C#! Това означава две важни неща:
    1.  Всеки ред в `int[][]` може да има **различна дължина** (напр. ред 0 да е с 3 елемента, а ред 1 с 10 елемента).
    2.  За принтиране на 2D масив в конзолата `Arrays.toString(matrix)` ще изведе адресите на редовете (`[[I@..., [I@...]`), затова за многомерни масиви **задължително** се използва **`Arrays.deepToString(matrix)`**!
