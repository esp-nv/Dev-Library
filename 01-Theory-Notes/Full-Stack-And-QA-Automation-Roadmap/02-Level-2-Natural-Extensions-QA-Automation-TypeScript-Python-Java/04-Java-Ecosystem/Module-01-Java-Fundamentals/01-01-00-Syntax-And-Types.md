## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Осемте примитивни типа в Java (Няма `decimal`, няма `uint`!):**
    *   **4 Целочислени (всички са със знак +/-):** `byte` (1B), `short` (2B), `int` (4B), `long` (8B — завършва с `100L`).
    *   **2 Дробни (Floating-Point):** `float` (4B — завършва с `3.14f`), `double` (8B — стандартът). *(За пари в банки ползваме класа **`BigDecimal`**, аналог на C# `decimal`!)*.
    *   **1 Символен:** `char` (2B UTF-16 в единични кавички `'A'`).
    *   **1 Булев:** `boolean` (в Java се пише изцяло **`boolean`**, а не `bool` като в C#!).
*   **Boxing и Unboxing (Опаковане на подарък):**
    *   **Autoboxing:** Слагаш лекия примитив `int` в тежка картонена кутия `Integer`, за да можеш да го пъхнеш в `List<Integer>`.
    *   **Unboxing:** Вадиш числото от кутията (`Integer` ➔ `int`). Внимание: ако кутията е празна (`null`), ваденето взривява програмата с `NullPointerException`!

## 2. STACK СРЕЩУ HEAP: ПРИМИТИВИ СРЕЩУ WRAPPER КЛАСОВЕ (БЛОК-СХЕМА)

```text
STACK ПАМЕТ (Бърза, фиксирана)               HEAP ПАМЕТ (Динамична, управлявана от GC)
┌─────────────────────────────┐              ┌───────────────────────────────────────┐
│ int a = 42;                 │              │                                       │
│ (Стойността 42 е тук!)      │              │                                       │
├─────────────────────────────┤              │   ┌───────────────────────────────┐   │
│ Integer b = 42; ────────────┼──────────────┼─► │ Обект Integer (Header + 42)   │   │
│ (Пази само 64-bit адрес!)   │              │   │ (Заема ~16 Bytes вместо 4B!)   │   │
└─────────────────────────────┘              │   └───────────────────────────────┘   │
                                             └───────────────────────────────────────┘
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: JAVA ТИПОВЕ & МАСИВИ СРЕЩУ C# И PYTHON

| Концепция | Java 21+ | C# 12+ (.NET) | Python 3.x |
| :--- | :--- | :--- | :--- |
| **Булев тип** | `boolean isReady = true;` | `bool isReady = true;` | `is_ready = True` |
| **Тип за пари (Точна дроб)** | `BigDecimal price = new BigDecimal("19.99");` | `decimal price = 19.99m;` | `Decimal("19.99")` |
| **Беззнакови числа (`uint`)** | **Няма** (всички са signed) | `uint`, `ulong`, `byte` (0..255) | Безкрайни цели (`int`) |
| **Локално извеждане на тип** | `var count = 10;` (от Java 10+) | `var count = 10;` | Динамично (`count = 10`) |
| **Константа** | `final int MAX = 100;` | `const int Max = 100;` / `readonly` | Конвенция `MAX = 100` |
| **Дължина на масив** | `arr.length` (поле без скоби) | `arr.Length` (Property) | `len(arr)` (функция) |
| **Копиране / Сортиране на масив** | `Arrays.copyOf()` / `Arrays.sort()` | `Array.Copy()` / `Array.Sort()` | `arr.copy()` / `arr.sort()` |

## 4. ПЛЮСОВЕ И МИНУСИ НА РАЗДЕЛЕНИЕТО ПРИМИТИВИ / ОБЕКТИ В JAVA

### 🟢 Предимства (Pros):
*   **Светкавична математика върху масиви от примитиви:** Един `int[]` с 1 000 000 елемента заема точно 4 MB непрекъсната RAM памет без обектни заглавия (Object Headers), което позволява на процесора да го обработва с максимална скорост.

### 🔴 Недостатъци (Cons):
*   **Двойна система от типове:** Принуден си да помниш два варианта за всеки тип (`int` / `Integer`, `double` / `Double`, `char` / `Character`), защото колекциите в Java (`List`, `Map`, `Set`) не приемат примитиви.
*   **Скрито забавяне при Autoboxing в цикли:** Ако напишеш `Long sum = 0L;` (с главно `L`!) и въртиш цикъл `sum += i;` 10 милиона пъти, Java ще създаде и изхвърли 10 милиона нови `Long` обекта в Heap паметта!

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД (`SCANNER` БУФЕР И `NULLPOINTEREXCEPTION`)

### ❌ ГРЕШЕН КОД (Капанът `nextInt()` преди `nextLine()` и срив при `null` Unboxing):
```java
Scanner scanner = new Scanner(System.in);
int age = scanner.nextInt();
// 🚨 ГРЕШКА 1: nextInt() чете само числото, но оставя символа за нов ред '\n' в буфера!
// Следващият nextLine() веднага поглъща празния '\n' и прескача въвеждането на името!
String fullName = scanner.nextLine(); 

// 🚨 ГРЕШКА 2: Скрит NullPointerException при Unboxing!
Integer bonus = null;
int total = 100 + bonus; // JVM се опитва да извика bonus.intValue() върху null -> CRASH!
```
*   **Как да се избегне:** Когато четеш смесени типове от конзолата, **винаги чети с `scanner.nextLine()`** и парсвай с `Integer.parseInt(...)` / `Double.parseDouble(...)` (точно както `int.Parse(Console.ReadLine())` в C#!).

### 🟢 ПРАВИЛЕН КОД (Чисто парсване от конзолата и защита от `null`):
```java
import java.util.Scanner;

public class CleanInputDemo {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        // Винаги четем целия ред -> няма остатъчен '\n' в буфера!
        int age = Integer.parseInt(scanner.nextLine());
        String fullName = scanner.nextLine();

        Integer bonus = null;
        int safeBonus = (bonus != null) ? bonus : 0; // Безопасен Unboxing
        System.out.printf("Име: %s, Възраст: %d, Бонус: %d%n", fullName, age, safeBonus);
    }
}
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Какво е **Pass-by-Value (Предаване по стойност)** в Java и вярно ли е твърдението, че обектите в Java се предават по референция (Pass-by-Reference)?“*
*   **Уловката:** 80% от кандидатите отговарят: *„Примитивите се предават по стойност, а обектите по референция“*. **Това е грешно!**
*   **Точен Senior отговор:** **Java е 100% Pass-by-Value за абсолютно всичко — включително и за обектите!** Когато подадеш обект `user` на метод `changeUser(User u)`, Java копира **стойността на адреса (указателя)** в нова локална променлива `u`.
    *   Ако вътре в метода промениш състоянието на обекта (`u.setName("Ivan")`), промяната се вижда отвън, защото и двата указателя сочат към същия адрес в Heap-а.
    *   Но ако пренасочиш параметъра към нов обект (`u = new User("Maria")`), оригиналната променлива отвън **не се променя**, защото в Java няма ключова дума `ref` или `out` като в C#!
