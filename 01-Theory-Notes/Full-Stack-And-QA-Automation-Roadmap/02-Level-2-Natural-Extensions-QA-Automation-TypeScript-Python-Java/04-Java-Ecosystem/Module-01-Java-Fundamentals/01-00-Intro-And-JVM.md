## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Трите матрешки на Java (JDK ➔ JRE ➔ JVM):**
    *   **JVM (Java Virtual Machine):** Двигателят (аналог на **CLR** в C#), който чете `.class` байткода и го превежда на машинния език на Windows, Linux или macOS (*"Write Once, Run Anywhere"*).
    *   **JRE (Java Runtime Environment):** `JVM + Стандартните библиотеки` (нужното, за да **пускаш** готови Java програми).
    *   **JDK (Java Development Kit):** `JRE + Компилатор (javac) + Инструменти` (аналог на **.NET SDK** — нужното, за да **пишеш и компилираш** код).
*   **Именни конвенции в Java (C# PascalCase ➔ Java camelCase):**
    *   Класове и Интерфейси: `PascalCase` (като в C#: `UserService`).
    *   **Методи и променливи:** **`camelCase`** с малка първа буква (`calculateTotal()`, а не `CalculateTotal()` като в C#!).
    *   Пакети (Namespaces): изцяло с **малки букви** (`package bg.softuni.shop;`).

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: JAVA 21+ СРЕЩУ C# 12+ (.NET)

| Концепция | Java 21+ (JDK) | C# 12+ (.NET 8+) |
| :--- | :--- | :--- |
| **Виртуална машина** | **JVM** (Java Virtual Machine) | **CLR** (Common Language Runtime) |
| **Входна точка на програмата** | `public static void main(String[] args)` | `static void Main(string[] args)` |
| **Конзолен изход / вход** | `System.out.println()` / `Scanner` | `Console.WriteLine()` / `Console.ReadLine()` |
| **Пакети / Пространства** | `package com.app;` + `import java.util.*;` | `namespace App;` + `using System.Collections;` |
| **Build инструмент** | **Maven** (`pom.xml`) или **Gradle** | **MSBuild** / `dotnet CLI` (`.csproj`) |
| **Стойностни структури (`struct`)** | **Няма** (само 8 примитива + класове) | **Да** (`struct`, `record struct`) |
| **Properties (`get; set;`)** | **Няма** (пишат се методи `getName()`, `setName()` или Lombok) | **Вградени** (`public string Name { get; set; }`) |

## 4. ПЛЮСОВЕ И МИНУСИ НА JAVA ЕКОСИСТЕМАТА

### 🟢 Предимства (Pros):
*   **Огромна корпоративна стабилност и обратна съвместимост:** Код, написан на Java 8 преди 12 години, се компилира и работи без грешка на Java 21 днес.
*   **Най-зрялата бекенд екосистема в света:** Spring Boot, Hibernate, Apache Kafka и Elasticsearch са изградени върху JVM и са индустриален стандарт за банки, телекоми и големи облачни системи.

### 🔴 Недостатъци (Cons):
*   **По-многословен синтаксис (Boilerplate):** Липсата на C# Properties и претоварване на оператори (`==` за обекти) води до повече писане на `getters`/`setters` (често се решава с библиотеката **Lombok** или с модерни `record` класове).
*   **Type Erasure при Generics:** За разлика от C#, където `List<int>` пази типа си по време на изпълнение, в Java генериците се изтриват при компилация и не можеш да имаш `List<int>` (задължително ползваш Wrapper класа `List<Integer>`).

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД (СРАВНЕНИЕ НА НИЗОВЕ)

### ❌ ГРЕШЕН КОД (Капан №1 за C# разработчици в Java — операторът `==` върху `String`!):
```java
Scanner scanner = new Scanner(System.in);
String input = scanner.nextLine(); // Потребителят въвежда "admin"

// 🚨 ГРЕШКА: В Java операторът '==' върху обекти (вкл. String) сравнява АДРЕСИТЕ В ПАМЕТТА (References),
// а НЕ съдържанието на текста! Този if ще върне FALSE, дори текстът да е "admin"!
if (input == "admin") {
    System.out.println("Добре дошли!");
}
```
*   **Как да се избегне:** В Java **никога** не сравнявай `String`, `Integer` или какъвто и да е обект с `==`. **Винаги** използвай метода **`.equals()`** (най-безопасно с константата отпред: `"admin".equals(input)`, за да избегнеш `NullPointerException`, ако `input` е `null`!).

### 🟢 ПРАВИЛЕН КОД (Безопасно сравнение и стандартен шаблон на Java програма):
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        String input = scanner.nextLine();

        // Безопасен "Yoda condition" стил -> никога не гърми с NullPointerException!
        if ("admin".equals(input)) {
            System.out.println("Добре дошли в системата!");
        }
    }
}
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Как работи **String Pool** в Java и защо `Integer a = 100; Integer b = 100; (a == b)` връща `true`, докато `Integer x = 200; Integer y = 200; (x == y)` връща `false`?“*
*   **Уловката:** Това е класически въпрос на всяко Java техническо интервю!
*   **Точен Senior отговор:** 
    1.  **String Pool:** В Java стринговете са неизменяеми (`Immutable`). Когато напишеш `String s1 = "Java"; String s2 = "Java";`, JVM ги записва в специална зона в Heap паметта (**String Constant Pool**) и кара и двете променливи да сочат към един и същ адрес, за да пести RAM. Но `new String("Java")` принудително създава нов обект извън пула.
    2.  **Integer Cache (`-128` до `127`):** За да пести памет, JVM кешира предварително всички `Integer` обекти в диапазона от **`-128` до `127`**. Затова `100` сочи към един и същ кеширан обект (`a == b` е `true`), докато за `200` (извън диапазона) JVM създава два отделни обекта в паметта (`x == y` е `false`)! **Правило:** Винаги сравнявай обекти с `.equals()`.
