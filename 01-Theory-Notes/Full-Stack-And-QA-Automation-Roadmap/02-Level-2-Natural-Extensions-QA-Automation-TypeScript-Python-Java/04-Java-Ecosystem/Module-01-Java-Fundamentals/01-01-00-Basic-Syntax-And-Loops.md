## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Законът на точка и запетая (`;`):** Както в C#, всяка инструкция в Java задължително завършва с `;`, а блоковете код се ограждат с фигурни скоби `{ ... }`.
*   **Условието в `if` и `while` приема САМО `boolean`:** За разлика от Python (където `if 1:` или `if "abc":` минава за истина) и JavaScript (където има *Truthy/Falsy* стойности), в Java **`if (1)` е компилационна грешка**! Вътре в скобите винаги трябва да стои израз, връщащ `true` или `false` (напр. `if (count > 0)`).
*   **Правилото за `Scanner` (Четецът на конзолата):** В C# имаш готов статичен метод `Console.ReadLine()`, но в Java трябва първо да създадеш обект-четец: `Scanner scanner = new Scanner(System.in);`.

## 3. СРАВНИТЕЛНА ТАБЛИЦА: JAVA СРЕЩУ C#, PYTHON И JAVASCRIPT

| Конструкция / Действие | ☕ Java 21+ | 🟣 C# 12+ (.NET) | 🐍 Python 3.x | 🟡 JavaScript (ES6+) |
| :--- | :--- | :--- | :--- | :--- |
| **Печат на нов ред** | `System.out.println("Hi");` | `Console.WriteLine("Hi");` | `print("Hi")` | `console.log("Hi");` |
| **Форматиран печат** | `System.out.printf("%.2f", x);` | `Console.Write($"{x:F2}");` | `print(f"{x:.2f}")` | `console.log(x.toFixed(2));` |
| **Четене на ред текст** | `scanner.nextLine()` | `Console.ReadLine()` | `input()` | `readline` / `prompt()` |
| **Парсване към цяло число** | `Integer.parseInt(str)` | `int.Parse(str)` | `int(str)` | `parseInt(str, 10)` |
| **Сравнение на текст** | `"stop".equals(cmd)` | `cmd == "stop"` | `cmd == "stop"` | `cmd === "stop"` |
| **Стандартен `for` цикъл** | `for (int i = 0; i < n; i++)` | `for (int i = 0; i < n; i++)` | `for i in range(n):` | `for (let i = 0; i < n; i++)` |
| **Обхождане (`for-each`)** | `for (var item : list)` | `foreach (var item in list)` | `for item in list:` | `for (const item of list)` |
| **Модерен `switch`** | `switch (x) { case 1 -> "A"; }` | `x switch { 1 => "A", _ => "" }` | `match x: case 1: ...` | `switch (x) { case 1: ... }` |

## 4. ПЛЮСОВЕ И МИНУСИ НА СИНТАКСИСА В МОДЕРНА JAVA 21+

### 🟢 Предимства (Pros):
*   **Модерни Switch Expressions (от Java 14+):** Новият `switch` със стрелка `->` връща директно стойност, не изисква `break` и компилаторът проверява дали си покрил всички възможни случаи.
*   **Строга проверка по време на компилация:** Грешки като `if (x = 5)` (присвояване вместо сравнение `==`) са напълно невъзможни в Java, защото компилаторът ги спира веднага.

### 🔴 Недостатъци (Cons):
*   **Тромав конзолен вход със `Scanner`:** За разлика от Python `input()` и C# `Console.ReadLine()`, в Java четенето на числа изисква или обгръщане в `Integer.parseInt(scanner.nextLine())`, или внимателно чистене на буфера.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД (`SCANNER` БУФЕР И СРАВНЕНИЕ НА НИЗОВЕ)

### ❌ ГРЕШЕН КОД (Капанът с `==` върху `String` и смесване на `nextDouble()` с `nextLine()`):
```java
Scanner scanner = new Scanner(System.in);
double budget = scanner.nextDouble();
// 🚨 ГРЕШКА 1: nextDouble() оставя '\n' в буфера -> city ще стане празен стринг ""!
String city = scanner.nextLine(); 

// 🚨 ГРЕШКА 2: Сравнение на съдържанието на String с '==' вместо '.equals()' -> винаги връща false!
if (city == "Sofia") {
    System.out.println("Столица");
}
```
*   **Как да се избегне:** Винаги чети всеки ред с **`scanner.nextLine()`** и парсвай с `Double.parseDouble(...)` / `Integer.parseInt(...)`. Винаги сравнявай текстове с **`"Sofia".equals(city)`**.

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic/C# стил в Java без буферни капани):
```java
import java.util.Scanner;

public class CleanSyntaxDemo {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        double budget = Double.parseDouble(scanner.nextLine());
        String city = scanner.nextLine();

        if ("Sofia".equals(city) && budget >= 100.0) {
            System.out.printf("Пътуване до %s с бюджет %.2f лв.%n", city, budget);
        }
    }
}
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Каква е разликата между класическия `switch` с двоеточие (`case 1:`) и модерния `switch` израз със стрелка (`case 1 ->`) в Java, и какво означава терминът **Fall-through**?“*
*   **Уловката:** В стария `switch` забравянето на `break;` води до тихо изпълнение на следващите `case` блокове — един от най-честите бъгове в историята на C и Java.
*   **Точен Senior отговор:** 
    1.  **Fall-through (Пропадане):** При стария `switch (x) { case 1: ... case 2: ... }`, ако пропуснеш `break;`, кодът продължава да изпълнява и `case 2`, и `case 3`, докато не срещне `break` или края на блока.
    2.  **Модерен Switch Expression (`->`):** При синтаксиса със стрелка **`case 1 -> ...`** няма Fall-through — изпълнява се **само съответният клон** без нужда от `break`, може да се изброяват множество стойности на един ред (`case "Sat", "Sun" -> ...`) и целият `switch` връща директно резултат в променлива.
