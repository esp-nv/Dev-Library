## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Тестът „Е вид“ (`IS-A`):** Наследяването е правилно само ако можеш да кажеш с чисто сърце *„Кучето Е ВИД Животно“* (`Dog extends Animal`) или *„Мениджърът Е ВИД Служител“* (`Manager extends Employee`). Ако не е „Е вид“, ползвай композиция!
*   **Трите лица на ключовата дума `final` (Спирачката в Java):**
    1.  `final int X = 10;` ➔ **Константа** (стойността не може да се променя).
    2.  `final void pay()` ➔ **Забрана за пренаписване** (наследниците не могат да направят `@Override` на този метод).
    3.  `final class String` ➔ **Забрана за наследяване** (никой клас не може да направи `extends String`).

## 2. РЕД НА ИЗПЪЛНЕНИЕ НА КОНСТРУКТОРИТЕ ПРИ НАСЛЕДЯВАНЕ (БЛОК-СХЕМА)

Когато създадеш наследник `new GoldenRetriever("Рекс")`, Java строи сградата **от основите нагоре (Top-Down)**:

```text
new GoldenRetriever("Рекс")
       │
       ▼ 1. Извиква суперкласа Animal(name)
┌──────────────────────────────────────────────────────────┐
│ Object() ➔ Animal("Рекс") (Инициализира базовите полета) │
└────────────────────────────┬─────────────────────────────┘
                             ▼ 2. Извиква Dog(name)
┌──────────────────────────────────────────────────────────┐
│ Dog("Рекс") (Инициализира полетата на кучето)            │
└────────────────────────────┬─────────────────────────────┘
                             ▼ 3. Накрая изпълнява GoldenRetriever
┌──────────────────────────────────────────────────────────┐
│ GoldenRetriever("Рекс") (Готов обект в Heap паметта!)    │
└──────────────────────────────────────────────────────────┘
```

## 3. СРАВНИТЕЛНА КАРТА В 4 ЕЗИКА (JAVA, C#, PYTHON, JAVASCRIPT)

| Концепция | ☕ Java 21+ | 🟣 C# 12+ (.NET) | 🐍 Python 3.x | 🟡 JavaScript (ES6+) |
| :--- | :--- | :--- | :--- | :--- |
| **Наследяване на клас** | `class Dog extends Animal` | `class Dog : Animal` | `class Dog(Animal):` | `class Dog extends Animal` |
| **Множествено наследяване** | **Не** (само 1 клас) | **Не** (само 1 клас) | **Да** (`class C(A, B):`) | **Не** (само 1 клас) |
| **Викане на родителски ctor** | `super(args);` (1-ви ред!) | `: base(args)` (в заглавието) | `super().__init__(args)` | `super(args);` (преди `this`) |
| **Викане на родителски метод** | `super.eat();` | `base.Eat();` | `super().eat()` | `super.eat();` |
| **Забрана за наследяване** | `final class MyClass` | `sealed class MyClass` | `@final` (typing) | `Object.freeze()` |
| **Корен на всички класове** | `java.lang.Object` | `System.Object` (`object`) | `object` | `Object.prototype` |

## 4. ПЛЮСОВЕ И МИНУСИ НА НАСЛЕДЯВАНЕТО

### 🟢 Предимства (Pros):
*   **Преизползване на общ код и състояние:** Общите полета (`id`, `createdAt`, `name`) и методите за работа с тях се пишат веднъж в базовия клас.
*   **Полиморфизъм по базов тип:** Позволява да държиш различни наследници в един списък `List<Animal>`.

### 🔴 Недостатъци (Cons):
*   **Силна свързаност (Tight Coupling):** Промяна в базовия клас може неволно да счупи наследниците.
*   **Конструкторите НЕ се наследяват:** Всеки наследник трябва да дефинира свои конструктори и да подаде нужните аргументи нагоре чрез `super(...)`.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД (СКРИТО `SUPER()` И СЧУПВАНЕ НА БАЗОВ КЛАС)

### ❌ ГРЕШЕН КОД (Липсващ празен конструктор в родителя и грешен ред на `super()`):
```java
class Person {
    private String name;
    // Базовият клас има САМО конструктор с параметър (няма Person() без параметри!)
    public Person(String name) { this.name = name; }
}

class Student extends Person {
    private double grade;

    public Student(String name, double grade) {
        // 🚨 ГРЕШКА 1: Ако не напишеш super(name), Java тайно слага празно super() на 1-ви ред
        // и компилаторът гърми: "There is no default constructor available in Person"!
        this.grade = grade;
        // 🚨 ГРЕШКА 2: super(name) НЕ МОЖЕ да е на 2-ри ред! Задължително е ПЪРВИЯТ ред!
        super(name); 
    }
}
```
*   **Как да се избегне:** Ако родителският клас няма конструктор без параметри, извикването **`super(...)`** **задължително** трябва да бъде **най-първият ред** в конструктора на наследника.

### 🟢 ПРАВИЛЕН КОД (Чиста йерархия с `super(...)` и `@Override`):
```java
class Person {
    private final String name;

    public Person(String name) {
        this.name = name;
    }

    public String getName() { return name; }

    public String getInfo() {
        return "Лице: " + name;
    }
}

class Student extends Person {
    private final double grade;

    public Student(String name, double grade) {
        super(name); // Задължително първи ред!
        this.grade = grade;
    }

    @Override
    public String getInfo() {
        // Преизползваме логиката на родителя чрез super.getInfo() и я надграждаме
        return super.getInfo() + String.format(" | Оценка: %.2f", grade);
    }
}
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Какво ще се случи, ако в базов клас конструктурът извика пренаписан (`@Override`) метод от наследника, преди конструкторът на наследника да е приключил?“*
*   **Уловката:** Това е един от най-коварните капани в Java (и C#) — извикване на виртуален метод вътре в конструктор!
*   **Точен Senior отговор:** Когато се изпълнява конструкторът на базовия клас `Parent`, **полетата на наследника `Child` все още НЕ са инициализирани** (имат стойности по подразбиране `0`, `false` или `null`). Ако `Parent()` извика метод `printValue()`, който е пренаписан в `Child` и чете поле `this.secret = "Hello"`, методът ще отпечата **`null`** (а не `"Hello"`), защото инициализацията на `Child` още не е стигнала! **Правило:** Никога не извиквай не-`final` / пренаписваеми методи вътре в конструктор!

## 7. АРХИТЕКТУРНО СРАВНЕНИЕ: JAVA 21+ СРЕЩУ C# 12+ (.NET)

| Архитектурен детайл | ☕ Java 21+ (JVM) | 🟣 C# 12+ (.NET 8+ CLR) |
| :--- | :--- | :--- |
| **Синтаксис за наследяване** | `class Dog extends Animal` | `class Dog : Animal` |
| **Извикване на базов конструктор** | `super(name);` вътре като **първи ред** на тялото | `: base(name)` в **сигнатурата** преди отварящата скоба `{` |
| **Пренаписване на метод** | Всички методи са виртуални по подразбиране; пишем `@Override` | Родителят пише `virtual`, наследникът пише `override` |
| **Забрана за наследяване на клас** | `public final class MyClass` | `public sealed class MyClass` |
| **Забрана за пренаписване на метод** | `public final void run()` | `public sealed override void Run()` |
| **Diamond Problem решение** | Само 1 родителски клас; конфликт в `default` методи на интерфейси се решава с `InterfaceName.super.method()` | Само 1 родителски клас; интерфейсите с default методи се достъпват чрез каст `((IMyInterface)this).Method()` |
