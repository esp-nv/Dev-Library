## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Четирите стълба на ООП (`A-P-I-E`):** Абстракция (`interface`/`abstract class`), Полиморфизъм (различно поведение при еднакъв интерфейс), Наследяване (`extends`) и Капсулация (`private` полета с валидация).
*   **`this` срещу `super`:** **`this`** се отнася до текущия обект, докато **`super`** насочва към родителския клас.

## 4. ПЛЮСОВЕ И МИНУСИ НА ООП В JAVA

### 🟢 Предимства (Pros):
*   **Виртуални методи по подразбиране:** Всички нестатични, не-`private` и не-`final` методи в Java са виртуални по подразбиране и могат да бъдат пренаписвани (`@Override`) без нужда от ключовата дума `virtual` (както е в C#).
*   **Строга архитектура и Sealed Classes (Java 17+):** Позволява ти да ограничиш точно кои класове имат право да наследяват даден базов клас (`sealed class Shape permits Circle, Square`).

### 🔴 Недостатъци (Cons):
*   **Няма множествено наследяване на класове:** Един клас може да разширява (`extends`) само един родителски клас (но може да имплементира неограничен брой интерфейси).
*   **Повече шаблонни редове (Boilerplate):** Изисква изрични конструктори, `getters` и `setters` (решава се с `record` или библиотеката **Lombok**).

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Публични полета без капсулация и липсващо `@Override`):
```java
public class BadAccount {
    // 🚨 ГРЕШКА 1: Публично поле -> всеки отвън може да напише account.balance = -5000!
    public double balance;

    // 🚨 ГРЕШКА 2: Липсва анотацията @Override!
    // Ако сбъркаш името на метода (напр. tostring() вместо toString()), компилаторът мълчи
    // и създава нов метод вместо да пренапише наследения!
    public String tostring() {
        return "Balance: " + balance;
    }
}
```
*   **Как да се избегне:** Държи всички полета **`private`**, валидирай данните в конструктора/сетърите и **винаги** слагай **`@Override`** над всеки пренаписан метод.

### 🟢 ПРАВИЛЕН КОД (Чист капсулиран Java клас с валидация и `@Override`):
```java
public class BankAccount {
    private String owner;
    private double balance;

    public BankAccount(String owner, double initialBalance) {
        this.setOwner(owner);
        this.deposit(initialBalance);
    }

    public void setOwner(String owner) {
        if (owner == null || owner.isBlank()) {
            throw new IllegalArgumentException("Името на собственика е задължително!");
        }
        this.owner = owner;
    }

    public void deposit(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException("Сумата трябва да е положителна!");
        }
        this.balance += amount;
    }

    @Override
    public String toString() {
        return String.format("Сметка на %s | Баланс: %.2f лв.", owner, balance);
    }
}
```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Какво означава златното ООП правило **„Favor composition over inheritance“ (Предпочитай композицията пред наследяването)** и какъв е проблемът с крехкия базов клас (**Fragile Base Class Problem**)?“*
*   **Уловката:** Начинаещите разработчици наследяват класове само за да преизползват 2–3 метода (напр. `class Stack extends ArrayList`), което чупи капсулацията!
*   **Точен Senior отговор:** 
    1.  **Наследяването (`IS-A`)** създава най-силната възможна зависимост между два класа. Ако промениш вътрешната логика на базовия клас, може неволно да счупиш всички 15 наследника (**Fragile Base Class Problem**). Освен това наследникът получава и публични методи, които не би трябвало да има (напр. `stack.add(2, "x")` в средата на стека!).
    2.  **Композицията (`HAS-A`)** означава да държиш другия клас като **`private final` поле** вътре в твоя клас и да излагаш само методите, които искаш. Така кодът е по-гъвкав, по-лесен за тестване с Mockito и спазва SOLID принципите.

## 7. АРХИТЕКТУРНО СРАВНЕНИЕ: JAVA 21+ СРЕЩУ C# 12+ (.NET)

Дълбок сравнителен преглед на спецификите на ООП двигателя между двата корпоративни езика:

| Архитектурен детайл | ☕ Java 21+ (JVM) | 🟣 C# 12+ (.NET 8+ CLR) |
| :--- | :--- | :--- |
| **Виртуални методи** | **Всички нестатични методи са виртуални по подразбиране** (забраняват се с `final`) | **Невиртуални по подразбиране** (изискват изрично `virtual` или `abstract`) |
| **Скриване на наследен метод** | Няма директен еквивалент (винаги пренаписва) | Ключова дума `new` (`public new void Run()`) |
| **Множествено наследяване на поведение** | Чрез **`default` методи в интерфейси** (Java 8+) | Чрез **Default Interface Methods** (C# 8+) |
| **Ограничено наследяване (Sealed)** | `sealed class A permits B, C` (контролира *кои* класове наследяват) | `sealed class A` (забранява *всякакво* наследяване, като `final` в Java) |
| **Стойностни обекти (Value Types)** | Няма потребителски структури (само 8 примитива; *Project Valhalla* е в разработка) | `struct` и `record struct` (живеят в Stack паметта без GC товар) |
| **Инкапсулация по пакет / сборка** | `package-private` (без модификатор — видим в същия `package`) | `internal` (видим в целия `.csproj` проект / Assembly) |
| **Properties (Свойства)** | Няма в езика (пишат се `getX()` / `setX()` или се генерират с **Lombok**) | Вградени в езика (`public string Name { get; set; }`) |
| **Първични конструктори** | Само при **`record`** (`record User(String name) {}`) | При **всички класове и структури** (`class User(string name)`) |
