## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Кортеж (`tuple`) = Заключен списък в стъклена витрина:** Огражда се с обикновени кръгли скоби `()`. Можеш да гледаш елементите по индекс (`t`), но не можеш да ги променяш, добавяш или триеш.
*   **Множество (`set`) = Торба с уникални топчета:** Огражда се с фигурни скоби `{}`. Вътре **няма ред** (не можеш да кажеш „дай ми първото топче“ с `s`) и **няма дубликати** — ако пуснеш две еднакви числа, второто се изпарява автоматично.

---

## 2. ЕТАПИ НА ХЕШИРАНЕ В МНОЖЕСТВО И БЛОК-СХЕМА

Множеството (`set`) под капака е **Речник (`dict`) само с ключове и без стойности**. Това го прави светкавично при проверки за принадлежност (`x in my_set`).

```text
Входен списък: [10, 20, 10, 30] ──► Превръщане в set()

1. Взима 10 ──► hash(10) ──► Слот #2 е празен ──► Записва 10
2. Взима 20 ──► hash(20) ──► Слот #5 е празен ──► Записва 20
3. Взима 10 ──► hash(10) ──► Слот #2 ВЕЧЕ Е ЗАЕТ от 10 ──► Игнорира дубликата!
4. Взима 30 ──► hash(30) ──► Слот #1 е празен ──► Записва 30

Резултат в RAM: {10, 20, 30} (Проверено за O(1) време!)
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Структура / Операция | Python 3.x | C# (.NET) | JavaScript (ES6+) |
| :--- | :--- | :--- | :--- |
| **Кортеж (Tuple)** | `t = (1, "Admin")` (Immutable) | `var t = (1, "Admin");` (ValueTuple) | Няма нативен (ползва се `Object.freeze`) |
| **Множество (Set)** | `s = {1, 2, 3}` | `var s = new HashSet<int> {1, 2, 3};` | `const s = new Set([1, 2, 3]);` |
| **Празно множество** | `s = set()` (`{}` е празен `dict`!) | `new HashSet<T>()` | `new Set()` |
| **Сечение (Intersection)** | `set_a & set_b` | `setA.IntersectWith(setB)` | `setA.intersection(setB)` (ES2025) |
| **Обединение (Union)** | `set_a \| set_b` | `setA.UnionWith(setB)` | `setA.union(setB)` |

## 4. ПЛЮСОВЕ И МИНУСИ НА TUPLES И SETS

### 🟢 Предимства (Pros):
*   **Максимална скорост при търсене (`set`):** Проверка `if user_id in banned_ids:` в `set` от 1 000 000 елемента отнема **O(1)** (микросекунди), докато в `list` отнема **O(n)**.
*   **Икономия на памет при `tuple`:** Тъй като кортежът не може да расте, Python заделя точно толкова RAM, колкото е нужна, без излишни резервни буфери.

### 🔴 Недостатъци (Cons):
*   **Липса на индексиране в `set`:** Не можеш да напишеш `my_set` или `my_set[1:3]` (хвърля `TypeError`).
*   **Неизменяемост на `tuple`:** Ако трябва да промениш един елемент в кортеж, трябва да го обърнеш в списък (`list(t)`), да го промениш и да го върнеш обратно в `tuple(t)`.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Капанът на кортежа с 1 елемент и празното множество):
```python
# 🚨 ГРЕШКА 1: Създаване на кортеж с 1 елемент без запетая!
not_a_tuple = ("Admin")     # Това е обикновен стринг 'str', НЕ е tuple!

# 🚨 ГРЕШКА 2: Създаване на празно множество с фигурни скоби {}
empty_thing = {}            # Това създава празен РЕЧНИК (dict), НЕ множество!
# empty_thing.add(5)        -> Гърми с AttributeError: 'dict' object has no attribute 'add'!
```
*   **Как да се избегне:** Кортеж с един елемент **задължително** завършва със запетая: `("Admin",)`. Празно множество се прави **само** с `set()`.

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic стандарт за множества и кортежи):
```python
# 1. Правилно създаване на единичен кортеж и разопаковане
server_endpoint = ("192.168.1.10", 8080)
single_role = ("SuperAdmin",)
ip, port = server_endpoint
print(f"Сървър: {ip}:{port} | Тип на ролята: {type(single_role)}")

# 2. Филтриране на права чрез операции от теория на множествата
required_skills = {"Python", "SQL", "Docker", "Git"}
candidate_skills = {"Python", "Git", "HTML", "CSS"}

matching = required_skills & candidate_skills      # Сечение (Общи умения)
missing = required_skills - candidate_skills       # Разлика (Какво липсва)

print(f"Съвпадащи умения: {matching}")
print(f"Липсващи умения:  {missing}")
```
*   **Изход в конзолата:**
    ```text
    Сървър: 192.168.1.10:8080 | Тип на ролята: <class 'tuple'>
    Съвпадащи умения: {'Python', 'Git'}
    Липсващи умения:  {'Docker', 'SQL'}
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Вярно ли е твърдението, че кортежът (`tuple`) в Python е 100% неизменяем и съдържанието му никога не може да се промени?“*
*   **Уловката:** Почти всички отговарят „Да, напълно неизменяем е“.
*   **Точен Senior отговор:** **Не винаги!** Кортежът е неизменяем като **контейнер от референции** (не можеш да смениш на кой адрес в паметта сочи индекс 0). Но ако на индекс 0 вътре в кортежа си сложил **изменяем обект (Mutable)**, като например списък `t = (1, [10, 20])`, ти не можеш да направиш `t = 99`, но можеш спокойно да направиш **`t.append(30)`**! Тогава кортежът става `(1, [10, 20, 30])` без грешка. Също така такъв кортеж веднага губи способността си да бъде ключ в речник (става Unhashable).
