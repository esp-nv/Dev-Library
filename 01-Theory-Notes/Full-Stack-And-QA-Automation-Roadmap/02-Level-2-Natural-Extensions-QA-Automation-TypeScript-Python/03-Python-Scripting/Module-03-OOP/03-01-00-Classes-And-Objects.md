## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Клас = Чертеж на къща, Обект = Построената къща:** От един чертеж (`class Car`) можеш да построиш хиляди реални коли (`car1`, `car2`), всяка със свой цвят и регистрационен номер.
*   **`__str__` срещу `__repr__`:**
    *   **`__str__`** е за **крайния потребител** (красиво, четимо съобщение при `print(obj)`).
    *   **`__repr__`** е за **програмиста (Developer)** (показва как точно да пресъздадеш обекта в кода при дебъгване или вътре в списък `[obj1, obj2]`).

## 2. ЕТАПИ НА СЪЗДАВАНЕ НА ОБЕКТ В ПАМЕТТА И БЛОК-СХЕМА

Всеки стандартен обект в Python пази своите данни вътре в скрит речник, наречен **`__dict__`**, докато методите му стоят горе в самия клас.

```text
user = User("Елизабет")

┌───────────────────────────────────────┐
│ Клас 'User' в RAM паметта             │
│ • Методи: __init__, get_info()        │
│ • Class Attributes (общи за всички)   │
└───────────────────▲───────────────────┘
                    │ (Указател към типа)
┌───────────────────┴───────────────────┐
│ Инстанция 'user' в RAM паметта        │
│ • __dict__: {'name': 'Елизабет'}      │
└───────────────────────────────────────┘
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Концепция | Python 3.x | C# (.NET) | JavaScript (ES6+) |
| :--- | :--- | :--- | :--- |
| **Дефиниране на клас** | `class User:` (PascalCase) | `public class User { }` | `class User { }` |
| **Създаване на обект** | `u = User("Иван")` (**без** `new`!) | `var u = new User("Иван");` | `const u = new User("Иван");` |
| **Текстово представяне** | `def __str__(self):` | `public override string ToString()` | `toString()` |
| **Деструктор** | `def __del__(self):` (несигурен) | `~User()` (Finalizer) | Няма (`FinalizationRegistry`) |
| **Бърз клас за данни** | `@dataclass` (Python 3.7+) | `record User(string Name);` | Няма нативен еквивалент |

## 4. ПЛЮСОВЕ И МИНУСИ НА КЛАСОВЕТЕ В PYTHON

### 🟢 Предимства (Pros):
*   **Модулът `dataclasses`:** Декораторът `@dataclass` автоматично генерира `__init__`, `__repr__` и `__eq__` (сравнение по стойност), спестявайки десетки редове шаблонен код.
*   **Операторно предефиниране (Operator Overloading):** Чрез Dunder методи като `__add__` (`+`) или `__eq__` (`==`) можеш да научиш твоите класове да се събират и сравняват нативно.

### 🔴 Недостатъци (Cons):
*   **Висок разход на RAM заради `__dict__`:** Тъй като всеки обект носи собствен речник `__dict__` в паметта, създаването на 1 милион малки обекта хаби стотици мегабайти RAM (решава се с `__slots__`).
*   **Риск от случайни правописни грешки в атрибутите:** Ако напишеш `self.pric = 10` вместо `self.price = 10`, Python тихо създава второ поле, вместо да спре компилацията.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД

### ❌ ГРЕШЕН КОД (Бъркане на Class Attribute с Instance Attribute):
```python
class ServerNode:
    # 🚨 ГРЕШКА: Това е общ атрибут на класа (като static в C#)!
    active_connections = 0

node_a = ServerNode()
node_b = ServerNode()

# Уловка: Променяме го през инстанцията node_a!
# Python НЕ променя общия атрибут, а създава ново локално поле само за node_a!
node_a.active_connections += 1

print(node_a.active_connections)  # 1 (локално поле в node_a.__dict__)
print(node_b.active_connections)  # 0 (чете общото поле от класа!)
```
*   **Как да се избегне:** Ако променяш атрибут на класа (Class Attribute), **винаги** го достъпвай през името на класа (`ServerNode.active_connections += 1`), никога през `self` или инстанция!

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic ООП стандарт с `__str__`, `__repr__` и `@dataclass`):
```python
from dataclasses import dataclass

# Модерен начин за писане на класове за данни (DTO / Models)
@dataclass
class CourseModule:
    code: str
    title: str
    max_points: int = 100

    def is_passed(self, student_points: int) -> bool:
        return student_points >= (self.max_points * 0.6)

# Автоматично генерирани __init__, __repr__ и == сравнение!
mod1 = CourseModule("PY-OOP", "Classes and Objects")
mod2 = CourseModule("PY-OOP", "Classes and Objects")

print(mod1)                                     # Красив автоматичен __repr__ изход
print(f"Еднакви ли са по стойност: {mod1 == mod2}") # True (сравнява полетата, не адресите!)
print(f"Взет изпит с 75 т.: {mod1.is_passed(75)}")
```
*   **Изход в конзолата:**
    ```text
    CourseModule(code='PY-OOP', title='Classes and Objects', max_points=100)
    Еднакви ли са по стойност: True
    Взет изпит с 75 т.: True
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Какво представлява `__slots__` в Python класовете, как оптимизира оперативната памет и какви ограничения налага?“*
*   **Уловката:** Кандидатите често не знаят как да намалят паметта при милиони обекти в Python.
*   **Точен Senior отговор:** По подразбиране всеки Python обект пази атрибутите си в динамичен речник `__dict__`, който заема много RAM памет. Когато дефинираме **`__slots__ = ("id", "name")`** вътре в класа, Python **не създава речник `__dict__`** за инстанциите, а заделя фиксиран, компактен масив от байтове само за тези две полета (намалявайки разхода на RAM с 40% до 60% и ускорявайки достъпа до свойствата).
    *   *Ограничение:* След като сложиш `__slots__`, вече **не можеш** динамично да добавяш нови произволни атрибути към обекта по време на изпълнение (`obj.new_field = 5` хвърля `AttributeError`).
