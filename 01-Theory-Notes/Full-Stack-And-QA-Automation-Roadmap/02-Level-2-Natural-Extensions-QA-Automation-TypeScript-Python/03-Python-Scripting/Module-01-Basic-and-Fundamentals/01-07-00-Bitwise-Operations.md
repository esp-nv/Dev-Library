## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Електрически ключове (Лампи):** Представи си всяко число като редица от лампи, които могат да бъдат само включени (`1`) или изключени (`0`). Побитовите операции не гледат числото като „пет“ или „шест“, а сравняват **лампа по лампа** (колона по колона отдясно наляво).
*   **Трите златни правила на символите:**
    *   **`&` (AND / И):** Строг пазач — свети (`1`) **само** ако и двете лампи светят (`1 & 1 = 1`).
    *   **`|` (OR / ИЛИ):** Щедър — свети (`1`), стига **поне едната** лампа да свети (`1 | 0 = 1`).
    *   **`^` (XOR / Изключващо ИЛИ):** Търси разликата — свети (`1`) **само** ако двете лампи са в различно състояние (`1 ^ 0 = 1`, но `1 ^ 1 = 0`).

## 2. ЕТАПИ НА ПОБИТОВА ОПЕРАЦИЯ И БЛОК-СХЕМА

Процесорът (CPU) извършва побитовите операции директно в своите хардуерни регистри за един-единствен тактов цикъл, без сложни математически алгоритми.

```text
Операция: 5 & 3  (5 в двоичен вид е 0101, 3 в двоичен вид е 0011)

  Число 5:   [ 0 ]  [ 1 ]  [ 0 ]  [ 1 ]
  Число 3:   [ 0 ]  [ 0 ]  [ 1 ]  [ 1 ]
               │      │      │      │
  Оператор &   ▼      ▼      ▼      ▼   (1 само където И двете са 1)
  Резултат:  [ 0 ]  [ 0 ]  [ 0 ]  [ 1 ]  ➔ Десетично число: 1
```

## 4. ПЛЮСОВЕ И МИНУСИ НА ПОБИТОВИТЕ ОПЕРАЦИИ

### 🟢 Предимства (Pros):
*   **Максимална скорост и икономия на RAM (Bitmasks):** Вместо да пазиш 8 отделни булеви променливи (`can_read`, `can_write`, `can_delete`...), можеш да събереш всички права за достъп в **едно-единствено число от 1 байт** (използва се масово в Linux права `chmod 755` и игрови двигатели).
*   **Светкавична математика:** Изместването наляво (`x << 1`) умножава по 2, а изместването надясно (`x >> 1`) дели целочислено на 2 много по-бързо от стандартните аритметични оператори.

### 🔴 Недостатъци (Cons):
*   **Ниска четимост за хора:** Израз като `flags |= (1 << 3)` изглежда като криптография за програмист, който не познава битовите маски, и изисква задължителни коментари.
*   **Риск от грешки с отрицателни числа:** Поради безкрайната дължина на `int` в Python, побитовото обръщане (`~`) се държи различно спрямо фиксираните 32-битови числа в C# и JS.

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД (И КОМЕНТАРИ)

### ❌ ГРЕШЕН КОД (Бъркане на побитови с логически оператори):
```python
a = 5  # Двоично: 0101
b = 2  # Двоично: 0010

# 🚨 ГРЕШКА: Използване на побитово '&' вместо логическото 'and' в if проверка!
if a & b:  # 0101 & 0010 дава 0000 (0 -> False!), въпреки че и двете числа са ненулеви!
    print("И двете са истина")
else:
    print("Уловка! Влезе в else, защото 5 & 2 == 0!")
```
*   **Как да се избегне:** За логически проверки в `if` условия **винаги** пиши думите `and`, `or`, `not`. Символите `&`, `|`, `~` се ползват **единствено** за битова математика и маски.

### 🟢 ПРАВИЛЕН КОД (Управление на потребителски права чрез Bitmask):
```python
# Дефиниране на права за достъп като степени на двойката (отделни битове)
READ = 1      # 0001 (1 << 0)
WRITE = 2     # 0010 (1 << 1)
DELETE = 4    # 0100 (1 << 2)
ADMIN = 8     # 1000 (1 << 3)

# 1. Даване на права за Четене и Писане чрез побитово ИЛИ (|)
user_permissions = READ | WRITE  # 0001 | 0010 = 0011 (числото 3)

# 2. Проверка дали потребителят има право за Писане чрез побитово И (&)
has_write = (user_permissions & WRITE) != 0
has_delete = (user_permissions & DELETE) != 0

# 3. Премахване на право за Писане чрез комбинация от & и ~
user_permissions = user_permissions & ~WRITE

print(f"Може ли да пише (преди): {has_write}")
print(f"Може ли да трие:          {has_delete}")
print(f"Може ли да пише (след):  {(user_permissions & WRITE) != 0}")
```
*   **Изход в конзолата:**
    ```text
    Може ли да пише (преди): True
    Може ли да трие:          False
    Може ли да пише (след):  False
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Как можеш да провериш дали едно цяло число `n` е степен на двойката (напр. 2, 4, 8, 16, 32...) на един ред, без цикли и без логаритми, използвайки побитова операция?“*
*   **Уловката:** Кандидатите често забравят случая за числото `0` или отрицателните числа.
*   **Точен Senior отговор:** В двоичната бройна система всяка степен на двойката има **само един вдигнат бит `1`**, последван от нули (напр. `8` е `1000`), а числото преди него (`7`) има само единици на по-младшите позиции (`0111`). Когато приложим побитово И между тях (`8 & 7`), резултатът винаги е точно **`0`**!
    *   **Формула:** `is_power_of_two = (n > 0) and ((n & (n - 1)) == 0)` (проверката `n > 0` е задължителна, за да изключи нулата).
