## 1. КАК ДА СЕ ЗАПОМНИ И ЧЕТЕ ПО-ЛЕСНО (МНЕМОНИКА)

*   **Телефонен указател или JSON обект:** Речникът (`dict`) в Python е точно това, което е **`Dictionary<TKey, TValue>` в C#** или **`Object` / `Map` в JavaScript**. Вместо да търсиш по числов индекс (`0, 1, 2`), ти търсиш по уникално име (Ключ), например `user["email"]`.
*   **Правилото за ключовете:** Стойностите могат да бъдат абсолютно всичко (числа, списъци, други речници). Ключовете обаче **задължително** трябва да са уникални и **неизменяеми (Immutable / Hashable)** — например `str`, `int` или `tuple`. Списък (`list`) не може да бъде ключ!

## 2. ЕТАПИ НА ТЪРСЕНЕ ПО ХЕШ И БЛОК-СХЕМА

Под капака речникът е високооптимизирана **Хеш таблица (Hash Table)**. Когато търсиш `data["Sofia"]`, Python не обхожда елементите един по един от началото до края, а изчислява математически адрес в паметта за миг.

```text
Заявка: user_ages["Елизабет"]

┌──────────────────────────┐     1. Хеш функция       ┌─────────────────────────┐
│ Ключ: "Елизабет"         │ ───────────────────────► │ Хеш код (Число):        │
│                          │   hash("Елизабет")       │ -4829104829104          │
└──────────────────────────┘                          └────────────┬────────────┘
                                                                   │ 2. Индекс в RAM
                                                                   ▼
┌──────────────────────────┐     3. Директен достъп   ┌─────────────────────────┐
│ Връща стойността: 25     │ ◄─────────────────────── │ Слот #4 в Хеш Таблицата │
│ Скорост: O(1) мигновено  │                          │ [Ключ: "Елизабет", 25]  │
└──────────────────────────┘                          └─────────────────────────┘
```

## 3. АРХИТЕКТУРНО СРАВНЕНИЕ: PYTHON СРЕЩУ C# И JAVASCRIPT

| Операция | Python `dict` | C# `Dictionary<K, V>` | JavaScript `Object` / `Map` |
| :--- | :--- | :--- | :--- |
| **Синтаксис** | `{"name": "Иван"}` | `new() { ["name"] = "Иван" }` | `{ name: "Иван" }` |
| **Запазва ли реда?** | **Да** (от Python 3.7+ насам) | Не е гарантирано при триене | `Map` да, `Object` с условности |
| **Липсващ ключ (четене)** | `d["x"]` хвърля `KeyError` | `d["x"]` хвърля `KeyNotFoundException` | `obj.x` връща `undefined` |
| **Безопасно четене** | `d.get("x", "По подразбиране")` | `d.TryGetValue("x", out var val)` | `obj.x ?? "По подразбиране"` |
| **Всички ключове** | `d.keys()` | `d.Keys` | `Object.keys(obj)` |

## 4. ПЛЮСОВЕ И МИНУСИ НА РЕЧНИЦИТЕ

### 🟢 Предимства (Pros):
*   **Светкавично търсене O(1):** Дори речникът да съдържа 5 милиона записа, намирането на стойност по ключ отнема същото нищожно време, както при речник с 5 записа.
*   **Директна съвместимост с JSON:** Структурата на Python речниците е почти 1:1 с JSON формата, което прави работата с REST API и NoSQL бази (като Redis и MongoDB) изключително лесна.

### 🔴 Недостатъци (Cons):
*   **По-голям разход на оперативна памет (RAM):** Хеш таблиците умишлено поддържат около 1/3 празни слотове в паметта, за да избягват сблъсъци (Hash Collisions), което ги прави по-тежки от списъците.
*   **Не можеш да достъпваш по числов индекс:** Изразът `my_dict[0]` не взима първия елемент, а търси ключ с числото `0`!

## 5. КОДОВ ОДИТ: ПРАВИЛЕН СРЕЩУ ГРЕШЕН КОД (И КОМЕНТАРИ)

### ❌ ГРЕШЕН КОД (Срив с KeyError и грешно обхождане):
```python
student = {"name": "Георги", "grade": 5.50}

# 🚨 ГРЕШКА 1: Директно четене на ключ, който може да липсва в JSON отговора
# email = student["email"] -> Програмата гърми с KeyError: 'email'!

# 🚨 ГРЕШКА 2: Обхождане на речник директно с цикъл връща САМО ключовете, не и стойностите!
for item in student:
    print(item)  # Принтира само "name" и "grade", без стойностите!
```
*   **Как да се избегне:** При четене на външни данни винаги използвай `.get("ключ", стойност_по_подразбиране)`. За обхождане на двойки ключ-стойност винаги използвай `.items()`.

### 🟢 ПРАВИЛЕН КОД (Чист Pythonic стандарт за работа с речници):
```python
# 1. Безопасно четене и обновяване на данни
user_cache = {"id": 101, "username": "esp_nv", "login_count": 4}

# Използваме .get(), за да не гръмне програмата ако ключът липсва
user_role = user_cache.get("role", "Guest")
print(f"Роля на потребителя: {user_role}")

# Безопасно увеличаване на брояч (ако го няма, започва от 0)
user_cache["login_count"] = user_cache.get("login_count", 0) + 1

# 2. Правилно обхождане на ключ и стойност едновременно с .items()
for key, value in user_cache.items():
    print(f"Ключ: {key:<12} | Стойност: {value}")
```
*   **Изход в конзолата:**
    ```text
    Роля на потребителя: Guest
    Ключ: id           | Стойност: 101
    Ключ: username     | Стойност: esp_nv
    Ключ: login_count  | Стойност: 5
    ```

## 6. ИНТЕРВЮ КАПАНИ, ВЪПРОСИ И УЛОВКИ

*   **Въпрос на интервюто:** *„Защо в Python списък (`list`) не може да се използва като ключ в речник, докато кортеж (`tuple`) може?“*
*   **Уловката:** Кандидатите често отговарят „защото списъкът е по-бавен“, което е грешно.
*   **Точен Senior отговор:** За да бъде един обект ключ в хеш таблица, той трябва да бъде **Hashable** — неговият хеш код (`hash(key)`) никога да не се променя през целия му живот в паметта. Тъй като списъкът е **изменяем (Mutable)**, ако го сложиш като ключ и после добавиш нов елемент в него с `.append()`, неговият хеш би се променил и Python никога повече няма да може да намери слота му в таблицата. Кортежът (`tuple`) е **неизменяем (Immutable)**, затова неговият хеш е константа и той е напълно валиден ключ (освен ако вътре в самия кортеж не си скрил списък!).
