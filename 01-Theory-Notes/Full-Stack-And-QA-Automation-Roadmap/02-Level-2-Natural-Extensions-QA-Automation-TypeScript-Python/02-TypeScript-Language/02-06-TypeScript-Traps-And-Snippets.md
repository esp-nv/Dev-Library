## 1. ИНТЕРВЮ ВЪПРОС (Тема 02-01 & 02-03): Феноменът Изтриване на типове (Type Erasure Капан)

*   **Въпрос на интервюто:** *„Какво представлява концепцията 'Type Erasure' (Изтриване на типове) в TypeScript и защо следния C# / Java модел за проверка на инстанция през `instanceof` ще се срине брутално при изпълнение (Runtime)?“*
    ```typescript
    interface ICustomProfile { username: string; }
    function validateInput(obj: any) {
        if (obj instanceof ICustomProfile) { // 🚨 КРАХ при компилация!
            console.log("Валиден интерфейс.");
        }
    }
    ```
*   **Точен Senior отговор:** Този код се срива, защото интерфейсите (`Interfaces`) и типовите алиаси (`Type Aliases`) в TypeScript са чисти **компилационни структури**. Феноменът **Type Erasure** означава, че след като компилаторът `tsc` завърши своя статичен анализ и превърне кода в чист JavaScript, абсолютно всички типови декларации, интерфейси и дженерик скоби **се изтриват напълно от паметта** и липсват в крайния JS файл. Тъй като JavaScript няма никаква софтуерна представа какво е `ICustomProfile`, операторът `instanceof` (който търси реален физически прототип на клас в Runtime) хвърля критична грешка. Проверката за съвместимост на интерфейси се извършва ръчно чрез потребителски функции за стесняване, наречени **Type Predicates** (`typeof` или `in` оператори).

## 2. ИНТЕРВЮ ВЪПРОС (Тема 02-02): Капанът на Компромисния тип Any и Срив на инспекцията

*   **Въпрос на интервюто:** *„Защо масовото използване на типа `any` се счита за тежък архитектурен анти-патърн (лоша практика) и каква модерна, сигурна алтернатива ни предоставя TypeScript v5.x?“*
*   **Точен Senior отговор:** Използването на типа **`any`** напълно изключва защитния механизъм на компилатора. Когато присвоиш `any` на променлива, ти казваш на софтуера: *„Спри да проверяваш това парче памет и приеми, че всичко, което пиша тук, е вярно“*. Това отваря уязвимости към тихи Runtime бъгове и премахва ползите от IntelliSense автодопълнението. Модерната и напълно сигурна алтернатива е типът **`unknown`**. Типът `unknown` също може да приеме абсолютно всякаква стойност в паметта, но за разлика от `any`, TypeScript **забранява каквото и да е действие или извикване на методи над `unknown` обект**, докато не извършиш изрична софтуерна проверка (`Type Guard`) и не докажеш на компилатора какъв примитив стои вътре на ниско ниво.

## 3. ИНТЕРВЮ ВЪПРОС (Тема 02-04): Архитектурен сблъсък на структурната типизация (Structural vs. Nominal Typing)

*   **Въпрос на интервюто:** *„Езикът C# използва Номинална типизация (Nominal Typing), докато TypeScript стъпва на Структурна типизация (Structural / Duck Typing). Обяснете защо следният кодов фрагмент е напълно валиден и не хвърля грешка при компилация в TypeScript среди:“*
    ```typescript
    class DbUser { name!: string; }
    class WebProduct { name!: string; }

    const entity: DbUser = new WebProduct(); // 🟢 Напълно легитимно в TS!
    ```
*   **Точен Senior отговор:** В C# (Nominal) този код би довел до незабавен срив, защото двата класа имат напълно различни имена и йерархии на наследяване. TypeScript обаче изобщо не се интересува от името на класа или неговия корен; той работи по законите на **Структурната типизация** (ако изглежда като патица и ходи като патица, значи е патица). Тъй като и двата класа `DbUser` и `WebProduct` притежават **напълно идентична вътрешна софтуерна форма и свойства** (и двата имат само по едно текстово поле `name: string`), компилаторът ги отчита в паметта като 100% съвместими кутии и позволява тяхната директна замяна безрисково.

## 4. ПРОИЗВОДСТВЕНИ КАПАНИ: ИНТЕГРАЦИЯ НА НЕТИПИЗИРАНИ ВЪНШНИ JS БИБЛИОТЕКИ (D.TS СРИВОВЕ)

### 🚨 Капан №1: Билдът на проекта се срива при импортиране на стара npm JavaScript библиотека
*   **Причина:** Инсталирала си по-стара, но критична за бизнес логиката JS библиотека през npm. Когато напишеш `import md5 from 'old-md5-package';`, Vite или компилаторът `tsc` спират компилацията на мига с грешка: *Could not find a declaration file for module*. Това се случва, защото библиотеката е писана на суров JavaScript и в нея липсват декларационни файлове за типове (**`.d.ts`** файлове), които да преведат формите ѝ на езика на TypeScript.
*   **Решение (Два начина за фикс):** 
    1. Провери дали общността не е разписала готово типово разширение в отвореното хранилище на DefinitelyTyped, като изпълниш в терминала: `npm install @types/old-md5-package --save-dev`.
    2. Ако няма готово разширение, създай празен файл в твоята папка за разработка с име `declarations.d.ts` и впиши следната софтуерна тапа, която казва на TypeScript да спре да гърми и да приеме библиотеката чисто под общ `any` чадър:
       ```typescript
       // 🟢 СЕНЬОР СПАСИТЕЛЕН ОДИТ (Във declarations.d.ts файла):
       declare module 'old-md5-package';
       ```
