## 1. ИНТЕРВЮ ВЪПРОС (Тема 05-00): Изтичане на конфиденциални данни в URL адреса

*   **Въпрос на интервюто:** *„Какво ще се случи, ако проектираме форма за сигурен вход с поле за парола, но пропуснем изричното дефиниране на атрибута `method="POST"` във `<form>` тага?“*
*   **Точен Senior отговор:** Браузърът автоматично ще приложи своя вграден уеб стандарт по подразбиране — **`GET`**. Когато потребителят натисне бутона Submit, всички въведени данни, включително суровата парола на клиента, ще бъдат прикачени публично към уеб адреса под формата на Query String (напр. `/login?Email=test@bg.com&Password=Secret123`). Това представлява тежък критичен срив на сигурността (Security Leak). Данните ще изтекат и ще бъдат записани в историята на браузъра, в кеша на прокситата и в уеб логовете на сървъра, правейки ги лесна плячка за хакери. Операции, които пишат или пренасят пароли, изискват твърдо `method="POST"`.

## 2. ИНТЕРВЮ ВЪПРОС (Тема 05-01): Празни C# свойства в .NET контролера (Model Binding Крах)

*   **Въпрос на интервюто:** *„HTML формата изпраща POST заявка успешно към нашия ASP.NET Core бекенд без мрежови грешки (Status 200/201), но C# обектът пристига празен или със свойства, съдържащи `null` и `0`. Къде лежи дефектът във фронтенд кода?“*
*   **Точен Senior отговор:** Проблемът идва от липсата или грешното изписване на атрибута **`name="..."`** във входящите HTML инпути. Програмистите често бъркат атрибутите `id` (който служи само за CSS и DOM достъп) с атрибута `name`. Когато браузърът пакетира HTTP Request Body тялото, той използва единствено стойността в `name` като ключ. Бекенд мениджърът (.NET Model Binder) сканира тези ключове и търси съвпадение буква по буква със свойствата в C# DTO / Input модела. Ако `name` липсва или се разминава по регистър, моделът се срива и пристига напълно празен.

## 3. ИНТЕРВЮ ВЪПРОС (Тема 05-02): Блокиране на асинхронни нишки при AJAX Submit операции

*   **Въпрос на интервюто:** *„Закачаме JavaScript събитие за изпращане на форма. Искаме да обработим и пратим данните асинхронно през Fetch API (AJAX) без опресняване на екрана. Защо сайтът продължава да се презарежда твърдо и как се спира това софтуерно?“*
*   **Точен Senior отговор:** По рождение браузърът има вградено автоматично действие за събитието `submit` — той веднага прекратява текущия скрипт и прави синхронен уеб рестарт към адреса в `action` атрибута. За да се даде пълна автономия на асинхронните JavaScript/AJAX нишки, това дефолтно действие трябва да бъде спряно насила в първия ред на функцията чрез метода **`event.preventDefault()`**:
    ```javascript
    form.addEventListener('submit', function(event) {
        event.preventDefault(); // 🟢 СЕНЬОР ФИКС: Спира презареждането на браузъра!
        // Изпълнение на FETCH / AJAX трансакция...
    });
    ```

## 4. ПРОИЗВОДСТВЕНИ КАПАНИ: СРИВОВЕ ПРИ РАДИО ГРУПИ БЕЗ СПОДЕЛЕН NAME ПАРАМЕТЪР

### 🚨 Капан №1: Радио бутоните позволяват маркиране на всички опции едновременно
*   **Причина:** Разписала си два радио инпута за избор на пол или роля, но си им задала различни имена: `<input type="radio" name="RoleStudent">` и `<input type="radio" name="RoleTeacher">`. Браузърът ги отчита като две напълно независими уеб полета. Потребителят може да кликне и на двете едновременно, което чупи бизнес логиката на избора.
*   **Решение:** Принудете браузъра да ги обедини в обща група, където маркирането на една опция автоматично изключва останалите, като им наложиш **напълно идентичен `name` атрибут**:
    ```html
    <!-- 🟢 ПРАВИЛЕН СТАНДАРТ (Обща група "UserRole"): -->
    <input type="radio" id="student" name="UserRole" value="Student" checked>
    <input type="radio" id="teacher" name="UserRole" value="Teacher">
    ```
