## 1. ГОЛЕМИЯТ СРИВ: ПРОБЛЕМЪТ С ДЕФОЛТНИЯ CONTENT-BOX

По подразбиране браузърът налага свойството `box-sizing: content-box;`. Ако направиш две колони с `width: 50%;` една до друга във Flexbox, но на едната добавиш дори само `1px` padding, кутията се раздува хоризонтално, надхвърля общите 100% и се срива на долния ред, разбивайки целия интерфейс пред Judge.

---

## 2. АРХИТЕКТУРНОТО РЕШЕНИЕ: ГЛОБАЛНО BORDER-BOX НУЛИРАНЕ

За да застраховаш кода си от такова раздуване, в самия връх на CSS файла се налага глобален одит, който принуждава браузъра да **свива padding-а и рамката НАВЪТРЕ** в рамките на дефинирания width:

```css
/* 🟢 ЖЕЛЕЗЕН ИЗПИТЕН ЗАКОН ЗА ВСЕКИ ПРОЕКТ: */
*, *::before, *::after {
    box-sizing: border-box;
    margin: 0;
    padding: 0;
}
```
*Сега, ако заложиш ширина 300px, тя си остава точно 300px на екрана, без значение колко вътрешни очертания добавяш!*

---

## 3. ФЕНОМЕНЪТ MARGIN COLLAPSE (ПРОПАДАНЕ НА ВЪНШНИ ПОЛЕТА)

Когато два вертикални блока (напр. два параграфа) се докоснат, техните марджини не се събират. Браузърът ги слива едни в други и налага само по-голямата от двете стойности.
*   *Пример:* Горна кутия с `margin-bottom: 30px;` + долна кутия с `margin-top: 20px;` ➔ Реалното разстояние на екрана ще бъде **само 30px**, а не 50px.
*   *Решение:* Ако ти трябва закован пикселен буфер без пропадания, преминете към вътрешен `padding` над общия им родителски контейнер.
