## 1. ИНТЕРВЮ ВЪПРОС (Тема 07-00 & 07-03): Срив на падащите менюта поради липсващ Popper.js

*   **Въпрос на интервюто:** *„Инсталираме Bootstrap през npm в нашия Vite проект. Пишем валиден HTML код за бутон с падащо меню `.dropdown-menu` и добавяме правилните атрибути `data-bs-toggle="dropdown"`. Когато кликнем върху бутона обаче, нищо не се случва. В конзолата няма CSS грешки, но менюто не изскача. Къде лежи софтуерният дефект?“*
*   **Точен Senior отговор:** Проблемът идва от липсата на нисконивовата JavaScript зависимост **Popper.js** (`@popperjs/core`), или от импортирането на грешен компилиран JS файл в `main.js`. Интерактивните компоненти на Bootstrap като Dropdowns, Popovers и Tooltips изчисляват динамично своите координати на екрана спрямо прозореца (Viewport) посредством Popper.js. Ако си импортирала просто `bootstrap.min.js`, в него липсва този математически двигател и софтуерът тихо отказва да работи.
*   **Решение:** Трябва винаги да се импортира т.нар. **Bundle** пакет, който съдържа Popper.js компресиран в същия байтов поток:
    ```javascript
    // 🟢 СЕНЬОР СТАНДАРТ (Включва Popper.js под капака напълно автоматично):
    import 'bootstrap/dist/js/bootstrap.bundle.min.js';
    ```

## 2. ИНТЕРВЮ ВЪПРОС (Тема 07-01): Счупване на хоризонталната подредба и препълване на ред (The Grid Crash)

*   **Въпрос на интервюто:** *„Изграждаме двуколонен Layout. Искаме колона 1 да заема 8 виртуални единици, а колона 2 — останалите 4. Разписваме `<div class="col-8">` и `<div class="col-4">`. Когато отворим сайта обаче, колоните не застават една до друга, а се избутват вертикално на нови редове, чупейки дизайна. Защо?“*
*   **Точен Senior отговор:** Този срив се случва, защото колоните са оставени в DOM дървото без изричен общ родител с клас **`.row`**. В архитектурата на Bootstrap, колоните (`.col-*`) нямат native сили сами по себе си да се подреждат хоризонтално; те са чисти кутии с падинг отстрани. Класът `.row` е този, който налага критичния Flexbox контекст (`display: flex; flex-wrap: wrap;`) и прилага негативни марджини, за да издърпа колоните насила в перфектна хоризонтална линия. **Твърд архитектурен закон: Колона НЕ може да съществува самостоятелно без родителски `.row`!**

## 3. ИНТЕРВЮ ВЪПРОС (Тема 07-04): Феноменът Сблъсък на Специфика (The CSS Specificity Collision)

*   **Въпрос на интервюто:** *„Искаме да променим цвета на текста на даден Bootstrap бутон `<button class="btn btn-primary my-custom-text">` и написваме в нашия суров CSS файл: `.my-custom-text { color: red; }`. Защо браузърът напълно игнорира нашето правило и как можем да го поправим без използване на лошия анти-патерн `!important`?“*
*   **Точен Senior отговор:** Браузърът игнорира правилото поради законите за **Тежестта на селекторите (CSS Specificity)**. Твоят селектор притежава тежест от само 1 клас (`.my-custom-text` = 10 точки). Под капака обаче, Bootstrap дефинира бутоните чрез силно комбинирани селектори (напр. `.btn-primary:hover` или `.btn.btn-primary` = 20 точки). Тъй като кумулативната тежест на фреймуърка е по-голяма, твоето правило бива пренаписано насила. За да го поправиш чисто без `!important`, трябва просто да увеличиш спецификата на твоя селектор, като верижно го обвържеш с базовия клас на Bootstrap:
    ```css
    /* 🟢 ПРАВИЛЕН СЕНЬОР ФИКС (Увеличава тежестта на 20 точки и побеждава каскадата): */
    .btn.my-custom-text {
        color: red;
    }
    ```

## 4. ПРОИЗВОДСТВЕНИ КАПАНИ: ПАРАЛИЗА НА МОДАЛНИ ПРОЗОРЦИ (MODAL BACKGROUND SOFT LOCK)

### 🚨 Капан №1: Модалният прозорец се отваря, но остава заключен И ЗАД полупрозрачния черен фон
*   **Причина:** Поставила си HTML кода на твоя модален прозор (`<div class="modal">`) вложен дълбоко вътре в кутия, която има наложени CSS свойства от типа `position: relative;`, `overflow: hidden;` или специфичен `z-index`. Когато Bootstrap инжектира своя глобален засенчващ слой (`.modal-backdrop`) в корена на `<body>` тага, се задейства нов контекст на натрупване (Stacking Context). Твоят модал остава софтуерно заклещен вътре в координатната система на своя родител и черният фон го закрива напълно визуално, правейки кликането върху бутоните му невъзможно (Soft lock).
*   **Решение:** **Твърд закон за модали:** Винаги поставяйте HTML кода за модални прозорци в най-външно ниво — директно преди затварящия таг `</body>`, извън каквито и да е други позиционирани контейнери, гарантирайки чиста координатна изолация.
