## 1. МРЕЖОВАТА ВРЪЗКА: КАК LIVE SERVER ПРЕНАСЯ ДАННИТЕ КЪМ CHROME

Когато кликнеш върху бутона **`Go Live`** в долния десен ъгъл на VS Code, разширението стартира лек фонов Node.js уеб сървър, който заделя локален мрежов порт (обикновено порт **`5500`**).
*   Адресът в браузъра става: `http://127.0.0`.
*   *Механизъм на работа:* Live Server инжектира скрито JavaScript парче код (`WebSocket` връзка) в уеб страницата. Когато промениш нещо във VS Code, сървърът праща светкавичен пакет по WebSocket канала и кара Chrome да презареди страницата без твоя намеса.

---

## 2. СЕНЬОР ДЕБЪГВАНЕ: КОНЗОЛАТА И ПРОВЕРКА НА HTML ГРЕШКИ

Ако даден интерактивен бутон или стил спре да работи, отваряш Chrome DevTools чрез клавиша **`F12`** (или `Fn + F12` на лаптоп):
*   **Табът Console:** Твоят най-важен изпитен радар. Ако имаш правописна грешка в JavaScript, липсващ файл или счупена WebSocket връзка, тук веднага светва червена линия с точното софтуерно съобщение за грешка и номера на реда във VS Code.
*   **Табът Elements:** Покава реалното, живо **DOM дърво** в RAM паметта. Можеш да правиш промени по текстовете направо в браузъра, за да тестваш как ще изглежда дизайнът, преди да го запишеш твърдо на диска.

---

## 3. ИНТЕГРАЦИЯ МЕЖДУ СОФТУЕРНИТЕ ПРОЗОРЦИ (SIDE-BY-SIDE LAYOUT)

Индустриалният стандарт за висока скорост при изпити и уъркшопи е разделянето на екрана на две равни части (**Side-by-Side Layout**):
*   **Лява половина на монитора:** Разполагаш прозореца на VS Code.
*   **Дясна половина на монитора:** Разполагаш прозореца на Google Chrome, отворен през Live Server, заедно с активния DevTools диагностичен панел отдясно.

```text
 ┌───────────────────────────────────────┬───────────────────────────────────────┐
 │                                       │                                       │
 │         VS Code Editor                │         Google Chrome Browser         │
 │         (Ляв прозорец)                │         (Десен прозорец)              │
 │                                       │                                       │
 └───────────────────────────────────────┴───────────────────────────────────────┘
```
*Това ти позволява да виждаш как всяка единична написана буква отляво веднага се рендерира визуално и се проверява за грешки отдясно, вдигайки скоростта на писане двойно.*

---

## 4. СИСТЕМНИ КАПАНИ: КЕШИРАНИ СТАРИ ФАЙЛОВЕ (THE CACHE TRAP)

### 🚨 Капан №1: Браузърът показва стария дизайн, въпреки че кодът във VS Code е записан
*   **Какво правиш:** Променяш цвета на даден блок в CSS файла и го записваш. Live Server опреснява браузъра, но на екрана си виждаш стария цвят. Изтриваш кода, пишеш го пак — нищо не се променя.
*   **Защо се случва (Капанът на браузърния кеш):** С цел икономия на интернет трафик, браузърите притежават вградена памет, наречена **Cache (Кеш)**. Когато заредят тежък CSS файл веднъж, те го заключват на твърдия диск и при следващо опресняване отказват да го прочетат от уеб сървъра, зареждайки старите кеширани байтове памет.
*   **Как да го поправиш (Изпитен спасителен фикс):** Отвори DevTools с `F12`. Кликни с десен бутон върху иконата за опресняване на страната (Refresh бутона със стрелката горе вляво) и от падналото меню избери **`Empty Cache and Hard Reload` (Изпразване на кеша и насилствено презареждане)**. Браузърът ще изтрие старата заключена памет насила и ще изтегли новия ти чист CSS код от сървъра.
